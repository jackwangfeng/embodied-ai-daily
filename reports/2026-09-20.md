## 🇨🇳 国内

### 1️⃣ 【深度】joykraft/6d_grasp —— 语言引导的 6D 视觉抓取，从手眼标定到真机抓取一条不缺

**是什么。**
一个中文写全的研究型 6D 抓取工程：Intel RealSense 出 RGB-D → GraspNet 生成六自由度抓取候选 →
碰撞 / 抓取角度 / 高度三重筛选 → 用手眼标定矩阵把相机系位姿换算到机械臂基座系 → 逆解执行。
上面再叠一层 VLM：你说「抓香蕉」，Grounding DINO 或 DashScope 负责把这句话落到点云里的一块区域。
仓库带一段 **约 43 秒的原速真机视频**（香蕉抓取 → 搬运 → 放置，有声），
这在这类仓库里很少见 —— 大部分只给仿真 GIF。

**为什么现在值得做。**
6D 抓取这条线的三个零件（GraspNet 权重、RealSense SDK、开源 VLM 检测）单独都开放很久了，
**卡人的从来是中间那段手眼标定和坐标变换** —— 教程要么只讲原理不给脚本，要么给的脚本绑死某个商业臂。
这个仓库把标定拆成四个可以单步跑、单步检查的脚本（`1.1.generate_points.py` → `2.2.generate_images_and_T.py`
→ `3.calibrate.py` → `4.test_gripper.py`），并且在 `3.calibrate.py` 里让你**在 Horaud / Tsai / Park 三种解法里选**，
输出 `T_camera2end.yaml` 之后可以拿去复用。这是能直接抄进自己项目的部分。

**个人怎么切进去（分步 / 带成本和时间）。**

| 步 | 做什么 | 时间 | 花费 |
|---|---|---|---|
| 0 | 先不碰机械臂。只装环境 + 跑 `1.verify_grasp.py`，用仓库里的静态点云验证 GraspNet 能出候选 | 半天 | 0（A4000 够） |
| 1 | 编 `pointnet2` / `knn` 两个 CUDA 扩展。仓库给的环境是 Python 3.8 + PyTorch 2.0.1 + CUDA 11.8 | 2–4 小时（多半卡在这） | 0 |
| 2 | 买/借一台 RGB-D。D435 约 ¥1300–2000；国产 Orbbec/奥比中光同级约 ¥700–1200，但要自己改 `pyrealsense2` 那层 | — | ¥700–2000 |
| 3 | 打印一张 11×8 内角点、方格 13.6 mm 的棋盘格（A3 硬纸板贴平即可），按 `config.yaml` 改成你的实际尺寸 | 1 小时 | ¥20 |
| 4 | 眼在手外标定四步走完，核对重投影误差 | 半天 | 0 |
| 5 | 语言指定目标。默认走 DashScope API，一次抓取 ≈ 1 张图 + 几十 token 的 prompt，**单次约 ¥0.01–0.03**；不想花钱就换本地 `grounding-dino-base`（约 1.6 GB 权重，A4000 上和 GraspNet 同时驻留没问题） | 2 小时 | ≈0 |

**产出终点很明确**：`T_camera2end.yaml` + 一段自己的真机（或 MuJoCo 回放）抓取视频。
没有机械臂的话，1–4 步依然成立 —— 标定那一段换成「相机 + 手持棋盘格」也能练，
GraspNet 候选可视化（Open3D）本身就是一个能交付的结果。

**坑与风险（按严重程度排）。**

1. **没有 LICENSE。** 仓库根目录没有许可证文件，意味着**默认保留所有权利** —— 自己学习复现没问题，
   但不能直接并进你要发布的项目。想用就先开 issue 问作者。
2. **`episodeApp.py` 是 TCP 客户端，不是服务端。** 它默认连 `localhost:12345`，
   而那个 Episode 机械臂的控制服务**不在仓库里**，由厂商提供。换别的臂就要自己重写这一层
   —— 好消息是这层只是「发目标位姿 / 读当前位姿」，接口很薄。
3. **CUDA 扩展是版本地雷。** `pointnet2` 和 `knn` 换 CUDA/PyTorch 版本必须重编，
   README 也明写了这点。建议老老实实建 cu118 的 conda 环境，别在系统 Python 上折腾。
4. **它会让机械臂真的动。** README 自己写了「运行前请完整阅读安全须知和已知限制」。
   第一次跑务必把速度限到最低、手放在急停上。
5. 目录名是中文的 `代码/`。在某些 CI / Docker 挂载场景下会有编码麻烦，本地用没事。

### 2️⃣ xiaohu-art/Weave —— 清华 IIIS × 港大，全身灵巧 loco-manipulation；真正的礼物是那 23 小时数据集

- **是什么**：从人-物交互动捕出发，先做「接触感知的重定向 + 接近动作补全」，把人的演示变成机器人可执行的参考轨迹；
  核心策略**同时指挥 29 个身体关节 + 12 个手指关节**（Unitree G1 + 因时灵巧手），跨多物体、多交互序列。
- **数字**：9 个物体上训练内交互 **92.5% 成功率**；**未经任何额外训练**，在训练时没见过的序列上 **65.0%**。
- **真正可拿走的东西**：作者放出了 **约 9000 条物理执行 rollout、合计约 23 小时**、带接触标注的机器人-物体轨迹。
  这批数据不依赖你有没有 G1 —— 拿来做下游交互策略学习、或者做物理一致的 HOI 动作生成，都是现成的。
- **本机能做什么**：训练侧 README 默认 `num_envs=8192`，那是多卡口径；A4000 16G 上要降到 512–1024 才起得来，
  收敛时间按线性外推大概是文档口径的 8–16 倍，**不建议**在这台机器上追完整复现。
  值得做的是：`git lfs pull` 拿数据 → 用 `scripts/rsl_rl/eval.py` 逐 clip 看 `metrics.json` → 拿数据训自己的小模型。
- **坑**：① **无 LICENSE**，数据集的使用条件也就跟着不明确，商用前必须问作者；
  ② 安装要求 **~30 GB 空闲盘**（Isaac Sim + IsaacLab + venv 全塞一个 workspace）；
  ③ 依赖 Git LFS，`git clone` 之后必须 `git lfs pull`，否则拿到的是一堆指针文件。
- **出处**：<https://github.com/xiaohu-art/Weave>（72★，无 LICENSE）
  ｜[论文 arXiv:2609.16683](https://arxiv.org/abs/2609.16683) ｜[项目页](https://xiaohu-art.github.io/Weave/)
  ｜[Isaac Lab](https://github.com/isaac-sim/IsaacLab) ｜[rsl_rl（训练用的 PPO）](https://github.com/leggedrobotics/rsl_rl)

### 3️⃣ 115239/M20-Piper —— 整机买不起，但那块参数化转接板和 24 关节 USD 是白给的

- **是什么**：把云深处 M20 Pro 轮足底盘和松灵 Piper 机械臂拼成一台移动操作平台，
  仓库给出**完整 Isaac Sim 5.1 组合模型（6 个 USD，24 个可动关节：底盘 16 / 机械臂 6 / 夹爪 2）**、
  底盘运控包，以及两个打印件：机身转接板（`base_adapter.stl` + **同一块板的 OpenSCAD 参数化源文件** `base_adapter.scad`）
  和 Piper 腕部 D435i 相机支架（`.STEP`）。
- **为什么值得看**：整机远超预算（M20 Pro 是十万量级），**但硬件预算和可复用价值在这里是分开的**。
  一块给出 `.scad` 源文件的转接板，意味着你换成别的底盘/别的臂只要改几个参数就能重出 STL；
  腕部 D435i 支架更是所有装 RealSense 的臂都要做一遍的活儿。**这两个件加起来打印成本 ¥5–15。**
- **切进去的方式**：把 `piper_piper_d435i_sensors.usda` 在 Isaac Sim 5.1 里打开当作现成的移动操作场景（免费），
  或者只拿 `3d_printing/` 两个件改尺寸自用。仓库只有两个 Python 文件（`simulation.py` 启动仿真、
  `policy/controller.py` 驱动底盘），读起来快。
- **坑**：① **无 LICENSE**（有 `NOTICE.md` 和 `LICENSES/` 记录第三方来源，但仓库自身许可缺失）；
  ② 演示视频里的商超场景**不在仓库里**，`run.sh` 跑的是平地示例，别按视频预期结果；
  ③ `model/` 目录必须整体保留，单独搬一个 USD 会丢引用；④ 单位是米、Z 向上、根节点 `/M20_Piper`。
- **出处**：<https://github.com/115239/M20-Piper>（3★，2026-09-17 建，无 LICENSE）

### 1️⃣ 【深度】arpitg1304/armature —— 一个 HTML 文件里的机器人工作室：建场景、采示教、导 LeRobot 数据集

**是什么。**
浏览器里的机器人仿真工作室。打开网页就能：摆一个 kitting 工作台（零件、目标位、夹具，支持撤销）→
选机器人（**Franka Panda / SO-101 / UR5e / xArm 6**）→ 选任务（kitting、搬运、分拣、堆叠、插装、变光照）→
手动接管录一段示教 → 看 RGB / 合成深度 / 实例分割三种观测 → **按 LeRobot v3 风格的目录结构导出数据集** →
跑 seeded 压力测试扫参、回放失败的那一次。
机器人资产、场景、代码、仿真 worker **全部内联在生成的单个 HTML 里**：下载那个页面，断网也能跑。

**为什么现在值得做。**
过去一年里「我想练 VLA / 模仿学习但没有机械臂」这个问题的标准答案是装 MuJoCo/Isaac + 写采集脚本，
门槛落在环境上而不是落在学习上。armature 把门槛压到**零安装**：
没有 Python、没有 CUDA、没有 ROS，一个页面就把「采数据」这一环补齐了，
而且吐出来的是 LeRobot 风格的数据集 —— 直接能喂给下游训练。
更关键的是它**把「可复现」当成一等公民**：seeded 试验扫描、逐次回放、失败用例检视，
这正是个人做小实验时最容易省掉、然后回头说不清楚结论从哪来的那部分。

**个人怎么切进去（分步 / 带成本和时间）。**

| 步 | 做什么 | 时间 | 花费 |
|---|---|---|---|
| 0 | 直接开 [在线版](https://arpitg1304.github.io/armature/)，选默认的 Panda + kitting cell，跑一遍 Demonstrate | 20 分钟 | 0 |
| 1 | 切到 **SO-101**（和低价开源臂同构），设计一个你真想要的任务；用 Tools → Robot bookmarks 存几个关键位姿（注意：这是关节空间移动，**不做碰撞规划**） | 1 小时 | 0 |
| 2 | 录 100–200 条示教。手动接管录制，导出 LeRobot v3 风格数据集 | 2–4 小时（人肉） | 0 |
| 3 | 在本机 A4000 上训 ACT 或 flow-matching 策略（可以直接用下面第 2 条那套代码），跑 eval | 训练 1–3 小时 | 0 |
| 4 | 回到 armature 用 seeded 压力试验扫光照 / 摆位，把失败 case 回放出来，写成一份「泛化边界」报告 | 半天 | 0 |
| 5 | 想本地改：Node.js 22+，`npm ci && npm run build`，改 `src/` 重新出 `dist/robotics-arm-studio.html`。仓库自带四档测试（`npm test`、`test:browser`、`test:stress-ui`、`test:pages`） | — | 0 |

**全程 0 元、0 硬件**，终点是一份自己的数据集 + 一个训出来的策略 + 一份可复现的泛化报告。
这是本期六条主线里**唯一一条今天就能从头做到尾、不需要买任何东西**的。

**坑与风险。**

1. **GPL-3.0。** 想把它嵌进闭源产品不行；个人使用、改造、发布衍生开源项目没问题。
2. **它是浏览器物理，不是 MuJoCo/Isaac。** 接触和摩擦的保真度不要当真机代理；
   在这里训出来的策略拿去真机大概率要重新采数据。它的定位是**流程练手和数据格式练手**，不是 sim2real。
3. 「LeRobot v3 **风格**」不等于 LeRobot v3 官方格式。导出后先用 `lerobot` 的 dataset 加载器验一遍，
   字段对不上就写个小转换脚本（这一步本身也是很好的练习）。
4. 相机预览的「放大」只是放大现有像素，**不提高录制分辨率** —— 要更高分辨率得在录制设置里改。
5. 1★ 的新项目，作者一个人在推。别把它当长期依赖，**当成一次性的数据生成器**用最稳妥。

### 2️⃣ nizan-mashall/imitation-learning-tutorial —— 三种模仿学习策略从零实现，**带预训练 checkpoint**

- **是什么**：海法大学 SAIL Lab 出的教学仓库，在 RoboSuite **Lift** 任务上实现三档递进的策略，
  共用 DINOv2 视觉骨干：

  | 策略 | 视觉特征 | 动作头 | action chunking | 随机性 |
  |---|---|---|---|---|
  | MLP Policy | DINOv2 CLS token | MLP | ✗ | ✗ |
  | Transformer Policy | DINOv2 patch tokens | Encoder-Decoder | ✓ | ✗ |
  | Flow Matching Policy | DINOv2 patch tokens | Encoder-Decoder + Flow Matching | ✓ | ✓ |

- **为什么值得做**：这是把「ACT 为什么要 chunking」「flow matching 比确定性回归多给了什么」
  这两个问题**用能跑的代码**摆清楚的最短路径。数据准备就一条命令：从 Robomimic 下 200 条人类演示（约 200 MB），
  在 MuJoCo 里重放并渲染观测，落成一个 hdf5。三个策略各自 `train` / `test`，test 直接在 RoboSuite 里 rollout 报成功率。
  还有一个 `visualize_denoising`，把 100 条去噪轨迹收敛到真值动作的过程画成 GIF —— 讲清 flow matching 直觉的好素材。
- **本机可行性**：README 说「tested on A100」，但这是三个小策略 + DINOv2 冻结特征，
  **A4000 16G（可用约 11.6G）完全够**；把 batch size 砍一半、开 AMP 即可。作者给了 pretrained checkpoints，
  所以**先跑 eval 再决定要不要训**，零等待。CPU-only 安装分支也写好了（只做推理和可视化）。
- **坑**：① 仓库里那条 Medium 文章链接是空的（`#`），正文只能看代码；
  ② 依赖钉死 `torch==2.13.0 / torchvision==0.28.0 + cu124`，和本机 CUDA 13.1 的驱动栈共存没问题（pip wheel 自带 runtime），
  但别和 `/workspace/cuda/env.sh` 那套 ORT 环境混用；
  ③ 只有 Lift 一个任务，换任务要自己改 `data/prepare_dataset`。
- **出处**：<https://github.com/nizan-mashall/imitation-learning-tutorial>（MIT，3★）
  ｜[RoboSuite](https://github.com/ARISE-Initiative/robosuite)

### 🇨🇳 Kanon163/datum —— 从现实物体到**有测量证据**的参数化 CAD，而且几乎不花 token

**是什么。** 一个 Codex Skill + 本地三维测量工作台。
你把机械零件的照片或图纸丢给 agent，它先建一个初步参数化模型，**并明确指出「这里我不知道，你去量」**；
你照着页面提示用卡尺输读数，工作台重建、验证、导出可继续设计的 STEP。
支持外尺寸、板厚、内孔径、孔中心距、板边偏移、元件离板高度六类测量；
装配体里的部件可以单独选中高亮，复杂对象先只显示关键测量项。

**为什么值得做。** 「text → CAD」这一年被做烂了，但真做改件的人都知道：
**大部分时候你不是要凭空造一个零件，而是要给一个已经存在的东西配一个新零件。**
那个已经存在的东西没有 CAD 文件 —— 只有它躺在桌上。
datum 把这段「照片 + 卡尺 → 可继续设计的 STEP」做成了带证据链的流程：
每个尺寸都记录**真实读数、用的什么工具、不确定度、备注**，原始记录保留历史；
尺寸错了会**保留上一版有效模型**而不是直接崩掉。
这和 09-17 那条 `cadxray`（从 STEP/STL 反推参数化）是互补的两半 ——
cadxray 解决「有网格没参数」，datum 解决「连网格都没有」。

**个人怎么切进去。**
1. 把一句话给 Codex：「请安装并配置 `https://github.com/Kanon163/datum`，完成环境检查，然后打开测量工作台。」
   仓库的 `AGENTS.md` 就是给 agent 看的完整安装流程，界面是构建好的，**普通安装不需要 Node/npm**。
2. 先跑自带的两个样例摸流程：`examples/mounting-plate`（带孔安装板，基本测量）和
   `examples/electronics-assembly`（**30 个实体、81 个参数**的教学电子装配，首轮只让你量 9 个关键尺寸）。
3. 再上真活儿：拍你要改的那个零件（比如机械臂的电机座、相机支架的安装面），量 5–10 个尺寸，导出 STEP。
4. 拿 STEP 进 build123d / FreeCAD 接着长出你的新零件，切片打印。

**成本（含 API token 费）。**
这条链路的独特之处是 **它不另外买模型 API**：README 明写「无需另外购买模型 API 或配置 API key」，
几何重建跑在本地 Python CAD 环境里，模型只出现在「读照片 + 决定量哪里」这一步，
用的就是你 Codex 订阅本身的额度。按一个中等复杂零件（10 个尺寸、2–3 轮修正）估，
**大约几万到十几万 token，折合几毛到两三块人民币**；对比走云端 mesh 生成的方案（一个件 ¥1–5 起），
这条路的边际成本基本可以忽略。真正的开销是**你的卡尺和你的时间**。

② 它是 **Codex Skill**，Claude Code 用户要自己把 `skills/datum/SKILL.md` 翻成对应格式；

### 🇨🇳 hku-sail/StreamPI —— 不加一个参数，把 π0.5 从「单帧」变成「有记忆的流」

**是什么。**
港大 SAIL Lab（+ ACE Robotics）的工作，官方实现直接建在 [openpi](https://github.com/Physical-Intelligence/openpi) 上。
核心观察很直接：**π0.5 这类 SOTA VLA 是单帧的** —— 每次决策只看当下这一帧，
既记不住刚才发生了什么，也拿不到多帧聚合出来的精确空间感；
而窗口式多帧模型每步都重算整段历史，代价太大。

StreamPI 的做法是把每个 **(视觉观测, 语言指令)** 绑成一个不可分割的时序单元：
- **单元内双向注意力** —— 图文充分融合；
- **单元间因果注意力** —— 保证自回归流式推理，配 KV cache，历史不重算；
- **指令在每个单元里重复出现**，作为持久语义锚点，防止视觉上下文变长之后任务目标被稀释；
- **随机间隔流式训练**：训练时随机采样帧间隔（比如每 3 帧一个单元）+ 时序掩码，
  让策略提前适应「观测什么时候到不一定」的异步部署现实。

**可量化的口子。**

| 指标 | 论文口径（单张 RTX 4090） | 折算到本机 A4000（×2～2.5） |
|---|---|---|
| 单帧上下文平均推理延迟 | **94.4 ms** | **约 210–235 ms（折算值）** |
| 五帧上下文平均推理延迟 | **103.6 ms** | **约 230–260 ms（折算值）** |
| 1→5 帧的**增量**代价 | **+9.2 ms** | **约 +20–23 ms（折算值）** |

**这个 +9.2 ms 才是重点**：把上下文拉长 5 倍，延迟只涨 9.7%。
换句话说，「给 VLA 加记忆」这件事的推理侧代价，已经被 KV cache + 块状注意力掩码压到近乎免费。

**为什么值得做。**
它**不新增任何参数**，完整继承 π0.5 的预训练权重，靠 LLM 骨干的长度外推吃下更长序列，
而且**单帧和多帧推理都支持** —— 意味着你可以拿同一份权重做 A/B：
关掉时序看基线、打开时序看增益，控制变量非常干净。
对个人来说这是难得的「可以只改推理侧就复现出结论」的工作。

**个人怎么切进去。**
1. **先别训。** clone 下来读 `docs/remote_inference.md` 和 `docs/norm_stats.md`，
   跑它的 remote inference client/server 拆分 —— 这一步在 CPU 上就能验证协议。
2. LIBERO / CALVIN 的 `norm_stats.json` 仓库里已经带了（`assets/pi05_libero/`、`assets/pi05_calvin/`），
   省掉自己算归一化统计这一步。
3. **推理侧复现**：π0.5 约 3B 参数，bf16 权重约 6–7 GB，本机可用显存约 11.6 GB —— **能塞下**，
   但 KV cache 随上下文增长，五帧上下文要留足余量，建议先从 2–3 帧试。
   做的事情是：固定一个任务，量 1 帧 vs 3 帧 vs 5 帧的**本机实测延迟**，和论文的 4090 曲线对一下折算系数准不准。
   **这本身就是一份能发出去的结果**（本地台账里还没有 A4000 上的 VLA 流式延迟基准）。
4. **别碰训练。** JAX 多节点分布式训练是它的卖点之一，但那是多机多卡口径，单张 A4000 无从谈起。

**坑。**
① **权重状态要自己确认**：README 的 News 写着「2026-08-30：Code and model weights will be released」，
   而仓库**最后一次推送停在 2026-08-27**，代码（1900+ 文件）确实在，**但 StreamPI 自己的 checkpoint 在仓库里找不到**。
   动手前先去项目页/issue 核一下，别按「权重已放」排计划。基础的 π0.5 权重走 openpi 是公开的。
② 它是 **openpi 的分支形态**，不是轻量插件 —— JAX 栈、Docker 文档一套，环境比 PyTorch 那套重。
③ 带 `LICENSE_GEMMA.txt`，骨干继承 Gemma 的使用条款，商用前看清楚。
④ 论文实验在真机 + LIBERO + CALVIN 上，**报的是「一致提升」而不是某个单一大数字** —— 别指望复现出一个爆炸性的成功率。

### 🌍 shakstzy/edge-reflex —— 10 Hz 的动作块底下，垫一层 400 µs 的反射弧

**是什么。**
针对一个具体且真实的工程缺口：**VLA（π0 / OpenVLA / Octo / ACT）以 10 Hz 吐出 50 步的关节轨迹块，
然后开环执行 100 ms。** 这 100 ms 里世界要是变了 —— 人手伸进来、物体滚过来 —— 策略完全不知道。
学术界的标准答案是用控制障碍函数（CBF / HOCBF）在底下做安全过滤，
但作者指出了一个在真硬件上致命的问题：**当机械臂带速逼近障碍时，
满足 CBF 约束所需的制动力矩经常超过电机的连续力矩上限**
（Franka 腕部 5–7 轴 τ_max 只有 12 N·m），标准 CBF-QP **原始不可行** ——
求解器要么报 INFEASIBLE，要么做启发式力矩截断，而截断会直接破坏前向不变性，结果是高速撞上去。

edge-reflex 的解法有四块：① 完整 Franka Panda 空间动力学（DH 运动学、URDF 质心偏置、
3×3 连杆转动惯量张量、科氏漂移）；② 把箱约束 QP 解析化成**连续二次背包问题（CQKP）**，
用单调分段二分**精确求 KKT 乘子 λ\***，零启发式截断；③ **可行性调控器**：
检测到物理力矩上限使标称衰减不可能时，主动注入动能耗散（最大边界制动 + 零空间阻尼 −K_d·q̇）；
④ 纯 NumPy 实现。

**可量化的口子（全部是 CPU 口径，不需要折算）。**

| 指标 | 数值 |
|---|---|
| 闭环执行频率 | **> 2,500 Hz**（标准 CPU 核，纯 NumPy，零深度学习开销） |
| 单次屏蔽决策耗时 | **约 400 µs** |
| KKT 乘子二分求解 | 16 次迭代，**< 50 µs**，到机器精度 |
| 上层 VLA 动作块频率 | 10 Hz（50 步轨迹） |
| 对照 | 无屏蔽的 10 Hz 块**穿透障碍体（碰撞）**；加屏蔽后沿安全边界切向滑过，且不越电机包络 |

**为什么值得做。**
它是「执行侧异步」这一类里少见的**不需要 GPU、不需要训练、不需要数据**的一条 ——
整个东西就是一个 `edge_reflex.py` 加一个 `test_edge_reflex.py`。
而它解决的问题对任何要把 VLA 放到真硬件上的人都是必经之路：
**大模型慢是物理事实，你需要在它底下有一层比它快两个数量级的东西。**
本机（A4000 那张卡在这儿完全用不上，纯 CPU）跑它的 benchmark 是分钟级的事。

**个人怎么切进去。**
1. `pyproject.toml` 装上，跑 `test_edge_reflex.py`，复现 >2,500 Hz 和 400 µs 那两个数（**在你自己的 CPU 上**，
   数会和作者的不一样，记录下来）。
2. 读 `HOW_I_BUILT_EDGE_REFLEX.md` —— 作者把推导过程写出来了，这是这个仓库最值钱的部分。
3. **接上真的 VLA 输出**：拿本期第 2 条（armature）或上面 StreamPI 的动作块，
   喂给 edge-reflex 做屏蔽，看它砍掉了多少步、砍在哪里。这是一个没人做过、结果可发布的小实验。
4. 换机器人：现在硬编码 Franka Panda 的 DH 和惯量。换成 SO-101 / xArm 需要自己填一套参数，
   工作量不大（就是从 URDF 里抄），**而且正好是检验你 URDF 惯量对不对的好办法**（和上面专题一那条呼应）。

**坑。**
1. **全部是仿真。** README 里的图是 3D 轨迹仿真，**没有真机验证数据**。
   400 µs 是算得快，不等于装到真臂上安全。
2. **0★、一个人、9-10 建的新仓**，`edge_reflex.py` 单文件约 20 KB。
   优点是能一晚上读完，缺点是没有任何第三方验证。**当参考实现读，别当库依赖。**
3. 作者用词很满（「certified」「mathematically rigorous」「solving this open problem」）——
   数学推导本身看起来是自洽的，但**「certified」在安全领域有特定含义，这里没有第三方认证**，自己心里有数。
4. 许可是 Apache-2.0（仓库里 `LICENSE` 文件确认过；GitHub API 把它识别成 "Other"，以文件内容为准）。

**出处**：<https://github.com/shakstzy/edge-reflex>（Apache-2.0，2026-09-10 建）

| 1 | **TacForcing: Streaming Action Generation with Execution-Time Tactile Feedback**<br><https://arxiv.org/abs/2608.25798> | 把动作专家换成**流式**动作专家，让执行期间新来的触觉直接改写还没执行的动作；再用 EATA 把触觉条件只加在「马上要执行」的那几步上，避免陈旧触觉污染整块。六个 UniVTAC 仿真任务平均 65%、三个真机接触密集任务平均 69%。 | ❌ **只有项目页**（[88runaway.github.io/tacforcing](https://88runaway.github.io/tacforcing/)，[仓库](https://github.com/88runaway/tacforcing) 里只有网页），无代码无权重 |
| 2 | **Agile-WAM: An Agile Tactile World Action Model for Contact-Rich Robot Control**<br><https://arxiv.org/abs/2609.20761> | 关键洞察：**视觉和触觉的时间尺度天然不同** —— 相邻视觉帧高度相似，触觉一接触就突变。于是做多视界多模态预测：视觉 latent 的监督放在更远的时间偏移，触觉 latent 只预测下一帧。九个仿真 + 五个真机任务，成功率超最强基线且保持低推理延迟。 | ❌ 未搜到公开仓库（2026-09-17 上传，太新） |

| 4 | **VLA-ULAP: Interleaving Cloud VLA Calls with Ultra-Lightweight Local Action Prediction at the Edge**<br><https://arxiv.org/abs/2609.18663> | 云边协同：边端跑一个**约 7.4M 参数**（含冻结视觉编码器）的本地动作预测器，不需要 VLA 隐状态、不需要在线校验、不需要回服务器。Jetson Orin Nano 上 **19.9 ms / 0.183 J** 一次推理，对比 GR00T 在 RTX A6000 上 **284.3 ms / 50.55 J**；砍掉 48.8–76.7% 的 VLA 调用，保住 95.0–97.5% 的基线成功率；真机 SO-101 上推理时间降 47.9–58.0%。 | ❌ 未搜到公开仓库。**但这条对个人最有参考价值** —— 7.4M 的模型在 A4000 上是玩具级开销 |

**对本机（A4000 16G）的读法**：这六篇里唯一能当天动手的是 #3 的推理侧；
#4 那个 7.4M 的本地预测器是**最值得自己重写一遍**的思路（它连隐状态都不要，接口极干净）；
#5 是很好的反面教材 —— **提醒你「把延迟砍掉 9 倍」在这个领域经常是拿成功率换的**，
自己做提速实验时一定要同时报成功率，否则结论没有意义。

## 📈 趋势观察

1. **厂商开始开协议栈，而不是开 SDK。** 09-18 云深处 Lite3 的逐帧线格式表，本期 OnRobot 的
   Modbus 寄存器级 C++17 库 + Isaac Sim 资产 —— 两家硬件厂在两周内做了同一件事：
   **把「怎么和我的设备说话」完整公开**。对买不起整机的个人，这等于白拿一份工业级协议参考，
   自制末端、自制底盘的门槛实质性下降了。这是本季度对个人最友好的变化。
2. **「慢模型 + 快垫层」正在取代「把模型做快」成为主线。**
   本期 edge-reflex（1 kHz 反射屏蔽）、论文清单里的 VLA-ULAP（7.4M 边端预测器）、
   Real-Time EXPO-FT（轻量编辑策略），加上 09-19 的 FlashVLA，
   四条独立工作收敛到同一个架构：**上面那个大东西慢是事实，别跟它较劲，在它底下垫一层快的。**
   而 #5 那篇 GR00T 技术报告从反面印证了这点 —— 硬把动作头压到一步，成功率就塌了。
3. **评测的诚实度在变成一种可见的品质信号。** 本期读到的仓库里，
   写了「本项目未接真机、仿真成功率一律 NOT_MEASURED」（ACT-so101）、
   「13/13 仅描述当前测试范围，不等同于总体成功率」（so101-smolvla-blue-cube）、
   「结果报告为速度-成功率权衡而非改进」（GR00T 报告）的，代码质量普遍也更高。
   **挑项目时先看它怎么描述自己的失败**，比看星数准。
4. **本期没写进主线但值得存档的三条**：
   [robot-hint/HINT](https://github.com/robot-hint/HINT)（浙大，Apache-2.0，长程操作的 pattern router
   决定信哪个相机/何时更新语义，靠视觉高亮 + 注意力先验注入 π0.5，**不加可训练参数**）；
   [DeRuiChen258/ACT-so101](https://github.com/DeRuiChen258/ACT-so101)（MIT，SO-101 上 ACT 全流程，
   C++/LibTorch 新进程重载 TorchScript，**约 12.7 ms 平均延迟**，训练 3000 步峰值显存 3.69 GB／15.3 分钟 ——
   显存数字说明这条路在 A4000 上很宽裕）；
   [robotensor/RoboTwin-ICIL](https://github.com/robotensor/RoboTwin-ICIL)（Apache-2.0，
   **单条演示**的 in-context 模仿学习基准，50 任务 × 100 episode，[HF 数据集](https://huggingface.co/datasets/robotensor/robotwin-icil-aloha-clean)已放）。
