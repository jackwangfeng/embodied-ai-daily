## 🇨🇳 国内

### ★ TOP 1（深度）· PhysBrain 1.5 —— 中关村系的具身 VLM，2B / 8B 权重 9 月 8 日刚上线

**类型：软件 ｜ 硬件成本 0 元 ｜ 显存：2B 约 5 GB、8B 需量化才进 16 G ｜ 周期 1 天出结果，1–2 周做完一轮微调**

**是什么。** DeepCybo 团队（联合中关村学院、中关村人工智能研究院）在 **2026-09-08** 放出的具身视觉-语言模型，同时上线 **8B 和 2B 两个尺寸**。它的设计不是「又一个 VLA」，而是把具身交互的闭环拆成三件事塞进同一个自回归骨干：**理解**观察到的世界、**生成**目标导向的动作、**预测**环境会怎么变。实现方式很直接 —— 在预训练的 Qwen3-VL 上扩词表，加入专门的 **动作 token 和视觉状态 token**，语言回答、结构化空间输出、末端执行器轨迹、未来世界状态全部表示成离散 token，用同一个 next-token 目标联合训练，**没有任何任务专用 head**。看 `config.json` 能验证这一点：架构就是原版 `Qwen3VLForConditionalGeneration`，只有 `vocab_size` 从 Qwen3-VL 的 15 万出头涨到 **168576**，多出来的一万多个就是那套统一动作码本。

具体能力分三块：① **具身理解** —— 在 28 个具身空间智能 / 规划 benchmark 上，8B 拿到 **72.5 总分，开源模型里排第一**，官方说法是「与领先闭源模型相当」；② **动作预测** —— 给指令 + 观测（+ 可选历史动作），输出下一段末端执行器动作 chunk，动作码本跨不同臂和控制配置共享，**一个 checkpoint 驱动多种本体**；③ **未来状态预测** —— 给当前观测和指令，预测一秒后的 RGB + 深度图 + 机器人 mask。

**为什么现在值得做。** 三个理由，按重要性排：

第一，**它是标准 Qwen3-VL 接口，不是又一套要你从源码编译的私有框架**。官方明说可以直接复用 Transformers、vLLM、SGLang、LLaMA-Factory、ms-swift、veRL。这是本条和大多数具身模型最本质的区别 —— 你不需要学一套新的训练栈，**LLaMA-Factory 的 LoRA 配置改个模型路径就能开跑**。社区反应也印证了这点：权重上线不到一天，`mradermacher` 就出了 2B 的 i1-GGUF 量化。

第二，**2B 这个尺寸是真的能在这台机器上做完整实验的**。bf16 下 2B 约 5 GB，A4000 的 16 G 可以放下模型 + 一个像样的 batch 做 LoRA。8B 是 4 个 safetensors 分片、bf16 约 17–18 GB，**16 G 卡装不下，必须走 4-bit 或 offload**。

第三，**它给了个人一个稀缺的中间形态**：不是纯 VLM（不会输出动作），也不是纯 VLA（除了动作啥也不会）。你可以只用它的**指点 / affordance / 轨迹推理**能力当感知前端，接到自己已有的控制器上 —— 这条路不需要任何机器人硬件。

**个人怎么切进去。**

1. **今天（0 元，10 分钟）**：先开 [官方 HF Demo Space](https://huggingface.co/spaces/hugging-apps/physbrain1-5-8b-demo) 传张自己屋里的照片，试试空间理解、指点定位和规划。**先确认它对你关心的场景有没有用，再决定要不要下 17 GB 权重。**
2. **第一天（本机，2 小时）**：拉 2B，用 stock `transformers` 起推理。因为架构名就是 `Qwen3VLForConditionalGeneration`，`AutoModelForCausalLM` / `AutoProcessor` 直接就能加载，不需要 `trust_remote_code` 之外的任何东西。跑通「图片 + 一句指令 → 点坐标」这条最短链路。
3. **第 2–3 天**：用 [EmbodiedEvalKit](https://github.com/pickxiguapi/EmbodiedEvalKit)（官方评测用的就是它）在**一两个**你能跑动的 benchmark 上复现 2B 的分数。**产出物是一张「2B 在 X benchmark 上的复现分 vs 官方报的分」对照表** —— 官方 README 明说 2B 那一列被排除在开源排名之外、没有单独详述，这块是真空地带，谁先测谁就有话说。
4. **第 2 周**：LLaMA-Factory 或 ms-swift 上做一次 LoRA。**别一上来微调动作 token**（动作码本的编解码细节技术报告还没出），先微调空间理解 / 指点这一侧 —— 输入输出都是纯文本坐标，数据你自己就能标。
5. **本机备注**：`. /workspace/cuda/env.sh` 那套是给 onnxruntime 用的，跑 PyTorch 不需要。2B 全量微调在 16 G 上偏紧，LoRA 宽裕。

**坑 / 风险。** 五条，前两条是硬伤：

① **没有声明许可证。** HF 模型页的 tag 里没有任何 `license:` 字段，仓库里也没有 LICENSE 文件。**这意味着你现在既不知道能不能商用，也不知道能不能再分发微调权重。** 个人学习无所谓，任何往外发的东西先去问作者。
② **配套 GitHub 仓库还没公开。** README 的 citation 指向 `github.com/DeepCybo-PhysAI/PhysBrain-1.5`，今天核过是 **404**。所以：没有官方推理示例、没有动作 token 的编解码脚本、没有微调配方。你拿到的就是权重 + 一份模型卡，**动作那一路目前基本用不起来**，能立刻用的是理解 / 指点 / 轨迹推理这一侧。
③ **技术报告没出**，README 里写的是「更多评测细节将在技术报告中给出」。72.5 这个数是官方自评自报的，虽然他们说明了会用统一 metric 重测所有对比模型（这点比多数论文诚实），但**没有第三方复现**。
④ **8B 在 16 G 卡上不能 bf16 跑**，见上。
⑤ 训练数据来源、是否包含中文场景、动作码本覆盖哪些本体，**模型卡里都没写**。

### 2 · 北京人形 Sprite —— 31 关节人形的 FreeCAD 原始工程 + 一条命令能看的 MuJoCo 模型

**类型：硬件（含仿真软件资产）｜ 整机成本远超 ¥5000（不建议整机复现）｜ 纯仿真侧 0 元 ｜ 周期 1–2 周**

- **是什么 / 为什么。** BeijingDynamics 在 **8-28** 同时开了两个仓：`sprite_humanoid_freecad` 放**硬件结构的 FreeCAD 源文件**（`00-SPRITE.FCStd` 顶层装配 + 分系统 / 连杆 / 关节 / 电机 / 轴承 / 紧固件的子文件），许可是 **CERN-OHL-S-2.0（强互惠）**；`open_sprite` 放机器人描述资产和可复现的仿真入口，许可 **AGPL-3.0**。公开的型号是 **Sprite0825**，约 0.95 m 高、**31 个驱动关节**、V 形骨盆。仓里有 2026-08-25 的网格、当前 Isaac Lab 训练在用的 sanitized v4 URDF、一个一条命令就能开的 MuJoCo 可视模型、一个专门给控制器开发用的浮动基座 external-PD 模型，还有**带 artifact 哈希的运动里程碑记录**和 `ASSET_SHA256SUMS`。
  **和 9-2 推过的智元 X1 的区别**：X1 给的是图纸 PDF + BOM，Sprite 给的是 **FreeCAD 可编辑源工程**（改完能直接出加工件），加上一个把「默认场景锁关节，免得你第一次开 viewer 看到机器人瘫在地上」这种细节都想到了的仿真入口。
- **怎么切进去。** 不要碰整机。**三步纯软件路线**：① `python -m mujoco.viewer --mjcf=models/sprite0825/mujoco/scene.xml` 先看几何；② `python scripts/validate_models.py` 跑官方校验器，它会打印 body / joint / DoF / geom / mesh / actuator / timestep 计数并验证所有相对网格路径 —— **这也是最好的贡献口子，任何路径或计数对不上就是一个能提的 issue**；③ 用 `scene_external_pd.xml` 那个浮动基座模型写自己的 PD 或 RL 控制器。想碰硬件就只打印一个手掌或小腿护板，验证 FreeCAD 工程能不能出可打印件。**产出物 = 一条 31 DoF 人形的站立 / 平衡控制器，或一份 FreeCAD → STL 的可打印性报告。**
- **坑。** ① **AGPL-3.0 是强传染的**，你基于 `open_sprite` 写的东西对外提供服务就要开源，比 X1 宽松的许可要小心得多；② 硬件侧是 **CERN-OHL-S 强互惠**，改了设计再分发必须同样开源；③ 仓库很新（8-28 建、8-28 最后推），**只有 12 / 9 个 star，没有 issue 沉淀**，遇到问题基本没人答；④ README 明确警告「制造前自行核验尺寸、材料、紧固件、载荷、间隙、公差、电机额定值、布线、安全限位和装配流程」—— 这是没有经过第三方验证的设计源文件，不是产品；⑤ 没有给 BOM 和成本。
- **出处。** [BeijingDynamics/open_sprite](https://github.com/BeijingDynamics/open_sprite)

### 3 · EngineAI Navigation —— 人形导航的完整训练到部署链路，中文文档一等公民

**类型：软件 ｜ 硬件成本 0 元（仿真侧）｜ Apache-2.0 ｜ 周期 1–2 周**

- **是什么 / 为什么。** 松延动力（EngineAI）**9-3 上线、9-4 仍在更新**的开源仓，做的是 PM01 人形的自主导航：**用有序 LiDAR Range Image 当感知输入，PPO 训端到端策略，输出速度指令交给底层行走策略执行**。价值不在算法新，在**它把一条链路从头给全了**：`training/` 是 Isaac Lab 任务 + SRU 训练框架 + 训练/导出脚本（**导出 ONNX**），`ros/src/simulation/` 是 Gazebo 仿真，`ros/src/deployment/` 是已在 PM01 + Livox Mid-360 上验证过的真机部署 —— 而且**仿真和真机是两套源码，README 明说了这一点**，没有拿仿真代码冒充真机代码。中文 README 是主文档，英文是副本。
- **怎么切进去。** 真机（PM01 + Mid-360）个人显然买不起，但**训练那一半完全免费**：装 Isaac Lab → 跑官方**冒烟测试**（README 单列了这一步，这是最省时间的入口）→ 正式训练 → 导出 ONNX → 在 Gazebo 里验证。**产出物 = 一条自己训的人形导航策略 + 一个 ONNX，以及一份「A4000 16G 上这个任务能开多少并行环境」的实测记录** —— 后者仓里没有，是个现成的贡献。
- **坑。** ① Isaac Lab 对显存和驱动都挑，16 G 卡要压并行环境数，先跑冒烟测试别直接上正式训练；② **底层行走策略不在这个仓里**，导航策略输出的速度指令要有东西去执行，纯看这个仓拼不出完整人形；③ ROS 2 那两套需要 colcon 工作空间和一堆依赖，只想训练的话别碰；④ 只有 23 star，同样是新仓。

## 🌍 国外

### ★ TOP 1（深度）· BittleJuice —— 一台 $319 的机器狗，从 MuJoCo 学步到真机 50 Hz 走路的完整闭环

**类型：硬件（含全套软件）｜ 硬件约 $319（≈ ¥2270，Petoi Bittle X v2）｜ 0 元也能玩（附训好的策略 + 仿真）｜ MIT ｜ 周期：一晚上到一周**

**是什么。** **8-27 上线、9-6 仍在推**的仓，做的是一件很具体的事：在 MuJoCo 里训一条行走策略，然后**让它在一台真的 Petoi Bittle X 上以 50 Hz 走起来**。仓里包含仿真、**实测拟合的 plant model**、把「指令 → 动作」延迟从 **198 ms 砍到 54 ms** 的固件补丁，以及一个不依赖 torch / mujoco 的独立运行时。**训练好的策略随仓发布**，所以从「拆箱的机器人」到「会走的机器人」可以完全不训练；想先看效果，三分钟、不需要任何硬件。

**为什么现在值得做。** 这是本期唯一一条**四条标准全部干净命中**的：$319 在预算内、单机 CPU 就够（PPO 跑一个 64 隐单元的网络，瓶颈在 MuJoCo 物理）、终点明确（robot 走路）、依赖全开源。但真正让它值得写深度的是**它诚实的程度**，这在开源机器人仓里非常罕见：

- **它主动告诉你这条策略是开环的。** README 专门做了一个 blindfold 测试 —— 把两路 IMU 都替换成常量「直立静止」，策略几乎没反应：速度只掉 1.1%，在专门用来抓「有没有在读重力」的 4° 斜坡上只掉 0.2%。作者的原话是「闭环闭在管道里，不在策略里；这个机器人跑的是一段学会的节奏，而不是在对什么做出反应」，并且**把它列为未开放的问题**，还给出了猜测的原因（策略几乎不摔，所以没有任何东西在选择恢复能力）和一条 `blindfold_test.py` 让你自己验。
- **它告诉你哪个指标才算数。** 判断策略能不能迁移的不是 reward 曲线，而是 `tools/mj_deployability.py` 输出的 **slew 饱和率**：随仓策略是 **2.6%，阈值 15%**。
- **它告诉你这台机器人有多烂。** 三条硬约束驱动了整个代码库的设计：**读不到关节位置**（固件能推一个，但每个关节约 20 ms 且期间腿是软的，全身读一遍实测只有 9 Hz，而控制环每 tick 只有 20 ms）—— 所以 `dof_pos` / `dof_vel` 全程是**估计值**，用主机自己发出去的目标过一遍舵机响应模型算出来，**并且仿真器也观测同一个估计值而不是它自己的 ground truth**；**没有原始陀螺仪**（角速度是从融合姿态流差分出来的，这决定了噪声下限）；**舵机很慢**，而 MuJoCo 默认执行器快得多，两级必须一起拟合否则同一份延迟会被算两遍。结论作者直接写了：**有意思的活儿在 plant model 里，不在算法里，RL 就是普通 PPO。**

**个人怎么切进去。** 仓里自带一张「按投入递增排序的入口表」，直接照抄：

| 阶段 | 你得到 | 你需要 | 大约 |
|---|---|---|---|
| 0 | viewer 里的一段步态 | 一台笔记本 | 3 分钟 |
| 1 | 一台会走的机器人 | Bittle X v2 + USB 线 + 刷固件 | 一个晚上 |
| 2 | 你自己的步态 | 上面 + 一颗像样的 CPU | +5 小时 |
| 3 | 拟合到你自己那台硬件的 plant model | 上面 + 耐心 | +1 天 |

1. **今天（0 元，3 分钟）**：`git clone --recurse-submodules` → `uv sync` → `uv run python sim/mj_eval.py -e shipped --video gait.mp4`（headless，SSH 上也能跑）。然后 `uv run pytest`（约 10 秒）和 `uv run python tools/mj_deployability.py -e shipped`。
2. **今天（再 5 分钟）**：跑 `tools/blindfold_test.py`，亲手看一遍「策略其实没在用 IMU」。**这一步比看 demo 视频有价值得多 —— 它教你以后怎么怀疑别人的 sim2real 结果。**
3. **买 Bittle X 之后（一个晚上）**：刷固件（**releases 页有 CI 构建的预编译镜像**，`tools/flash_firmware.py` 会先问机器人是什么型号、型号不对拒绝写入、并且写之前把整片 flash 备份到 `backups/`）→ 按 a→e 五道闸分阶段上电：先探活、再 dry-run 不发串口、再吊起来只保持站姿、再吊起来短跑、最后落地并用手护第一次。
4. **想深入**：`deploy/` 只依赖 numpy + pyserial，可以整个目录拷到树莓派上。训自己的步态从 `docs/training.md` 开始。

**坑 / 风险。** ① **必须是 Bittle X v2 + 合金齿舵机。** 作者写得很明白：舵机模型就是策略真正训练的对象，换了执行器就是换了 plant，早期版本和塑料齿舵机上「可能走得很差或者根本不走」，看到烂步态要读成 plant 不匹配而不是策略不好。② **固件镜像只对 Bittle X / BiBoard V1.0 / Rev D/E**，板子不同要自己编。③ **策略是在固定 0.10 m/s 训的**，导出时带着这个范围，别的 `--command` 会被 clamp（stdout 会说）。④ 随仓策略实测 0.097 m/s、仿真里能过 12 mm 粗糙地形不摔 —— **这就是天花板，别期待跑跳**。⑤ 上面那条开环性质意味着**这不是一个能直接拿去做具身智能上层任务的底座**，它是一个学 sim2real 工程的极好教材。

### 3 · RoboTok —— 不采数据，从互联网视频里「检索」人类演示来训灵巧操作

**类型：软件 ｜ MIT ｜ 需要 GPU（DTW kernel 是 numba CUDA）｜ 周期 1–2 周 ｜ 数据侧有硬门槛，见坑**

- **是什么 / 为什么。** 莱斯大学 RobotPI Lab + NVIDIA 的工作（arXiv 2609.03199，**HF Daily Papers 116 赞，本期国外热度最高的一篇**）。思路是：机器人数据贵且覆盖不了长尾，那就**给一段人类操作视频当 query，从网络视频里检索出「运动学上相似」的人类演示**，拿来训灵巧策略。核心是**从「以演员为中心的参考系」下的 3D 手部轨迹里学一个隐运动空间**，外加一个 VN 模型从双手轨迹估计躯干 / 身体坐标系 —— 后者是关键，因为不把手部轨迹从相机系换到人体系，网络视频里同一个动作在不同机位下就完全不像。代码 **8-31 上线、9-4 更新，43 star，MIT**。

## 🧩 专题 · AI Agent × 3D 打印 / 自动建模

> 本期起新增的固定小节（用户点名要的方向）。它和主线不是两件事：**开源机械臂、灵巧手、四足的本体零件本来就是打印出来的** —— AM-ARM、LEAP Hand v2、SO-101、本期的 BittleJuice 全是 FDM 件。所以「让 agent 把改件从一句话做到上机」这条链路，对个人做具身来说不是外围工具，是**把硬件迭代周期从「等打样」压到「隔夜」**的那一环。本期两条正好卡在这条链路的两端：一条把链路铺满（国外），一条把它的成本打下来（国内）。

### 🌍 国外 · text-to-cad —— 从「一句话」到「打印机开始动」的 11 个 agent skill，MIT

**类型：软件 ｜ MIT（Thompson Labs LLC）｜ ★15.1k ｜ 2026-04-22 建仓、2026-09-09 还在推 ｜ 硬件 0 元起 ｜ 主要成本是 token**

- **是什么。** 不是模型，是**一套装进你现有 agent（Claude Code / Codex / Grok Build）的技能库**，把「自然语言 → 可打印实体」拆成 11 个各管一段的 skill：`cad`（出 STEP，可导 STL / 3MF / GLB）、`cad-viewer`（本地浏览器预览）、`step-parts`（找现成螺丝轴承电机的 STEP 件）、`dxf`（2D 切割图）、**`dfam-check`**（按工艺量壁厚、悬垂角、支撑体积、推荐摆放方向）、**`gcode`**（调真实切片器 CLI 出带打印机 profile 的 `.gcode`，先 dry-run 再执行）、**`bambu-labs`**（校验过的 gcode 上传到本地拓竹并谨慎启动打印）、`sendcutsend`（上传外协钣金前先查）—— 以及跟具身直接相关的 **`urdf` / `srdf` / `sdf`**：写连杆关节限位惯量、给 MoveIt2 加规划组和碰撞规则、出仿真世界。
- **为什么这条值得单独讲。** 市面上 text-to-CAD 的东西不少，**但绝大多数停在「生成一个 mesh」**。这个库把后面三步补齐了，而且补的方式是对的：`dfam-check` 的说明里写着工具**只报测量事实、不给 pass/fail**，判定留给工作流；`gcode` 强制先 `--dry-run`；`bambu-labs` 单独拆出来是因为它是**唯一会让物理设备动起来的那个**。这是一套知道自己在操作现实世界的设计。对具身的意义更直接：**`cad` 出零件 + `urdf` 出描述文件 + `sdf` 出仿真世界**，是同一套 skill 里的三件事 —— 你改一版夹爪，能顺手把 URDF 和仿真模型一起更新掉。
- **个人怎么切进去。**
  1. `npx skills add earthtojake/text-to-cad`（或 `claude plugin marketplace add earthtojake/text-to-cad` + `claude plugin install cad@text-to-cad`）。**更新也用 `add`，别用 `update`** —— README 特意点了这个坑：`update` 只刷新 lockfile 里已有的，新增的 skill 会被静默漏掉。

  3. **有打印机再往下**：`dfam-check` 量一遍摆放和悬垂 → `gcode` 切片（本机要先装 PrusaSlicer / OrcaSlicer 的 CLI）→ 拓竹用户才走 `bambu-labs`。

### 🇨🇳 国内 · MAC（Multi-Agent CAD）—— 清华 IEI Lab，4 个 agent 分工，同样的活 1/116 的 token

**类型：软件 ｜ MIT（Tsinghua University · IEI Lab）｜ ★939 ｜ 2026-07-30 建仓、2026-08-13 最后更新 ｜ 硬件 0 元 ｜ 成本 ≈ ¥0.3–3 / 件**

- **是什么。** 一条把「一句话 → 可打印 STEP」做成四段流水线的多智能体框架，跑在 **build123d**（参数化 code-CAD）+ LangGraph 上：**Spec Planner**（读需求出 `CADBrief` JSON）→ **Geometric Architect**（出 `ArchitectPlan` JSON）→ **Coder**（写 build123d 代码）→ **Aider 修复**（读 QA 报错 + build123d 参考手册改代码）。关键设计有两个：**① 各 agent 之间只传结构化 JSON，不回放对话历史** —— 每个 agent 只读上一段的产物，从不重读整段 transcript；**② 一个确定性翻译器 `_plan_to_code`**，把 `extrude / revolve / hole / boolean / pattern / mirror / fillet / chamfer / shell` 这些常见操作**零 token** 直接从 plan 翻成代码，LLM 只在 translator 不支持的边缘情况（`draft`、`rib`、自定义多边形）上被叫醒，代码里留 `# TODO_AIDER` 占位。
- **数字（官方自测，见下面的坑）。** 拿 **text-to-cad 的 10 个 prompt** 当 benchmark 同题对比：token **103.9M → 0.90M（116×）**、成本 **¥125.69 → ¥9.67（13×）**、特征通过率 **97.9% → 99.3%**。单件成本最夸张的是径向发动机气缸 ¥17.42 → ¥0.53（32.9×），最小的是航空 clevis 支架 ¥15.21 → ¥3.10（4.9×）。**多轮迭代的 token 本来是指数增长的（生成→执行→报错→修复→再生成，每轮把完整对话重新塞进去），传结构化状态把它拉成线性** —— 这就是 116× 的来源，不是模型更强。
- **对打印这件事的硬指标。** 它能出 **print-in-place 多体联动件**：一个 STEP 里放多个独立实体、**控制 0.4–1 mm 的配合间隙**，下机就能转，不用装配。README 里有球笼和陀螺仪的实拍 GIF。这比单体生成难，因为间隙差 0.2 mm 就是「卡死」和「散架」的区别 —— **能稳定控住这个间隙，说明它是在做几何，不是在做形状**。
- **个人怎么切进去。**
  1. `git clone` → `conda env create -f environment.yml` → **单独 `pip install --no-deps "aider-chat==0.82.3"`**。这一步别跳：aider 在 PyPI 上硬 pin `numpy==1.26.4`，而 build123d 要 `numpy>=2`，纯 pip 装会死锁，README 给了 macOS / Windows 两套绕法。
  2. 配 `multi_agent_cad/config.py`：默认走阿里云 DashScope，但**只是个 OpenAI 兼容 endpoint**，改 `DS_BASE_URL` + 各段 `*_MODEL` 就能换 OpenAI / DeepSeek / 本地 Ollama（换非 Qwen provider 记得把 `*_KWARGS` 置空，那里面是 Qwen 专用的 thinking 开关）。
  3. **产出物建议直接对着上一条做**：MAC 出 STEP → text-to-cad 的 `dfam-check` 量可打印性 → `gcode` 切片。**这两条拼起来就是一条完整的、成本可控的个人链路** —— 便宜的那段做几何，铺得全的那段做落地。
  4. **想做点别人认得的东西**：它的 `pipeline_cache/` 全是白盒 artifact（`cad_brief.json`、`architect_plan.json`、`temp_measurements_*.json`、`temp_missed_*.json` 带 `MISSED_CUT` / `FILLET_FAILED` / `CHAMFER_FAILED` 分类），**换个模型跑一遍、把 token 账单和失败分类公开**，就是一份有人会引的复现报告（缺口见下面第 4 点）。
- **坑。** ① **116× / 13× 是作者自己在 10 条 prompt 上测的、和对手是「同题不同 harness」的对比，没有第三方复现** —— 当成「结构化状态传递值得抄」的证据可以，当成通用结论不行；② **一个月没更新了**（8-13 最后一推），比主线那些当周热更的仓要谨慎；③ **必须有 API key，跑不了纯离线**，README 列的本地路线是 Ollama `qwen3-coder:32b`，**这台 A4000 16G 装不下**，真要本地得降到 14B 级并接受质量下滑；④ 便宜归便宜，Architect 和 Coder 两段仍建议挂强模型，别指望全链路用小模型还保持 99.3%。

### 专题分析：这条链路今年真正变了什么

1. **变的不是「模型会建模了」，是几何被拆成了可验证的中间产物。** 两条都在做同一件事 —— 把「这个件对不对」从 LLM 的直觉里拿出来，交给确定性工具：MAC 的 `temp_measurements_*.json` 直接量出特征尺寸并把失败分成 `MISSED_CUT` / `FILLET_FAILED` / `CHAMFER_FAILED`；text-to-cad 的 `dfam-check` **明确规定工具只报事实、不下判定**。**有了可量的中间产物，agent 才能自我修复；没有的话，多轮迭代只是多轮猜。** 这跟主线趋势里「给自己的结论配一个能推翻它的脚本」是同一条方法论。
2. **成本结构是这条赛道当前的真瓶颈，而且解法是架构层面的。** ¥125.69 跑 10 个件，对个人不是能持续玩的价格；降到 ¥9.67 就是了。降的方式值得单独记住：**别用单 agent 硬顶长对话**——分段 + 只传结构化 JSON + 常见操作走确定性翻译器。这个模式跟 CAD 没关系，**任何「生成→执行→报错→修复」的循环都能抄**。
3. **对具身智能的实际意义是本体迭代速度。** `urdf` / `srdf` / `sdf` 三个 skill 和 `cad` 在同一套工具里，意味着改一版夹爪、连杆或电池仓，**几何、机器人描述文件、仿真模型可以一次性同步更新**，不再是「改完 CAD 忘了改 URDF，仿真和实机对不上」。对着开源臂改件的人，这是当下最值得先接上的一环。
4. **一个明确的个人贡献口（本期唯一还开着的入口）。** MAC 的 benchmark 只有 10 条 prompt、只有作者自测、只测了一个模型。**拿同一批 prompt 换模型跑一遍，公开 token 账单和失败分类**，成本按它自己的数据算大约十几块钱，一天能做完 —— 这是这条链路上门槛最低、又确实有人需要的产出。比赛入口方面本期依旧空缺（见下）。

**这条链路上还值得盯的（本期不展开，后续轮换写）**：[ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp)（★28k，让任意 LLM 直接操作 Blender，mesh 侧自动建模的事实标准）、[Adam-CAD/CADAM](https://github.com/Adam-CAD/CADAM)（★5.1k，开源 text-to-CAD Web 应用）、[partcad](https://github.com/partcad/partcad)（★493，「硬件的包管理器」，模块化零件复用）、[SadilKhan/Text2CAD](https://github.com/SadilKhan/Text2CAD)（NeurIPS'24 Spotlight，学术侧基线）。

## 趋势观察

1. **具身模型正在退回成「标准 LLM 权重」，这对个人是决定性利好。** PhysBrain 1.5 最重要的一条不是 72.5 分，是它的 `architectures` 字段写着原版 `Qwen3VLForConditionalGeneration` —— 动作和未来状态全部编码进扩出来的一万多个 token，**没有一个自定义 head**。后果是 vLLM、LLaMA-Factory、ms-swift、veRL 全部开箱可用，社区一天内就出了 GGUF。对比 Isaac 0.5：36B、锁死 commit、连 stock Transformers 和 stock LeRobot 都不支持。**同一周里两条相反的路线，个人能吃到的那条非常清楚。**
2. **「诚实的仓」开始出现，而且诚实本身就是可复制的方法。** BittleJuice 自带 `blindfold_test.py` 证明自己的策略几乎不看 IMU，并明说判断迁移的指标是 slew 饱和率而不是 reward 曲线；RoboTok 在 README 里直接列出哪几个数据文件没放；EngineAI 说明仿真和真机是两套源码。这跟 9-9 那期观察到的「评测正在变成配置文件」是同一件事的另一面 —— **当分数变得可比，藏问题的成本就高于承认问题**。个人做项目可以直接抄这个格式：**给自己的结论配一个能让别人推翻它的脚本**。
3. **硬件开源的交付形态在往上游走：从图纸到源工程。** 9-2 的智元 X1 给的是图纸和 BOM，本期北京人形 Sprite 给的是 **FreeCAD 可编辑装配体**（CERN-OHL-S 强互惠）。差别是前者你只能照着做，后者你能改完再出加工件。代价是许可变严 —— Sprite 软件侧 AGPL-3.0、硬件侧 CERN-OHL-S，两个都是强传染的，**在下载之前先想清楚你打算拿它做什么**。
4. **参与入口：本期依然没有对个人开放且仍在报名期的比赛。** 逐条核过：「江源杯」2026 具身智能场景技能挑战赛（[中国电子学会公告](https://www.cie.org.cn/list_43/16724.html)）虽然组队要求写了「个人或团队均可报名」，但**报名已于 2026-08-25 截止**（9-3 到 9-4 的宜宾晋级赛也已结束，总决赛 12 月中下旬），且参赛主体限定为合法注册的企业 / 高校科研院所 / 初创团队；iCAN「金视线杯」具身智能应用设计挑战赛报名截止 **2026-09-24** 尚在窗口内，但**要求 3 名在校学生 + 1–2 名指导老师组队**，个人和非学生进不去（[赛事说明](https://xingxiancn.com/article/40644)）。
   **仍然有效的替代入口有两个**：[RoboChallenge](https://robochallenge.ai/)（9-3 推过，远程真机评测，不用买机器人就能拿分数，长期开放）；以及本期六条里现成的贡献口子 —— PhysBrain 1.5 的 **2B 档评测复现**（官方把 2B 排除在排名外、没有细节，这是真空）、Sprite 的 `validate_models.py` **资产校验 issue**、EngineAI 的 **单卡并行环境数实测**。**在没有比赛可打的月份，一个别人认得的复现数字比一张参赛证书有用。**
