### ★ TOP 1（深度）· MotionVLA —— 给 π0 喂一段「只看过去」的几何运动史，而且权重真的放出来了

**是什么。**
华中科技大学 hustvl + D-Robotics + 武汉大学的 CoRL 2026 工作，9 月 7 日开源，Apache-2.0。
它做的事情一句话讲清：**π0 / π0.5 看到的是一帧帧 RGB，MotionVLA 在旁边接了一路「这些像素刚才是怎么动的」。**

具体是一个冻结的 [TraceAnything](https://github.com/ByteDance-Seed/TraceAnything)（字节 Seed 的轨迹场编码器）
把历史帧压成紧凑的 trajectory-field token，然后：

- **Decouple** —— 当前的视觉 token 主动去这堆运动 token 里检索和任务相关的那部分，而不是把运动无差别拼进序列；
- **历史末端重建** —— 拿历史 end-effector 位置做辅助监督，把运动表征拴在「和控制有关的动力学」上，不让它跑成通用光流；
- **Recouple** —— 可选的一条路，把检索到的运动再注回 VLA 主干。

关键约束是 **strictly past-only**：只用已经发生的 RGB，不偷看未来帧。这一点决定了它是能上真机的，
而不是又一个「训练时用了未来信息」的离线增强。

**为什么现在值得做。**

1. **它是本周唯一一个「论文 + 代码 + 权重」三样都齐的 CoRL 具身工作。** 同一周开源的生数 Motus2 和北大 SEED-UMI
   都只有项目页（见趋势观察第 3 点）。MotionVLA 的 HF 仓 `hustvl/MotionVLA` 里躺着实打实的
   `MotionVLA-pi0/params/`（orbax 格式）+ `norm_stats.json`，9 月 7 日上传，能直接下来评。
2. **配方给全了。** 仓里有四个 YAML：`libero_finetune.yaml`、`robotwin_stack_blocks_three_finetune.yaml`、
   `robotwin_stack_blocks_three_eval.yaml`、`robotwin_touch_finetune.yaml`。数据格式写得很细 ——
   10 Hz LeRobot，三路相机 `observation.images.cam_high` / `cam_left_wrist` / `cam_right_wrist`，
   `observation.state` 和 `action` 都是 `[14]`（双臂关节 + 夹爪）。照着准备数据不会卡在猜字段上。
3. **它是一个「加法」而不是「换底」。** 你已有的 π0 / π0.5 工作流不用推翻，加一路运动 token 就行。
   对个人来说这意味着：验证成本低，失败了也不亏。

**个人怎么分步切进去（带成本和时间）。**

先把最硬的现实说清楚：**π0 家族的微调，A4000 16 G 跑不了。** openpi 官方给的 LoRA 微调最低显存约 22.5 GB，
全量更高。所以下面分三条路，按「我会先做哪条」排序。

**路线 C —— 只评不训（半天，0 元，本机能做）。这是我会先做的那条。**

```bash
git clone --recurse-submodules https://github.com/hustvl/MotionVLA.git
cd MotionVLA
git submodule update --init --recursive third_party/TraceAnything

conda create -n motionvla-pi0 python=3.11 -y && conda activate motionvla-pi0
python -m pip install -e pi0/openpi
```

下 HF 上的 `MotionVLA-pi0`，装 RoboTwin，用 `pi0/configs/robotwin_stack_blocks_three_eval.yaml`
在 `stack_blocks_three` 任务上评一遍，复核作者的数字。π0 推理显存大约 8–10 GB，16 G 应该能过。
**产出**：一份「作者数字在我机器上复现到了多少」的记录 —— 这是最有价值也最少人做的一件事。

**路线 A —— 只玩运动编码器（1–2 天，0 元，本机能做）。**

跳过 VLA，只跑 TraceAnything 那一段：拉 `trace_anything.pt`
（[depth-anything/trace-anything](https://huggingface.co/depth-anything/trace-anything/resolve/main/trace_anything.pt)），
用自己手机拍的一段桌面操作视频抽 trajectory-field token，看 Decouple 检索出来的区域是不是真的落在被操作物体上。
纯推理，16 G 绰绰有余。**产出**：一个「TraceAnything 在我的真实场景上靠不靠谱」的判断 ——
这个判断决定了后面两条路值不值得投。

**路线 B —— 真的训一版（3–5 天，¥100–300 租卡费）。**

按 `robotwin_stack_blocks_three_finetune.yaml` 准备数据，租一张 A100 40G 或双 4090 跑微调。
按国内算力平台的常见价位（4090 约 ¥2–3/小时、A100 40G 约 ¥6–9/小时）跑 20–40 小时，是 **¥100–300** 的量级。
**产出**：MotionVLA vs 原生 π0 在同一任务上的成功率对照表。

> 租卡价格是按公开报价的量级估算，不是我的账单。动手前自己去平台核当日价。

**坑。**

- **TraceAnything 的 checkpoint 必须和选中 YAML 里记录的 SHA-256 对上。** README 明确写了这条 ——
  版本不对不会报错，会静默用错权重，然后你花三天找「为什么复现不出来」。
- **pi0 和 pi0.5 必须两个完全独立的 Python 3.11 环境。** 两边都提供一个叫 `openpi` 的包，装进同一个环境会互相覆盖。
- **task-specific 模块是随机初始化、seed 42。** 换 seed 复现不出论文数字是正常的，别当成 bug。
- **HF 上目前只有 pi0 那一路的权重**，pi0.5 有 config 没 checkpoint。想跑 pi0.5 只能自己训。
- **RoboTwin 本身是个大工程**，装它的时间很可能比装 MotionVLA 长。先给 RoboTwin 留一天。

**出处与相关链接。**

- 原始出处：<https://github.com/hustvl/MotionVLA>
- 项目页：<https://hustvl.github.io/MotionVLA/> ｜ 论文：<https://arxiv.org/abs/2606.08288>
- 权重：<https://huggingface.co/hustvl/MotionVLA> ｜ 依赖的 RoboTwin：<https://github.com/RoboTwin-Platform/RoboTwin>

### 3 · LEVI · 机器人数据工坊 —— 把 HF 的 LeRobot 可视化器改成中文默认，并且把转换流程搬进来了

- **是什么**：基于 [huggingface/lerobot-dataset-visualizer](https://github.com/huggingface/lerobot-dataset-visualizer)
  的独立工作台，Apache-2.0，9 月 10 日建仓、9 月 12 日还在推，当前 v0.2.0。
  保留了上游的多相机与信号同步、视觉问答、动作分析、三维回放，加了**默认中文界面**和 **SAM3 对象标注**。
- **真正的增量是「完全内置的采集数据转换流程」**：上游只负责看，LEVI 把「采集数据 → LeRobot 格式」的转换打包进了同一个
  `uv.lock`。换句话说 **不用再单独 clone 一个转换项目、也不用装训练环境**，`uv run levi convert` 就能用。
  对个人来说这一条省掉的是最烦的那半天。
- **个人怎么切**（15 分钟）：

  ```bash
  git clone https://github.com/Koooki3/LEVI.git && cd LEVI
  export LEVI_WORKSPACE="$PWD/.state"
  cp .env.example .env
  uv sync --locked && uv run levi setup && uv run levi build && uv run levi serve
  # 看到「已就绪 / Ready」后访问 http://127.0.0.1:7860
  ```

  跑在远程机器上的话，本地 `ssh -L 7860:127.0.0.1:7860 USER@SERVER` 再开同一个地址。
- **坑**：只测过 Linux x86_64（Windows 推荐 WSL2）；需要系统里有 `ffmpeg` / `ffprobe`；
  `levi setup` 会去下载 Bun 1.3.10（校验官方 SHA-256），出网不畅的机器会卡在这一步；
  内置转换器输出 H.264/yuv420p，浏览器能不能播取决于你的视频编码。仓库目前 1 star，属于「东西是好的但还没人用」的阶段。
- 出处：<https://github.com/Koooki3/LEVI>
- 相关：[上游 lerobot-dataset-visualizer](https://github.com/huggingface/lerobot-dataset-visualizer)

### ★ TOP 1（深度）· AM-Bench —— 当机械臂装在一个会飞的底座上，「固定基座」这个默认假设就没了

**是什么。**
CMU / Penn State 等一批人的 CoRL 2026 工作，9 月 7 日开源、9 月 11 日还在推，Apache-2.0。
一个建在 Isaac Lab 上的**空中操作（aerial manipulation）**仿真套件和 benchmark。

它的出发点是一句很扎实的观察：**现有的机器人操作 benchmark 几乎全都假设底座固定在地上。**
空中操作把这个假设整个掀了 —— 手臂一动，它挂着的底座就动；推力有上限；气动效应还把两者耦合在一起。

套件给了四个维度的正交组合：

- **四种驱动状态的本体** —— `UAQuad` / `UAHexa`（欠驱动）、`FAHexa`（全驱动）、`OmniHexa`（过驱动），
  外加一个 `EE` 浮动末端 oracle（把任务逻辑从飞行动力学里剥出来单独看）。
- **12 个任务、三类交互** —— 瞬时接触、物体运输、铰接或受约束接触。
- **标准底层控制器** —— 4-DoF / 6-DoF PID、L1 自适应、全身 MPC，IK 走 Pyroki。
- **可逐环境开关的扰动** —— 气动阻力、地面效应、近壁效应、旋翼执行器饱和。
- **策略学习基线** —— ACT、Diffusion Policy、OpenPI（π0 / π0.5），**共用同一份 LeRobot 数据格式**，
  而且**每个任务都有脚本专家**。

最后那半句是它比大多数 benchmark 强的地方：有脚本专家意味着你不需要真机、不需要人类演示，
`record_demos_scripted.py` 直接产出可训练的数据集。

**为什么现在值得做。**

1. **零硬件成本，而且真的零。** 全套在本机跑，A4000 16 G 够用。这在「具身智能」这个普遍要先花几千块的领域里很少见。
2. **它把四个变量做成了正交开关。** 本体 × 控制器 × 扰动 × 策略，任何一个格子的实验都是一个完整可交付的结果。
   这正好是 README 里的四条标准要的「产出可预期」—— 你从第一天就知道终点长什么样。
3. **论文里有的表，仓库 README 里没有。** README 只给了 `PressButton` 一个示例命令。
   把 `list_envs.py` 的完整环境表跑一遍、整理成对照，是一个能直接开 PR 的空位。

**个人怎么分步切进去（带成本和时间）。**

**Day 0（半天到一天）—— 装 Isaac Sim 5.1 + Isaac Lab。这是全程唯一的大坑。**
README 写得很明确：需要**原生 Linux**（Ubuntu 22.04 或 24.04）+ 独立 NVIDIA GPU + Python 3.11，
并且 **WSL 和 Docker 不是维护路径**。Isaac Sim 本体十几 GB，加上 assets 和后面的数据集，磁盘留 100 GB。

**Day 1 上午（2 小时）—— 装 AM-Bench。**

```bash
git clone --recursive https://github.com/ambench/ambench.git && cd ambench
source ../IsaacLab/env_isaaclab/bin/activate
./scripts/setup/install.sh          # 会顺手初始化 Pyroki、编 acados 库
export JAX_PLATFORMS=cpu
export ACADOS_SOURCE_DIR="$(pwd)/ext/acados"
export LD_LIBRARY_PATH="$ACADOS_SOURCE_DIR/lib:$ACADOS_SOURCE_DIR/build:$LD_LIBRARY_PATH"
python scripts/environments/list_envs.py
```

那三个 `export` 一定要写进 `~/.bashrc`，否则下次开新终端就挂。

**Day 1 下午（30 分钟）—— 确认场景能加载。**

```bash
python scripts/environments/zero_agent.py \
  --task PressButton-Am-EE-Abs-PID-Direct-v0 --num_envs 1 --headless --device cuda:0
```

注意这里用的是 `EE`（浮动末端 oracle）本体 —— **先绕开飞行动力学确认任务逻辑通**，再换真本体。

**Day 2–3 —— 采数据。** 换成 `FAHexa`（全驱动六旋翼）跑脚本专家：

```bash
python scripts/data/record_demos_scripted.py \
  --task PressButton-Am-FAHexa-Abs-PID-Direct-v0 \
  --dataset_root <dataset-root> --state_keys ee_pos ee_quat gripper_width \
  --task_prompt "press the button" --num_demos 10
```

然后按你要训的基线转格式：`scripts/data/export_lerobot_to_openpi.py` 或 `scripts/data/dp/lerobot_to_zarr.py`，
转完用 `validate_lerobotdataset.py` / `validate_zarr.py` 校一遍。

**Day 4–7 —— 训一个基线并出表。** 训 **Diffusion Policy 或 ACT**（这两个在 16 G 上没问题）。
**OpenPI 那一路先别碰** —— 和国内 TOP 1 是同一个显存问题。
终点交付物：一张「同一任务 × 四种本体 × 扰动开关」的成功率表。

**成本合计：硬件 0 元、算力 0 元（本机）、时间约 1 周。** 真正的成本是磁盘和那半天装 Isaac Sim。

**坑。**

- **别在 Windows / WSL / Docker 上试。** README 点名不维护，撞上去的问题没人接。
- **`git clone` 一定要 `--recursive`。** `ext/` 下 vendored 了 acados、openpi、pyroki 三个 submodule。
- **`acados` 要现编**，机器上缺 BLAS / LAPACK 会让 `install.sh` 中途炸，且报错不指向根因。
- **`JAX_PLATFORMS=cpu` 是故意的**（Pyroki 的 IK 走 CPU），别当成性能问题改成 `gpu` ——
  改了会和 Isaac Sim 抢显存，16 G 上直接 OOM。
- **许可是混合的**：整体 Apache-2.0，但仓里再分发了 UMI / Diffusion Policy 源树（MIT，Columbia）
  和若干派生自 Isaac Lab 的文件（BSD-3-Clause）。再分发前看 `THIRD_PARTY_NOTICES.md`。

**出处与相关链接。**

- 原始出处：<https://github.com/ambench/ambench>
- 项目页：<https://ambench.github.io/> ｜ 文档：<https://ambench.github.io/docs/> ｜ 论文：<https://arxiv.org/abs/2609.00641>

### 2 · Robstride-API —— 给那批 ¥400 档 QDD 电机写的 no_std Rust 驱动，带线格式回归向量

- **是什么**：RobStride（瑞尔创智）系列执行器的 CAN 驱动，9 月 9 日开源，MIT OR Apache-2.0 双许可。
  这批电机（RS00/RS01/RS02/RS03/RS04）是这两年 DIY 人形和机械臂用得最多的低价 QDD 执行器，
  单个几百块，但厂商的协议是**私有的 29-bit 扩展 ID CAN 协议**，文档零散，每个做 DIY 的人都在重复解一遍。
- **为什么这个仓值得看**：它不是又一个「我照着手册敲了一遍」，而是**从 HIRO 自家嵌入式机械臂固件里抽出来硬化的**，
  请求字节和反馈缩放都有**捕获的线格式回归向量**兜底 —— 也就是说这些数字是从真实总线上抓下来对过的，不是照抄手册。
- **工程上干净得少见**：零依赖、零堆分配、无宏、无 `unsafe`，transport-agnostic（你自己实现 `CanTransport`），
  `std` 和 `no_std` 都能用。功能覆盖 enable / disable / run-mode 选择 / 参数读写 / 改 CAN ID，
  五个型号各自正确的反馈缩放，两 bit 反馈模式 + 六 bit 故障状态解码，还有共享总线上的陈旧帧过滤。
- **个人怎么切**：`examples/mock_bus.rs` 让你**没有电机也能先跑通**协议层。有电机的话，
  照 `docs/protocol.md` 实现一个 `CanTransport`（socketcan 或你板子上的 CAN 外设），半天能点亮第一个电机。
- **坑**：

### 🌍 国外 · ModelRift openscad-skill —— 重点不是「让模型写 OpenSCAD」，是那个彩色 STL diff

**是什么。** 一个 agent skill，9 月 2 日发布，18 star。做的是 OpenSCAD 的 **render → inspect → revise** 回路。

README 里对「为什么是 OpenSCAD」的论证值得一读：OpenSCAD 更像一门几何 DSL 而不是 GUI 建模器 ——
模型就是文本（图元、变换、布尔、模块、参数），LLM 可以改文件、渲染、看结果、再改一版，
**不需要操纵隐藏的场景状态**。FreeCAD 和 Blender 都有 MCP 集成，但它们那套更大、更有状态的接口对 LLM 仍然更难可靠驱动。

然后它话锋一转，说了句大实话：**「难的部分是判断几何」**。
现在的 LLM 空间理解仍然有限 —— 能看渲染图，但经常漏掉人一眼就看见的东西：
一个别扭的倒角、不均匀的壁厚、藏在另一个零件后面的碰撞、一个打不出来的间隙。
一张干净的等轴测渲染图**还会主动掩盖**那些换成剖视图或量一下就暴露的问题。

**它的答案是 `scripts/stl_diff.py`** —— 用 OpenSCAD 自己渲染两个 STL 版本的彩色差异：
**红色是加上去的材料，蓝色是去掉的材料，灰色是没变的体积**，四个标准相机（iso / top / front / right）。
这把「我这一版改了什么」从「你自己看两张图找不同」变成了一张可直接看的图。
配套还有不可变版本命名（`.scad` / `.stl` / `.3mf` / preview）、2D 投影和剖视图、Customizer 参数约定、
lazy union 的多对象 3MF 导出，以及两个零依赖参考件：**螺纹连接器**和**print-in-place 合页**。

**个人怎么切进去。**
装一个 OpenSCAD **2026.x 开发快照**（下面第一条坑），把 skill 装进你的 agent，
先让它把那两个参考件**原封不动编译一遍**（skill 里明确要求这一步），再让它从参考件改起。
做螺纹件就先出一个短的公母配合试件（coupon）再做大件；做合页就要求渲染打印姿态和 45° / 90° / 闭合三个状态。
半天能走完一轮。

**成本（含 API token）。**
这是纯文本 code-CAD + 回看渲染图的工作流。一个中等复杂度的工程件（支架、适配器、安装座这类），
大约 5–10 轮迭代，每轮 15–40 k input token（含 1–3 张预览图）+ 1–3 k output。
按 Claude Sonnet 5 的 $3/M input、$15/M output 量级算，**一个件大约 $0.5–1.5（¥4–11）**。
换成本地模型（上期 dsh-print3d 那条路）token 费是 0，代价是判断质量。

**坑。**

1. **硬要求 OpenSCAD 2026.x 开发快照**，不是 2021.01 稳定版。整套流程依赖 Manifold 后端和 lazy-union。
   skill 里写了检查命令：`openscad --version` 和 `openscad --help 2>&1 | rg -- '--backend|lazy-union'`，
   不满足就停下来让用户去装快照。**别把旧的稳定 release 当成快照**。
2. **不要只信退出码。** skill 明确要求：日志里出现 `ERROR:`、`WARNING:`、断言失败、未知模块、缺失 include
   或空的顶层对象，就判定构建失败 —— OpenSCAD 这些情况下退出码可能仍是 0。
3. **适用面是被明确框住的**：✅ 有精确尺寸、角度、孔、壁厚、间隙的中小工程件（支架、适配器、安装座、盒体、收纳、垫片）；
   ❌ 雕塑类 / 有机 / 解剖 / 装饰性自由形体，以及多个相互作用或运动零件的复杂装配。别拿它做不该做的事。
4. **仓库没有 LICENSE。** 18 star 的 skill 仓，法律上现在谁都不能直接用。这是本条最实际的阻碍。
5. skill 自己要求**人在环**：一张看着合理的渲染图仍可能藏着碰撞、坏间隙、或一个动不到全行程的机构。

### 🇨🇳 国内 · idea-to-print · 一句话造物 —— 上期说「最空的那一格」是 DfAM 检查器，这期它出现了

**是什么。** 中文优先的三件套 agent skill + 配套 Python 工具，MIT，9 月 8 日建仓、9 日更新，13 star。
串起来的是：**图像生成 → 混元 3D → Blender → 几何门 → Bambu Studio 切片 → 交付**。

三个 skill 分工清楚：`idea-to-print`（编排与作业账本）、`printable-modeling`（生成与建模）、
`3d-print-workflow`（几何门、切片、打印机读取）。

**先说最重要的那一个文件。**
上一期的专题分析里我写过一句：「整条链路最空的一格是 agent 可调用的 DfAM 几何检查器，
形态应该是确定性的、返回 ok / warnings / blocked」。这期它出现了 ——
`skills/3d-print-workflow/scripts/printability_gate.py`：

- **19 个具名检查**：`input_integrity`、`watertight`、`edge_manifold`、`vertex_manifold`、`winding`、
  `degenerate_faces`、`duplicate_faces`、`components`、`outward_normals`、`build_volume`、`self_intersection`、
  `minimum_wall`、`minimum_detail`、`minimum_connection`、`base_contact`、`stability`、
  `appearance_fidelity`、`slicer_islands`、`support_removal`。
- **三态退出码**：`0 = PASS`、`2 = FAIL`、`3 = UNKNOWN`。注意 UNKNOWN 也是非零 —— **不确定即不放行**。
- **不允许结果覆盖**：profile 的键是白名单校验的，出现未知键直接抛
  `Unknown profile keys (no result overrides allowed)`。也就是说**你不能靠改配置把一个 FAIL 说成 PASS**。
- **单位必须显式声明**：`units` 不等于 `mm` 直接拒绝。（毫米/米搞错是这条链路上最常见的一类事故。）
- 文件头自己写着：「No mesh repair, evidence overrides, slicer or printer operations are performed.
  PASS certifies only required, implemented checks.」—— 它明确拒绝替你修，也明确说 PASS 只覆盖它真的检查了的那些。

**第二个值得抄的是证据分级。**
`references/acceptance.md` 给了七级证据表，每一级都写了**「不能证明什么」**：

| 阶段 | 证据 | 不能证明 |
|---|---|---|
| Modeled | 可编辑源、单位、包围盒、渲染网格视图 | 可打印的几何 |
| Mesh checked | 拓扑报告 + 断开件/壁厚/自交检查 | 打印强度、稳定性或支撑 |
| Sliced | 实际机器/喷嘴/材料/热床、层与支撑预览、哈希、时间重量、保留的警告 | 物理成功 |
| Sent | 一次唯一记录的下发尝试与结果 | 打印机已接受/已开始 |
| Started | 新的匹配任务 ID + PREPARE/RUNNING 里连贯的层 | 附着或成品 |
| Completed | 匹配的 FINISH / 全部层，或标注过的用户完成报告 | 表面质量或支撑好不好拆 |
| Accepted | 对形状、细节、断裂、支撑去除的实物检查反馈 | 一套通用的模型/材料预设 |

这张表是整条链路上我见过的第一份**把证据边界写下来**的东西。前几期的项目都在写「检查项」，没人写「这个检查不能说明什么」。

**第三个是尝试预算。** 默认 **2 次生成、3 次局部修复、1 次参考纠正**；连续无改善就退出策略，
达到上限时**交付最佳候选 + 未完成项清单**，而不是无限重试或假装成功。
用户评价和 agent 评价分开存，**用户的否决不会被后续 agent 评价覆盖**；模型、配置或截图一变，关联检查自动失效。

**个人怎么切进去。**
1. Python 3.11+，`pip install -r requirements.txt -r requirements-modeling.txt`（NumPy / SciPy / trimesh / manifold3d / rtree）。
   Blender 和 Bambu Studio 各自单独装。
2. 先**只跑几何门**：拿你手上任何一个 STL，写一份 `printability-profile.json`（仓里有 example），
   跑 `printability_gate.py`。这一步零 API 费、零云端，十分钟。**我建议所有人先做这一步** ——
   哪怕不用它的生成流程，这个门也能直接接进自己的工具链。
3. 要跑生成：设 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`，
   先 `python skills/printable-modeling/scripts/hunyuan31_api.py config-check`（只检查配置不提交任务）。

**成本（含 API token）—— 这条链路的钱分两笔，要分开算。**

- **第一笔：agent 编排的 token。** 这个流程比 code-CAD 更吃图像 —— 概念图、六视图灰模渲染（正/侧/左右斜/背/底）、
  切片关键层截图，每一轮都要回看。一个件 10–20 轮，**大约 $1–3（¥7–21）**，比上面 OpenSCAD 那条贵一倍左右。

### 专题分析：这一周这条链路上真正变了什么

**1. 上期点名的那个空格被填上了，而且填得比我预期的狠。**
上一期我写「整条链路最空的一格是 agent 可调用的 DfAM 几何检查器，形态可以照抄 orcaslicer-mcp 的
`check_profile_physics` —— 确定性、返回 ok / warnings / blocked」。
`printability_gate.py` 就是它，但它比那个形态更强硬：**UNKNOWN 也是非零退出**（不确定即不放行），
**profile 的键是白名单，不允许任何结果覆盖**，**单位必须显式声明 mm**。
换句话说它默认 agent 会试图绕过门，然后把绕过的路全堵死了。这是第一次看到有人按「防 agent 自证清白」来设计这个门。

**2. 两个仓不约而同地不再相信「渲染图看着对」，但走的是两条不同的路。**
openscad-skill 的答案是**让差异可见** —— 彩色 STL diff 把「这一版改了什么」渲染成红/蓝/灰，
不靠 LLM 去两张图里找不同。idea-to-print 的答案是**让证据分级** —— 七级表，每级明写「不能证明什么」，
切好片不等于打得出来，打完不等于表面质量好。
前者解决「改动看不见」，后者解决「结论越界」。这两个是这条链路上一直没人处理的两类失败，
而且都不是靠换更强的模型能解决的。

**3. 尝试预算第一次被当成一等公民，因为它直接等于钱。**
idea-to-print 默认 2 次生成 / 3 次局部修复 / 1 次参考纠正，连续无改善就退出并交付「最佳候选 + 未完成项」。
前两期的项目都没管这件事 —— 因为它们跑的是本地模型或纯文本 code-CAD，重试便宜。
一旦链路里接进按次计费的云端图生 3D，**无限重试就是无限账单**，预算就必须写进流程而不是留给用户自觉。
这是这条链路从「能跑通」走向「能天天跑」的必要一步。

**4. 还空着的一格换成了「逆向」。**
绝大多数开源机器人只发 STL。想让 agent 参数化改一个件，得先有可编辑的实体。
tianjin66 这周放的 Microduck STEP 逆向（30 件，附 SHA-256、偏差、体积和切削测试记录，
M12 镜头座从 491 面收到 53 面、7.73 MB 收到 0.21 MB）证明了这条路走得通，
**但它是一次性成果，不是可复用的工具链** —— 没有哪个 agent 现在能自己跑通「STL → 干净的可编辑实体」。
这是「改件 → 打印 → 上机」闭环里剩下的那个断点，也是下一个值得有人做的东西。

**1. 硬件侧这周在「做配件」，不在「做整机」。**
我用 10 个硬件向查询词扫了 09-01 之后创建的新仓，star > 0 的不到 20 个，且多数是课程作业。
真正有内容的硬件动作全是围着别人的本体做增量：microduck-playground 的秋千座和参数化高跷、
Robstride-API 给市售电机写驱动、tianjin66 把 Microduck 的 STL 逆向成 STEP。
**这不是坏消息。** 一套整机的门槛是几千块加几周，一个配件的门槛是一卷料加几个电机，低一个量级。
开源本体多到一定程度之后，「给现有本体做增量」会比「再造一台」更有产出效率 —— 这周看起来就是那个拐点。

**2. π0 / π0.5 正在变成这一代的 ResNet。**
本周开源的三个 CoRL 2026 工作，共同点是**把「另一路信息」接到 π0 家族上**：
MotionVLA 接几何运动轨迹场，AM-Bench 接一个会飞的底座，[EgoWAM](https://github.com/GaTech-RL2/EgoWAM)
接第一人称人类视频。没有人在重新设计底座，大家都在往上接东西。
对个人的含义很直接：**学 openpi 的那套接口比追具体模型更划算**，因为接口在复用，模型在换。

**3. 「发论文不发码」这周特别集中，看到 arXiv 别急着以为能跑。**
生数科技的 [Motus2](https://github.com/shengshu-ai/Motus2)（自进化通用世界模型，11 star）
README 里的开源清单是**七个全部未勾选的 checkbox**，写着「计划在 2026 年 9 月内逐步放出」；
北大 + 三角洲智能的 [SEED-UMI](https://github.com/Tengbo-Yu/SEED-UMI)（人和机器人共戴同一副外骨骼，
CoRL 26）整个仓只有项目页、PDF 和一个 Next.js 站点，**没有一行代码、没有一个 CAD 文件**。
两个都过不了本系列的「技术可达成」这一条。列在这里是因为它们的想法值得跟，但**现在别排进你的计划表**。

**4. 数据工具在往中文化 + 去依赖走。**
LEVI 把 HF 的 dataset-visualizer 改成中文默认，并且把数据转换内置进同一个 `uv.lock` ——
不用再 clone 第二个项目、不用装训练环境。这类活儿不需要显卡、不需要机器人、不需要许可谈判，
**是个人最容易插进去的口子**，也是最容易被低估的口子（LEVI 现在 1 star）。
