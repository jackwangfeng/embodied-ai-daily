### ★ TOP 1（深度）· OpenWAM —— 世界-动作模型的「对照实验」被整套开源了，包括 20 多个消融检查点

**类型：软件 ｜ Apache-2.0 ｜ ★493（建仓 5 天）｜ 2026-09-06 建仓、2026-09-10 还在推 ｜ 清华 + 北大 + 港大 + 浙大 + 港中文 + 上交 + NUS ｜ 硬件 0 元 ｜ 单卡可做的是「评测」不是「训练」**

- **是什么。** 一个把 **World–Action Model（WAM，世界模型 + 动作模型）** 的设计选择全部拆成可替换模块、并把对照实验结果连同检查点一起放出来的研究基座。三块：
  - **OpenWAM-Infra** —— 4 个视觉编码器 × 5 个视频骨干（Wan2.2-TI2V-5B / Wan2.1-VACE-1.3B / Wan2.1-I2V-14B / Cosmos-Predict2.5-2B / Cosmos3-Edge）× 6 种架构变体（`single_system` vanilla/moe、`dual_system` joint_self_attn/joint_cross_attn/idm、`tri_system`）× 4 种注意力掩码，全部藏在**同一个 trainer、同一个 policy server、同一套评测协议**后面。
  - **OpenWAM-Study** —— 六个**顺序**提问的对照实验（架构 → 骨干 → 表征 → 视频↔动作交互 → 数据配方 → 去噪策略），每一问都在前一问定下的条件里测。
  - **OpenWAM-α** —— 按结论搭出来的预训练模型，518M 帧 / 约 6400 小时第一人称人类 + 机器人数据，80 维统一动作空间，在 8 个仿真 benchmark + 3 个真机平台上评测过。
- **为什么现在值得做。** 这个领域今年的通病是「每篇论文一个 monolithic 实现」：换个骨干、换个注意力掩码就得重写一遍训练代码，于是**没人能判断某个提升到底来自哪个设计选择**。OpenWAM 干的事情不是又发一个更强的模型，而是**把六个设计维度正交化，然后把每个格点的检查点都传到 HF 上**。翻一眼 [HF 组织页](https://huggingface.co/OpenWAM) 就明白它的诚意在哪：`robotwin_dual_system_joint_self_attention` / `..._joint_cross_attention` / `..._joint_cross_attention_detach` / `..._idm` / `robotwin_single_system_vanilla` / `..._moe` / `robotwin_tri_system_joint_self_attention` 一字排开，还有 `..._isolated` / `..._mutual` / `..._video_sees_action` 三个注意力掩码变体，以及 `pretrain_robot_only` / `pretrain_ego_robot_cotrain_mutual` / `pretrain_two_stage_*` 这一组数据配方对照。**这是把「消融表格」变成了「可下载的对象」。**
  三条结论本身也值得记住（[项目页 Findings](https://openwam-official.github.io/)）：① 上游世界知识靠**足够强的生成式骨干 + 紧凑而信息密集的隐空间**传下来 —— 重建式编码器不是唯一选项，带维度压缩的表征式编码器同样好用；② 世界-动作协同需要**独立的动作容量 + 训练时显式的世界→动作信息流 + 推理时同步联合去噪**；③ 具身预训练主要改善的是**域外泛化**，第一人称视频 + 机器人数据**一阶段共训**优于两阶段。
- **个人怎么切进去（分步、带成本和时间）。** 先把话说清楚：**训练这东西个人做不了**，README 自己写着推荐 8×80GB。个人的入口是**评测和复现排序**，而这恰好是它最缺第三方数据的地方。
  1. **第 0 步（30 分钟，0 元）**：`pip install -e .`，只装基础环境。别碰 Cosmos extras（要编 transformer-engine，`nvcc` 必需）。`deepspeed` 是源码分发、装的时候现编，`gcc` 得在 PATH 上 —— 这两点是最常见的第一道墙。
  2. **第 1 步（半天，0 元 + 电费）**：`python scripts/download_assets/download_benchmark_data.py` 选 **LIBERO**（8 个 benchmark 里数据量最小、评测 client 最成熟，见 [`benchmarks/libero/`](https://github.com/OpenWAM-Official/OpenWAM/tree/main/benchmarks/libero)），再 `download_openwam_checkpoints.py` 下 **[`robotwin_dual_system_joint_self_attention_wan21_vace_1_3b`](https://huggingface.co/OpenWAM/robotwin_dual_system_joint_self_attention_wan21_vace_1_3b)** —— **专挑 1.3B 那个 VACE 变体，它是这批里唯一能塞进 16G 显存做推理的**。每个检查点目录自带 config，`bash scripts/deploy.sh <ckpt_dir>` 直接起 policy server。
  3. **第 2 步（1–2 天）**：跑 **同一个 benchmark、两个只差一处设计的检查点**。最便宜、结论最干净的一对是 `robotwin_dual_system_joint_cross_attention` vs `..._joint_cross_attention_detach` —— 只差「动作梯度是否回流进视频 DiT」这一个布尔量。把两条曲线和成功率贴出来。
  4. **第 3 步（想留下点东西）**：Support Status 表里 **SimplerEnv 和 Calvin 都标着 `Planned`**。这两个环境的评测 client 是**结构清晰、边界明确、不需要 GPU 集群的活**，照着 `benchmarks/libero/` 的 WebSocket client 抄一份就是一个有人会用的 PR。这是本期最实在的一个贡献口。
- **坑与风险。** ① **别被 ★493 骗去训练** —— 8×80GB 是 Wan2.2-5B 及更小骨干的推荐配置，A4000 单卡连 5B 的训练都起不来，微调也别想；② 1.3B 变体是**评测可行**，不代表**质量可比** —— 它在原文里就是骨干消融的下界，拿它的分数去和 α 比毫无意义；③ 8 个 benchmark 的数据下载量很大，`assets/` 会迅速吃掉几百 GB，先看盘；④ 论文 09-09 才上 arXiv、代码 09-06 才放，**接口很可能还在动**，锁个 commit 再开始；⑤ 那 20 多个 study 检查点没有单独的 model card，靠命名区分，配对之前把每个目录里的 config diff 一遍再下结论。
- **出处。** [OpenWAM-Official/OpenWAM](https://github.com/OpenWAM-Official/OpenWAM)

### 2 · qdd-joint —— 从零手写的 QDD 关节驱动器，一条命令自动认出电机参数

**类型：硬件（固件 + 上位机）｜ MIT（vendor 目录 Apache-2.0 © ST/Arm）｜ ★2 ｜ 2026-08-23 ｜ 整套约 ¥400–700**

- **是什么。** 面向人形 / 足式机器人关节的**准直驱（QDD）无刷驱动器完整控制栈**，对标 MIT Mini-Cheetah / 宇树那类关节的控制架构。M0–M7 里程碑全部标 ✅：SVPWM、闭环 dq 电流环（PI + 解耦前馈）、级联位置/速度环、**MIT 阻抗模式**（`iq = kp·(p_des − p) + kd·(v_des − v) + iq_ff`，就是人形机器人那个标准关节接口）、二类 PLL 编码器跟踪观测器、CRC16 二进制协议、Qt/C++ 实时上位机。
- **两个真正值得抄的设计。** ① **`identify` 一条命令做完全部参数辨识** —— Rs（V/I）、Ls（电压阶跃的伏秒积）、极对数 + 编码器方向 + 零点偏移（单次开环扫描的最小二乘拟合），结果自动落 flash 最后一页。传统流程里这一串是手调常数，这里被换成一次转子转一圈。② **SIL（软件在环）+ CI 门禁** —— `control/` 层是纯可移植 C，在**主机上**对着一个 PMSM 数学模型验证：电流环阶跃、完整位置级联、**以及整条辨识链（仿真电机 → 辨识出的参数）**，9 个测试套件由 CI 把关。换句话说，**没有电机也能把控制算法跑到有把握再上板**。
- **零框架依赖。** 不用 ST MCSDK、不基于 SimpleFOC、不是 ODrive 的 fork，寄存器级驱动直接压在裸 CMSIS 头上。想真正搞懂 FOC 的人，这份代码比任何库都好读。
- **个人怎么切进去。** ① **0 元第一步**：`tests/run.ps1`（或直接 gcc/clang 编 `control/`），在主机上把 SIL 跑通，看电流环阶跃和辨识链的输出 —— 这一步决定你要不要买板；② **买件（约 ¥400–700）**：控制板 **B-G431B-ESC1**（STM32G431CBU6 @170MHz，板载三相桥 + 三电阻采样，官方开发板，¥200 上下）、**AS5047P** 14 位绝对值磁编码器（¥30–60）、42 机座 BLDC（¥100–300，参数不用管、自动辨识）、24V 限流电源；③ 按 [`docs/board.md`](https://github.com/pantianen333777/qdd-joint/blob/master/docs/board.md) 接线（SPI1: SCK=PB3 / MISO=PB4 / MOSI=PB5 / CS=PA15，USART1 PB6/PB7 @921600）→ 串口敲 `identify` → `cl 0.5`（力矩）/ `spd 5`（速度）/ `move 90`（位置）；④ 上限玩法：把 MIT 模式接进你手上任何一条腿或一根臂，这块板就是宇树那类关节的**可读版**替身。
- **坑。** ① **★2、最后一次提交 2026-08-23**，是个人项目，别指望 issue 有人回；② README 的安全提示不是客套 —— **首次上电必须限流（≤2A）+ 降压（12V）**，反接电源当场炸功率级；`identify` 会让转子至少转一圈，**手和线离轴远点**，轴上别挂负载；③ 刷写脚本和主机测试脚本是 **PowerShell（Windows 路线）**，Linux 下要自己换 st-flash / openocd；④ 上位机要 **Qt 6**，编译比固件麻烦，先用串口 shell 也能玩全部模式；⑤ SIL 验证的是**控制算法**，不是**你的电机和布线** —— 绿灯不等于上板安全。
- **出处。** [pantianen333777/qdd-joint](https://github.com/pantianen333777/qdd-joint)

### 3 · NERV —— 给机器人接「神经系统」：脑、身、世界三种节点，中间那层负责路由、门控和留证

**类型：软件 ｜ MIT ｜ ★18 ｜ 2026-09-03 建仓、09-08 更新 ｜ 有完整中文文档 ｜ 硬件 0 元起（先跑仿真）**

- **是什么。** 一个把「语言模型大脑 + 机器人本体 + 世界（仿真或真机）+ 工具」四类节点解耦成独立进程的平台。节点之间**永不互相 import**，只通过注册表文件和五个接口（NERV/Operator、/Brain、/Body、/World、/Tool）见面。Body 和 Tool 走 **MCP**，World 走 ZMQ 上的 JSON 电机总线。
- **三个设计点值得记。** ① **双时钟** —— 大脑（System 2）每步推理一次，本体（System 1）用学出来的策略跑 30–50 Hz 直到一条命令结束，**策略永远不等模型**；② **每个接口都有数据面和控制面两层，而且不许穿透** —— 大脑能看到的只有传感器流（腕部相机、桌面相机、测距），**仿真器的 ground truth、场景真值、chase camera 全在控制面**，平台会主动拒绝「看起来像真值」的东西进观测；③ **硬件只在人「布防」之后才动** —— 每个动作过安全门，开关没拨之前本体拿不到任何指令，而且大脑会被告知原因（拒绝以 tool result 的形式回去，模型可以据此改主意）。
- **对个人的价值。** 09-03 那期的 quackd 是「给小机器人接个 LLM 大脑」，NERV 是同一个方向上**把工程边界画清楚**的版本 —— 一套动词（`move_joints` 这类 primitive、`move_forward` 这类 skill）写一次，仿真和真机是同一条电机总线的两个端点；技能执行完回报的是**测出来的量**（走了 2.20 m、失速、摔了、夹爪闭合），不是「已完成」。README 里那段 gpt-5.5 被要求「走到客厅」的未剪辑录像，三次 `move_forward` 分别测出 2.20 / 2.21 / 1.20 m，就是这个设计的产出。
- **个人怎么切进去。** `nerv serve` 起来 → 在注册表里选一个 brain（Claude / OpenAI 兼容 / Ollama / mock）× body × world 三元组建 session → 先用 **mock brain + MuJoCo world** 把回路跑通（0 元、0 硬件、也不烧 token）→ 换成真模型 → 有 LeRobot 臂再把 body 换成硬件驱动，**动作和动词一行都不用改**。想贡献：`nerv conformance <url>` 是它给出的节点一致性检查器，**照着 [`docs/nerv-body.md`](https://github.com/Yanshi-Robotics/nerv/blob/main/docs/nerv-body.md) 给你手上的臂写一个 body 节点并过 conformance**，是这个仓当前最缺的东西。
- **坑。** ① 抽象层次高，节点、注册表、会话、接口四层概念要先读完 [AGENTS.md](https://github.com/Yanshi-Robotics/nerv/blob/main/AGENTS.md) 再动手，直接摸 API 会绕；② ★18、刚建仓一周，body family 目前只有 humanoid 和 arm 两族，别的本体得自己写；③ 安全门是**软件**门，不能替代物理急停 —— `/hold` 保持姿态、摔倒会自锁存，但真机上该有的保险丝和拍钮一样都不能省。
- **出处。** [Yanshi-Robotics/nerv](https://github.com/Yanshi-Robotics/nerv)

### ★ TOP 1（深度）· Show-Harness —— 让 VLM 直接「玩」机器人，采数据只要一个浏览器

**类型：软件 ｜ Apache-2.0 ｜ ★158（建仓 4 天）｜ 2026-09-07 建仓、09-10 还在推 ｜ Show Lab @ 新加坡国立 ｜ 硬件 0 元起 ｜ 微调有 0.8B 档，A4000 能吃下**

- **是什么。** 一个 **embodied harness**：一层紧凑的语义接口，让视觉语言模型在**离散、增量的动作单元**上推理，再由本体专属的解释器把每个单元**确定性地**落成运动。关键在于责任划分 —— 解释器只做映射，**每一个物理决策仍然由 VLM 自己负责**。同一个接口下两种模式：闭源前沿 VLM **零样本**开机器人；小开源模型微调后**每步吐一个 action token**，无 planner。
- **为什么这条值得深讲（三个点，个人都吃得到）。**
  1. **GUMI —— 采演示不需要遥操作硬件。** 每个动作单元映射到一个键或一个按钮，人（或者一个会开 GUI 的 agent）**在浏览器里「玩」这个机器人**就完成了一次演示，每一步直接落成训练可用的 (observation, action) 对，**不需要后处理**。而且带 `--sim`：`python gumi/collect_rollouts_web.py data/rollouts_demo --sim`，开 `localhost:8600`，WASD 加方向键就能驱动夹爪 —— **在任何硬件到货之前，先把接口和数据格式摸清**。同一套键位还能在自主 rollout 时做人工接管。
  2. **微调档位一路铺到 0.8B。** [Show-Harness-VLMs](https://huggingface.co/showlab/Show-Harness-VLMs) 放了五个真机语料训出来的 LoRA：`qwen3_5_0_8b` / `2b` / `4b` / `9b` / `gemma4_e4b`，外加一个覆盖两个仿真器的 `qwen3_5_2b_sim`。作者自己的说法是**不到几个 H200 小时**就能把小模型调成可用策略 —— 折算到 A4000 上，**0.8B 那档的 LoRA 是本机真做得动的**，而演示数据（[Show-Harness-Data](https://huggingface.co/datasets/showlab/Show-Harness-Data)：真机 Franka / Piper rollout + RoboLab + ManiSkill）已经给你了。
  3. **插件是消融级的。** 每个插件挂在回路的一个阶段上，一个布尔量开关，**关掉时整条回路与「没有这个插件」逐字节相同**。想量某个模块到底值几分，这是少见的、设计上就支持干净对照的实现。
- **个人怎么切进去（分步、带成本和时间）。**
  1. **第 0 步（1 小时，0 元）**：`bash scripts/setup.sh base`（不带 `--real`，不装 RealSense / ROS 那一层），跑 `--sim` 的 GUMI，在浏览器里驱动一遍。**这一步就能判断这套动作词表适不适合你想做的任务。**
  2. **第 1 步（半天，只花 API 费）**：零样本模式。填 `configs/secrets.env`（默认 `GEMINI_API_KEY`，也能指任何 OpenAI 兼容端点），在 ManiSkill / Isaac-Lab 解释器上让前沿 VLM 自己开。**成本就是 token**：一步一次模型调用，一个几十步的任务大概几分到几毛钱一次 rollout，一天几十次 rollout 在十几块钱量级。
  3. **第 2 步（1–2 天，0 元）**：拉 `qwen3_5_0_8b` adapter + 基座（`ADAPTER=qwen3_5_0_8b WITH_BASE=1 bash scripts/model/download_vlm_model.sh`），本机 vLLM serve，仿真里跑微调模式。**从这里起完全离线，不再花 token。**
  4. **第 3 步（想留下点东西）**：用 GUMI `--sim` 自己采一批演示 → 走 [`train/`](https://github.com/showlab/Show-Harness/blob/main/train/README.md)（自建 venv，底层 LLaMA-Factory）出一个 LoRA → **把 0.8B / 2B / 4B 三档在同一批数据上的成功率贴出来**。作者放了五个档位但没给个人算力下的对比曲线，这是一份现在就有人想看的东西。
  5. **有真机再往下**：`--real` 加 Franka / Piper 硬件层，抄 `configs/site/franka.yaml.example`，**先跑 `scripts/check_setup.py`**（它会一次性检查环境、site 配置、标定、VLM 后端连通性、机器人和相机是否应答），再 `run_real.py`。

### 3 · OmArm One —— 每个受弯关节都走钢制轴承的打印臂，而且所有力矩数字都附了可重跑的推导脚本

### 🌍 国外 · design-os-3d-blender —— 把 Blender 变成 agent 的操作系统，重点是那个「拒绝含糊通过」的生产门

**类型：软件 ｜ MIT ｜ ★62 ｜ 2026-09-06 建仓、09-09 更新 ｜ Blender 5.2 LTS ｜ 硬件 0 元 ｜ 成本 ≈ 每个件几毛到几块钱 token**

- **是什么。** 一套装在 Blender 5.2 上的 agent 技能 + 执行契约 + 验证门 + 已完成实例。三个技能：`blender-agent-core`（原生场景执行、数值校核、交付配方）、`blender-image-to-3d`（参考图契约、分阶段建模、构造感知的视觉复核）、`blender-knowledge-workbench`（有界的 bpy 阅读包，防止模型瞎猜 API）。**执行契约**是 `scripts/agent_runtime.py` + `headless-run.sh`：每次 Blender pass 在隔离进程里跑，**最后一行 stdout 永远是 `AGENT_OK <json>` 或 `AGENT_FAIL <json>`**。
- **为什么这条值得单独讲 —— 它把「通过」定义得比大多数工程流程都严。** 核心是 [`scripts/production-gate.py`](https://github.com/jangtrinh/design-os-3d-blender/blob/main/scripts/production-gate.py)：你**在建细节之前**先写一份 build spec（`target_dims_mm`、`tol_mm`、`min_wall_mm`、`orientation_up`、`max_overhang_deg`、每个要紧的孔位 + 紧固件规格），门读 `.blend` 只回答一个问题 —— 这个几何满不满足这份契约。退出码是冻结的契约：`0` 全过、`1` 有要求没满足、`2` 输入无效或不完整、`3` 执行错误。
  真正少见的是它对**通过的边界**的态度（[`specs/README.md`](https://github.com/jangtrinh/design-os-3d-blender/blob/main/specs/README.md) 原文）：绿灯只证明「建出来的实体水密、是声明的毫米尺寸、有声明直径的声明孔位、过得了 STL 往返、过了两道粗糙的可打印性筛」。它**明确列出自己不证明什么** —— 不证明承载/刚度/疲劳（没 FEA 没试件），不证明打得成（没跑切片器，支撑、附着、翘曲、架桥、逐机收缩全在门外），不证明装配配合，不证明螺丝或热熔螺母真能进去。每份报告都把这些重复进 `exclusions[]`，每个没量的东西进 `coverage.unchecked[]`，**「不在 `coverage.checked[]` 里的说法，门就没做过」**。而且**没写 `target_dims_mm` 的件，门直接退出 2 拒绝运行** —— 理由是「它不会假装在给一个没人标过尺寸的件把关」。
  这条设计上的自觉，比它能建多复杂的模型重要得多。上期 text-to-cad 的 `dfam-check` 是「只报事实不下判定」，这一条是「下判定，但把判定的边界写进合同」—— **同一条方法论的两种成熟形态**。
- **和具身智能的接口在哪。** 仓里有两个已完成的机械臂实例，其中 [`builds/robot-arm-print-assembly/`](https://github.com/jangtrinh/design-os-3d-blender/blob/main/builds/robot-arm-print-assembly/README.md) 是**38 件配合原型，5 张板：32 件 PETG + 6 件 TPU**，按 220×220 mm 可用热床排的版，7 mm 边距、8 mm 件间距，PETG 和 TPU 分板。附 `parts-list.csv`（ID → 对象 → 板 → 材料 → 尺寸）、`plate-01..04-PETG.3mf` / `plate-05-TPU.3mf`、67 步可编辑装配动画（24 fps，帧 25–1429）+ `assembly-steps.csv` 把影片时间映射回打印件 ID。**这就是「改件 → 打印 → 上机」闭环里最容易被跳过、也最花时间的那一段（排版 + 装配顺序）被做出来的样子。** 另外还有一条 MakerWorld / 拓竹发布腿，做项目校验和发布约束。
- **个人怎么切进去。** ① **0 元**：只要 Blender 5.2.x + Python 3.10+（macOS/Linux），`export BLENDER_BIN=...`，跑 `python3 scripts/blender-knowledge.py check` 和三组 unittest（`tests/execution`、`tests/production-gate`、`tests/hq-coverage`），全用标准库，**不启动 agent 也不花 token**；② 抄 `specs/examples/bracket-m3.spec.json` 给你手上机械臂的一个替换件（夹爪指、电池仓盖）写 spec，再让 agent 去建 —— **顺序是先写 spec 再建模，反过来就没意义了**；③ 跑 `production-gate.py --scene part.blend --spec build.spec.json --report out/report.json --export-dir out/stl`，看 `coverage.checked[]` 和 `exclusions[]`；④ 交互式建模接 [blender-mcp](https://github.com/ahujasid/blender-mcp) 插件，同一个 pass 再走一遍 runtime。
- **坑。** ① **绿灯≠能打、更≠能用** —— 门自己列了一整页免责，`robot-arm-print-assembly` 的 README 也直说「未发布用于 250 g 负载运行或制造」，腕部力矩余量、薄壁、执行器适配件、保持结构、装配/工具可达性全是**未解决**；② `BLENDER_BIN` 默认值是 macOS 路径，Linux 必须自己设；③ **它是 mesh 侧（Blender）而不是参数化 code-CAD** —— 尺寸靠 spec 事后校核，而不是靠模型天生参数化，改一版尺寸不像 build123d 那样改个数就完；④ ORC 那批组件的**源模型不在公开仓里**（只有渲染衍生图），能拿到的是机械臂和手表上链盒两个实例；⑤ HQ coverage gate 只在它自己那条「显式受保护的启动路线」上生效，README 承认 C05 那次刷新是**绕过**自动前置保护直接调渲染器的 —— 门存在不等于门总在路上；⑥ 成本仍然是 token：Blender pass 要读 bpy 知识包、要看渲染复核，**一个中等复杂度的件几毛到几块钱**，多轮返工时留意账单。

- **成本这一栏是本期最值得说的数字：token 费可以是 0。** 它自带一段**面向本地小模型的精简 persona**（短句、明确指令、直接点名工具），配「3D 打印工程 Agent（本地版）」预设 + Ollama 上的 `qwen3:8b`，**全程离线免费** —— 只有电费。对照一下上期的账：text-to-cad 那条路子跑 10 个件 ¥125.69，MAC 优化后 ¥9.67；这一条把**打印执行段**的模型调用降到 0，因为这一段的活（切片、估算、悬垂检测）本质上是**确定性计算而不是推理**，只需要模型会正确地调工具。**这是「哪一段该给 LLM、哪一段该给代码」这条分界线被划对了的样子。**
  另一个细节也是为便宜服务的：生成类工具（STL / G-code / PNG）**默认直接落盘**到 `桌面/3Doutput/`（分 `stl` / `gcode` / `preview`）**只返回路径**，不把大段 STL 文本塞进上下文 —— README 明说「对本地小模型尤其重要」。8B 模型的上下文塞不起一个几万行的 STL。
- **个人怎么切进去。** ① `pnpm exec dsh plugin --profile web add dsh-print3d`，重启 DSH，任意预设的 agent 都能调 `print3d_*`；② **0 元第一步**：`scripts/` 下 5 个脚本可以**当纯 CLI 用**（`node scripts/xxx.cjs ...`），不装 DSH、不接模型，先手工跑一遍 `stl_analyze` 和 `gcode_estimate`，判断它的指标口径对不对你的胃口；③ 本地免费路线：起 Ollama（`qwen3:8b`）→ 选「3D 打印工程 Agent（本地版）」预设 → 一句话「给我一个 20×20×10 的方块 STL，再生成校准 G-code，估算打印时间」，看它是不是按 `gen_parametric_stl` → `gen_calibration_gcode` → `gcode_estimate` 三步走；④ **想扩能力**：[MODULES.md](https://github.com/weisofns/dsh-print3d/blob/main/MODULES.md) 写了加一个能力 = 加一个脚本 + 一个工具定义（+ 可选一个技能），不动现有模块 —— **补一个 OrcaSlicer 桥或者一个 Klipper/Moonraker 打印机控制工具，是这个仓当前最明显的缺口**，也是本期专题里门槛最低的贡献口。
- **坑。** ① **★2、单人项目、绑 DeepSeek Harness 生态** —— 不用 DSH 的人只能拿它当 5 个 CLI 脚本和 5 份 Markdown 知识包用（说实话这样也值），插件层不通用；② 安装指令是 PowerShell / Windows 路径（`桌面/3Doutput/` 也是 Windows 语境），Linux / macOS 下路径和命令都要自己调；③ `print3d_slice` 依赖本机装好 PrusaSlicer，**没装就整条断**（好消息是它明确报错而不是假装成功）；④ **参数化 STL 只有 7 种基本体 + gear**，复杂件还得靠 OpenSCAD 技能手写或者从上游（build123d / Blender）拿 —— 它是**执行段**的工具，不是建模引擎；⑤ 8B 本地模型跑得通不等于跑得好，工具链稳定 ≠ 工艺判断可靠，README 自己的安全红线写着「任何参数与 G-code 交付前都提示上机前人工核对，不声称绝对安全」，温度、通风（ABS/ASA/尼龙的 VOC）、机型/固件不明就先问 —— **这几句照做**。

### 专题分析：这一周这条链路上真正变的东西

1. **「通过」这两个字被拆成了合同条款，而且是双向的。** 上期看到的是「工具只报事实、不下判定」（text-to-cad 的 `dfam-check`）。本期看到的是下一步：**下判定，但把判定的覆盖面和排除项写进机器可读的报告**。design-os 的门每次都把 `coverage.checked[]` / `coverage.unchecked[]` / `exclusions[]` 一起交出来，还立了一条硬规矩 —— **没写目标尺寸的件，门拒绝运行**（退出码 2），理由是「不会假装在给一个没人标过尺寸的件把关」。这比「不下判定」进了一步：**不下判定是不担责，划清边界的判定是担有限的责**。对 agent 流水线来说后者才可用 —— 前者你还得自己写一层决策，后者可以直接接退出码。
2. **成本结构上出现了新的一刀：不是「让 LLM 更便宜」，是「把不需要 LLM 的段落拿走」。** 上期 MAC 的 116× 靠的是架构（分段 + 传结构化 JSON + 确定性翻译器），本质还是在优化模型调用。dsh-print3d 走得更远一层：**切片、悬垂检测、时间/耗材估算、刀路渲染，全都是确定性计算，模型在这一段的唯一职责是正确地调工具** —— 于是一个本地 8B 模型就够，token 费从「几毛一个件」降到 0。判断一段该不该给 LLM，有个很实用的判据：**这一段的正确答案是不是唯一且可计算的？** 是，就写成工具；不是，才让模型推理。
3. **上下文管理已经变成这条链路的一等工程问题。** 两条都在躲同一个坑：STL / G-code 是**巨大的文本**，塞进上下文既贵又会挤掉真正要推理的内容。dsh-print3d 的解法是生成类工具默认落盘只回路径；design-os 的解法是每个 Blender pass 在**隔离进程**里跑、只回一行 `AGENT_OK <json>`。**「工具的返回值是一个句柄，不是一堆数据」**——这个模式跟 3D 打印没关系，任何要处理大产物的 agent 流水线都该抄。
4. **具身侧最实际的进展是排版和装配顺序被做出来了。** 一个 38 件的机械臂配合原型，5 张板、PETG / TPU 分料、`parts-list.csv` 把 ID 映到板和材料、67 步装配动画再把影片时间映回打印件 ID —— **这些恰恰是「改件 → 打印 → 上机」闭环里最没人愿意做、又最容易把一个周末烧掉的活**。对着开源臂改件的人，先把这套 artifact 的组织方式抄过来（哪怕手工做），比先接 agent 更划算。
5. **本期最明显的两个个人贡献口（都在一天量级）。** ① 给 dsh-print3d **补一个 OrcaSlicer 桥或 Klipper/Moonraker 打印机控制工具** —— 它的模块化扩展说明写得很清楚（加一个脚本 + 一个工具定义），而现在只桥了 PrusaSlicer、完全没有打印机控制；② 给 design-os 的生产门**跑一批第三方 spec**，特别是**摆线件和薄壁件**（正好用本期主线的 Open-Gripper-Plus 那六个 STEP 当素材），把 `coverage.unchecked[]` 里反复出现的项目公开出来 —— 这直接告诉所有人这个门当前的盲区在哪。

**这条链路上还值得盯的（本期不展开，后续轮换写）**：[earthtojake/text-to-cad](https://github.com/earthtojake/text-to-cad)（上期国外条，11 个 skill 铺满链路，含 `urdf`/`srdf`/`sdf`）、[Pan-Chera/Multi-Agent-CAD](https://github.com/Pan-Chera/Multi-Agent-CAD)（上期国内条，token 1/116）、[gumyr/build123d](https://github.com/gumyr/build123d)（参数化 code-CAD 底座）、[ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp)（mesh 侧事实标准）。**具身接口段（URDF / SRDF / SDF 自动生成、灵巧手自制零件迭代）本期没有新东西值得单写，下期优先补。**

## 趋势观察

1. **「把消融表格变成可下载的对象」正在成为开源具身项目的新标配。** OpenWAM 传了 20 多个只差一处设计的检查点，Show-Harness 传了五个只差参数量的 LoRA，两家都不只是发一个最强模型。这件事对个人的意义比听起来大：**过去你要复现一个消融结论，得有集群；现在你只要能做推理，就能自己验一遍作者的排序对不对。** 这是本期最值得注意的结构性变化 —— 前沿工作的**可检验部分**第一次真正落到了单卡玩家手里。顺着这个逻辑，本期反复出现的那个贡献模式（拿作者的检查点/数据，在你自己的算力档位上跑出一条对比曲线并公开）已经不是「练手」，而是这些项目真实缺的东西。
2. **采数据这件事今年被两条不同的路各自打穿了硬件门槛。** 09-07 的 GRABETTE 是「手持设备，不要机器人」，本期 Show-Harness 的 GUMI 更狠：**浏览器里按 WASD 就是一次演示，每一步直接成训练对**，连采集设备都不要，而且 `--sim` 让你在硬件到货之前把接口摸完。这两条加起来意味着「没机器人就没数据」这个前提已经不成立了 —— 门槛从**硬件**转移到了**你愿不愿意花时间演示**。
3. **控制栈的开源正在往下走到「关节」这一层，而且带上了主机端验证。** 前几期是整机（Microduck、Sprite、BittleJuice）和臂（Star Arm、HumbleArm），本期的 qdd-joint 是**单个关节驱动器的完整 FOC 栈 + 一条命令参数自辨识 + 主机 SIL + CI**。这一层过去是「买宇树/T-Motor 的成品，或者自己啃 MCSDK」两个极端。中间这一档出现了，而且**先在主机上把控制算法验对再上板**的做法，是嵌入式侧少见的工程自觉。跟 09-10 BittleJuice 的 blindfold 自证脚本、本期 OmArm One 的力矩校核脚本是同一件事：**给自己的结论配一个能推翻它的脚本。** 这个模式在本期四条不同项目里独立出现，已经可以当成挑选项目的一条筛子了。
4. **「数字是推出来的还是宣称的」值得当成硬指标。** OmArm One ★0，但它给了扫描全关节空间最差姿态的质量模型和可重跑的校核脚本；design-os 的门把没量的东西列进 `coverage.unchecked[]`；Microduck 那两个挑战赛的数据卡把每个常数都标到源文件行号。反过来，本期看到不少 ★ 更高但只有一句 feature list 的仓（Open-Gripper-Plus 就是，硬件很实但文档极简）。**在个人可参与这个语境下，可验证性比 star 数更能预测你会不会浪费一个周末。**
5. **专题那条链路的分界线本周变清楚了：确定性计算的段落要从 LLM 手里拿走。** 详见专题分析第 2 点。这条判据（「这一段的正确答案是不是唯一且可计算的」）不限于 3D 打印，任何 agent 流水线都能用。

**真正现在就能提交、且对个人完全开放的，是这两个 —— 本期唯一的实在入口：**

1. **Microduck Stairs Challenge** ｜ CC-BY-4.0 ｜ HF 数据集 ｜ **纯 MuJoCo 仿真，零硬件，无截止日期**
   把 250 mm 高、14 个位控舵机的 Microduck 从地面弄上一级台阶并**站住**。提交物不是策略也不是视频，而是**一份 intent JSON**：14 个关节目标的若干关键帧 + 时间，评分器在固定的 plant 里回放并判定（控制周期 20 ms / 50 Hz）。判据是代码里那一行，作者把每一项都标到了源文件行号：`honest = s.up && lateral && s.x > RISER_X && s.above > 0.095 && s.feetOnTread >= 2`（`harness/rig3.mjs` 第 330 行）。
   **为什么值得做**：**这个 bar 从来没被达到过。** 及格线是 9 个鲁棒性格点里过 7 个，目前最好成绩是 60 mm 台阶高度下 **5/9**，而第六轮的裁判结论是「这是机器人和这一类动作的极限，而不是优化器的极限」。作者把判据、格点、当前记录、**负面结果**和整个 harness 全部公开，原话是「publishes ... so that somebody can beat it or show that it cannot be beaten」—— **推翻它和达到它同样算成果**，这在开放赛题里很少见。
   → <https://huggingface.co/datasets/craigm26/microduck-stairs-challenge>
2. **Microduck Ball Challenge** ｜ CC-BY-4.0 ｜ 同一个 plant ｜ **零硬件，无截止日期**
   让鸭子**够到并推动**一个 100 mm / 30 g 的球（不是踢 —— Pollen 已经有踢球策略了），从 450–1200 mm 距离、在它没法直着走过去的方位角上，14 个格点计分。两种参赛形态都从第一天起可评分：**authored move**（关键帧 + 混合，像 stairs 那样回放）或 **policy under a command schedule**（一个 `.onnx` + 一串 `[atSeconds, {vx, vy, vyaw}]`）。
   **头部空间极大**：作者公布的发现是「**bundled 的东西没有一个能追球**」—— Pollen 的两个踢球策略 **0/14**，一个被命令直着往前走的鸭子在 9 个核心格点里过 4 个，**而且不是预测的那三个**。也就是说随便一个稍微认真的方案都能刷新记录。
   → <https://huggingface.co/datasets/craigm26/microduck-ball-challenge>

**另外两个不是比赛、但确实缺人做的口子**（本期主线里已详述）：OpenWAM 的 **SimplerEnv / Calvin 评测 client**（Support Status 表里标 `Planned`，照 `benchmarks/libero/` 抄一份即可）；Show-Harness 的 **0.8B / 2B / 4B 三档在同一批数据上的成功率对比**（作者放了五个 adapter，没给个人算力档位下的曲线）。加上专题分析第 5 点里那两个（给 dsh-print3d 补 OrcaSlicer / Klipper 桥、给 design-os 的门跑第三方 spec），本期一共四个一天量级、有人会用的产出口。
