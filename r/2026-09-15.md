### ★ TOP 1（深度）· Easyhand —— 六个 SG90 舵机、一套 STEP、两百多块钱，做一只能抓杯子的五指仿生手

**是什么。**

一只**平面四杆连杆驱动的五指仿生灵巧手**，9 月 14 日建仓（昨天），采用 **CERN-OHL-P-2.0**
（permissive 型开源硬件许可，不传染、允许闭源衍生）。仓里一共 22 个文件，但该有的都有：
一份 STEP 总装、一份 PlatformIO 固件、两份中文文档（硬件/装配、控制系统），
外加实物正反面照片、三维图、爆炸图和三段演示视频（手指灵活度与手势、抓塑料杯、抓纸包）。

机械上的核心取舍写在第一句：**每根手指用一个 SG90 舵机，通过平面四杆连杆带动三个关节联动屈伸**，
拇指额外加一个旋转舵机。结果是 **16 个关节运动轴、6 个主动自由度**。

这不是「每指三舵机」的高配路线，是「一指一舵机 + 连杆耦合」的极简路线。
代价是手指关节不能独立控制（同一根手指三个关节的角度是耦合的），
好处是**整只手只要六个 ¥5 的舵机**，而且没有任何腱绳、滑轮、走线问题 —— 全是刚性连杆和销轴。

| 项 | 内容 |
|---|---|
| 驱动 | SG90 × 6（五指屈伸 + 拇指旋转） |
| 主控 | ESP32 30Pin / Type-C / CH340C（资料标 ESP32-D0WD、4 MB Flash） |
| PWM 驱动 | PCA9685，I²C 地址 `0x40`，50 Hz |
| 舵机供电 | 独立 5 V / 5 A 稳压锂电池组（**不接 ESP32 的 5V 脚**） |
| 打印 | 拓竹 PLA，层高 0.2 mm、2 层墙、15% 填充、树状支撑 |
| 五金 | Φ2 销轴 ×10/×12/×15 各 5 根；M2 金属球头扣 5 对（10 个） |
| 控制界面 | ESP32 内置 WebServer，热点 `DexterousHand_test`（**无密码**），`http://192.168.4.1/` |

**为什么现在值得做。**

1. **这是本系列做到第十一期，见过的「单位成本最低的、能真的抓起东西的五指手」。**
   翻一下台账：09-14 推的 Vision_Sync_Dexterous_Hand 驱动的是 BrainCo Revo2（商业灵巧手，五位数）；
   09-11 的 Open-Gripper-Plus 是双 ODrive + 摆线减速的两指夹爪；LEAP Hand v2 是研究级方案。
   **Easyhand 的整套物料按公开零售价粗算在 ¥200–300 量级**（详见下面的成本表），
   而且演示视频里它真的把一次性塑料杯和纸包抓起来了。
2. **它把「灵巧手」这件事的入场门槛降到了跟做个四轴机械臂差不多。**
   没有 FOC、没有 CAN、没有编码器、没有腱绳预紧，六路 PWM 加一块 PCA9685 就是全部电控。
   一个做过 Arduino 小车的人可以直接上手。
3. **作者把「不知道的东西」明确标成不知道**，这在 0 星新仓里很少见。README 和文档里几处原话：
   「未提供抓取力、额定负载或重复定位精度的测量数据」「程序角度不等于手指关节实际转角」
   「网页数值不能视为实测角度，抓握参数也不是力控制设定值」。
   **它不假装自己是个有力控的灵巧手，它就是一只位置控制的、连杆耦合的、便宜的手。**

**个人怎么分步切进去（带成本和时间）。**

**第零步 —— 先看视频，20 分钟，0 元。**
仓库首页直接嵌了三段 GitHub 托管的 MP4。先确认「连杆耦合手指到底能抓什么」，再决定买不买料。
这是唯一一个在花钱之前能做的判断，别跳过。

**第一步 —— 备料（¥200–300 量级，到货 2–5 天）。**

成本按公开零售价的量级估算（**不是作者给的核价单，作者没给价格**，下单前自己核）：

| 物料 | 数量 | 量级估算 |
|---|---:|---:|
| SG90 舵机 | 6 | ¥40–60 |
| ESP32 30Pin Type-C CH340C | 1 | ¥20–30 |
| PCA9685 驱动板 | 1 | ¥8–15 |
| 5 V / 5 A 稳压锂电池组 | 1 | ¥50–90 |
| Φ2 销轴（10/12/15 mm 各 5） | 15 | ¥10–20 |
| M2 金属球头扣 | 5 对 | ¥15–30 |
| 拓竹 PLA（本体用量） | — | ¥15–25 |
| 杜邦线、舵盘、紧固件 | — | ¥10–20 |
| **合计** | | **≈ ¥170–290** |

**注意作者自己标注的一句话**：「球头扣连接杆长度、紧固件明细和各销轴安装位置需结合总装模型核对；
上表未给出完整逐零件采购数量。」**所以打开 STEP 数一遍再下单，别照着 BOM 直接拍。**

**第二步 —— 打印（半天到一天，看你有几台机器）。**

```
下载 cad/left_hand_asm.stp
→ 用支持 STEP 的 CAD（FreeCAD 免费即可）打开总装
→ 按独立零件导出 STL
→ 切片：层高 0.2 / 2 层墙 / 15% 填充 / 树状支撑
```

**这一步是这个仓最大的摩擦点：仓里只有 STEP 总装，没有现成的 STL，也没有拆好的打印板。**
喷嘴尺寸、温度、摆放方向、支撑阈值都没给，得自己按机器定。
打完先清支撑和关节孔毛刺，**空载手动试销轴和球头扣能不能自由动，再装传动**。

**第三步 —— 接线与首次上电（2 小时）。**

逻辑连接（作者给了完整对照表）：

```
ESP32 3V3   → PCA9685 VCC
ESP32 GND   → PCA9685 GND
ESP32 GPIO21 → SDA
ESP32 GPIO22 → SCL
电池组 +5V  → PCA9685 V+（舵机电源端）
电池组 GND  → PCA9685 GND      ← 三方必须共地
```

舵机通道：拇指屈伸 CH0 / 食指 CH1 / 中指 CH2 / 无名指 CH3 / 小指 CH4 / 拇指旋转 CH5。

烧录：

```sh
# PlatformIO 打开 firmware/ 目录，板型 esp32dev，Arduino 框架
pio run
pio run --target upload
pio device monitor --baud 115200
```

依赖版本是**钉死的**：Espressif32 5.2.0（Arduino-ESP32 2.0.5）、
Adafruit PWM Servo Driver Library 3.0.3、Adafruit BusIO 1.17.4。别自己升。

**第四步 —— 校准（这一步决定成败，留一个晚上）。**

作者给的顺序不能颠倒：

1. **先卸掉舵盘或连杆负载**，烧录，确认每个通道对应哪个舵机；
2. 程序一上电就写自然姿态（**拇指屈伸 30°，其余五轴 20°**），
   **按这个姿态装舵盘**，装错了机械限位就全乱；
3. 小幅调单轴，确认方向和可用行程，按实际无干涉行程改 `main.cpp` 顶部的 `THUMB_MAX` 等限位；
4. 单轴过了再试预设手势 / 抓握 / 连续动作。

角度范围：拇指屈伸 0–90°，其余五轴 0–105°。四档速度 25 / 45 / 90 / 120 °/s，默认 45。
运动更新周期 20 ms，当前角度逐步逼近目标。
`SERVOMIN=102` / `SERVOMAX=492` 是 0–180° 指令到 PCA9685 计数的映射端点，**不是微秒**。

**第五步 —— 你能贡献什么（这才是推荐它的理由）。**

这个仓现在有四个明显的空格，每个都是半天到一周的活：

- **右手。** 仓里只有 `left_hand_asm.stp`，**是左手**。镜像一份右手总装，提 PR。
- **拆好的打印板 / STL 包。** 上面第二步那个摩擦点，你替所有后来的人省掉一次。
- **实测数据。** 抓取力、额定负载、重复定位精度 —— 作者明确写了「未提供」。
  一个数显推拉力计一百块钱，量五个手指的指尖夹持力，就是这个仓现在最值钱的数据。
- **把热点加上密码。** 现在 `DexterousHand_test` 无密码，作者自己写了「周围可连接热点的设备能够操作灵巧手，
  适用于本地受控演示」—— 说明他知道，只是还没做。

**坑与风险。**

1. **仓建于昨天（2026-09-14），0 星，只有作者一个人。** 结构、接口、角度映射都可能改。
   要在这上面做东西，先 fork 钉住 commit。
2. **只有 STEP，没有 STL，没有打印板，没有逐零件数量。** 前面说过了，这是真实工作量，别低估。
3. **无密码 AP + 无认证网页控制。** 只在你控得住的局域网/无网环境下用。
4. **SG90 是塑料齿的。** 连杆机构一旦装配干涉，堵转很容易崩齿。
   作者写了「如出现卡滞或持续堵转，切断舵机电源并检查装配与限位」—— 这句话要当真。
   备几个舵机，或者一开始就上金属齿的 MG90S（尺寸兼容，贵一点）。
5. **没有任何反馈。** 没有关节位置传感、没有力传感、没有电流采样。
   网页上那个 0–100 的「抓握参数」是**多轴协调的插值参数，不是力控设定值**。
   想做力控得自己加电流采样或者指尖触觉 —— 那是另一个项目了。
6. **左手 + 连杆耦合 = 不适合做 VLA 的执行端。** 如果你的目标是接 LeRobot / π0 做操作学习，
   这只手的自由度和可控性都不够。它适合做**人机交互、手势展示、教学、触觉实验的载体**。

### 2 · openarm-task-studio —— 给 OpenArm 双臂做的可视化任务编辑器，顺带一套摄像头动捕示教

**一句话**：在 Isaac Sim 里摆 Move / Grasp / Place 任务点并按序执行，
另外用 D435 或**普通 USB 摄像头**做上肢动作示教。GPL-3.0，中文 README，9 月 6 日建仓。

| 项 | 内容 |
|---|---|
| 目标本体 | [OpenArm](https://github.com/enactic/openarm)（Enactic 的开源双臂），走 [openarm_isaac_lab](https://github.com/enactic/openarm_isaac_lab) |
| 环境 | Ubuntu 22.04 + Isaac Sim **5.1.0** + Isaac Lab **2.3.0**，Isaac 侧 Python 3.11 |
| 动捕进程 | **系统 Python 3.10**（和 Isaac 分开），依赖 OpenCV + MediaPipe **0.10.21** + PyYAML |
| 能做 | 可视化建 Move/Grasp/Place 任务点、左右臂独立与并行、任务 JSON 存取与路径校验、MediaPipe 肩肘腕跟随与中立姿态标定、参数 GUI、纯 Python 单测 |
| 可选硬件 | Intel RealSense D435（没有就用普通摄像头）、ESP32-C3 记录按钮 |
| 演示 | [B 站视频：OpenArm + Isaac Sim 低成本动捕示教与双臂任务编排](https://www.bilibili.com/video/BV1gfMC6wEsw/) |

**为什么值得看**：它把「**遥操作示教的最低配版本**」做出来了 —— 一个笔记本摄像头 + MediaPipe，
不需要 VR 手柄、不需要主从臂、不需要动捕服。虽然精度肯定不如 D435，
但**「有没有」和「准不准」是两个量级的问题**，对个人来说前者更要紧。

**个人怎么切进去**：
① **没有 OpenArm 也能跑** —— Isaac Sim 5.1.0 + Isaac Lab 2.3.0 装好，先跑通 openarm_isaac_lab 自带示例，
再装 Task Studio，全程仿真，0 元（Isaac Sim 个人使用免费）。
② **把动捕那半拆出来单用** —— 动捕进程是独立的系统 Python 3.10 进程，
理论上可以摘出来驱动任何双臂，这是这个仓复用价值最高的部分。
③ **提可复现的 issue** —— 作者明确写了「复现失败时可以提交 Issue，并附上终端报错、系统版本和复现步骤」，
而且承认「README 无法覆盖所有机器的情况」。这种作者的仓，提 issue 的回报率高。

**坑**：
① **作者自己列了一串问题，照抄如下**：环境兼容性有限、部分错误提示不够清楚、
普通 RGB 摄像头的深度估计不如 D435 稳定、**避障不是真正的整臂运动规划**（是 TCP 对场景 AABB 采样）。
② 作者原话：「**请勿直接用于无人值守的真实机器人生产环境**」。
③ **装不上的锅八成在版本** —— 作者写「安装问题大多来自 Isaac Sim、Isaac Lab 和 OpenArm Isaac Lab 版本不匹配」。
先让 openarm_isaac_lab 的官方示例跑起来，再碰这个仓。
④ **A4000 16 G 跑 Isaac Sim 5.1 是边缘配置**，能起但场景复杂度上不去；作者只说要「能正常启动 Isaac Sim 的图形环境」，没给显存下限。
⑤ **披露**：作者主动声明「本项目使用 AI 辅助开发」，并说明功能设计、运行验证和最终取舍由本人完成。
这不是缺点，是应该被鼓励的做法 —— 但你读代码时心里要有数。

### 3 · mini-quadruped —— 纯 numpy 重写四足步态控制，24 项自校验，「已知边界」一节比正文还硬

**一句话**：不依赖 MuJoCo、Drake 或任何物理引擎，**全部 numpy**，
核心是一个**运动学仿真器**而不是动力学仿真器 —— 机身怎么动完全由「落地的脚不打滑」这一条约束解出来。

```bash
python -m quadruped.test_quadruped    # 24 项自校验测试
python demo_trot.py                   # 8 组机动指令对照表 + demo_trot.svg
```

四个文件、一个 DESIGN.md，全部代码加起来不到 10 个文件：

| 文件 | 内容 |
|---|---|
| `kinematics.py` | 3-DOF 腿（γ 侧摆 / α 髋 / β 膝）FK、闭式 IK、解析雅可比、可达性钳制 |
| `gait.py` | 步态相位、摆动/支撑轨迹、转向、偏航精确合成、Raibert 落足点 |
| `controller.py` | TrotController（步态 + Raibert 反馈 + 偏航前馈）、KinematicSimulator、2D Procrustes 位姿解算 |
| `stabilizer.py` | 凸包 / 支撑多边形 / 稳定裕度 / 切比雪夫中心 / ZMP / 摩擦锥力分配 |

**为什么推荐它**：本系列翻过大量四足仓，绝大多数是「跑 Isaac Lab 训一个策略」。
这个仓走的是相反方向 —— **把运动学那一层从零写一遍，并且用可复现的数字证明它是对的**。
实测表里前进 vx=0.40 → 实际 0.40000 m/s、高度偏差 2.8e-16 m；
FK→IK 往返 3.2e-15 rad；雅可比 vs 数值差分 5.8e-10。
**零依赖、零硬件、零显卡、几秒钟跑完** —— 这是全期门槛最低的一条。

**它最值得学的不是代码，是 README 的「已知边界（诚实记录）」一节**，五条全是自曝：

1. **是运动学仿真，不是动力学仿真** —— 忽略 roll/pitch、地面反力与足端滑移，
   接触被建模成「世界坐标位置冻结」。能严格检验步态逻辑，**回答不了「会不会翻」「会不会打滑」**。
2. **力分配是静态的，摩擦锥是投影而非重解** —— 伪逆解接触力后把越锥的切向分量就地限幅，
   限幅后竖直分量仍满足旋量，**但切向总量不再满足**：作者实测 50 N 前推时**有 21.2 N 剪切被丢掉**。
   它只用来回答「力矩可行吗」，不参与仿真闭环。
3. **爬行步态只验证了支撑多边形，机身横移没实现**（名义质心裕度 0、切比雪夫中心余量 6.7 cm）。
4. **交错落地时接触集可能只剩 1 个约束**，此时偏航运动学上不可观测，代码退回全部继承接触。
5. **dt 与步态周期不整除会引入 1 tick 边界量化**（0.4 s 配 2 ms 整除；0.5 s 配 2 ms 不整除）。

能把「我这里有 21.2 N 的剪切被静默丢掉了」写进 README 的仓，值得多看两眼。

**坑**：① **没有 LICENSE 文件**（作者可能只是忘了）—— 想用先开 issue 问，别默认可以。
② 1 星、9 月 13 日建仓，是个人练习项目的形态，不要当库依赖。
③ 上面那五条边界是真边界，**别拿它的输出去论证真机稳定性**。

### ★ TOP 1（深度）· LLMs Robot Arena —— 让编码 agent 写机器人控制器，然后把它们扔进同一个擂台

**先说清楚它在本系列里的位置。** 这不是一个 VLA、不是一个本体、不是一个 benchmark 论文。
它是一个**浏览器里的物理擂台**：两台同样身体、同样电机、同样前楔的机器人在一块悬空平台上对打，
区别只有控制它们的那段 JavaScript —— 而那段 JavaScript 由 LLM 写。

作者自己写了一句很重要的自我限定：
> *It's not an AGI benchmark. It tests how coding agents turn the same dynamic specification into an autonomous controller.*

**放进本系列是因为它恰好落在四条标准的正中间**：不需要任何硬件、不需要显卡、不需要账号、
不需要 API key 就能先玩，而且有一个**明确可交付的终点**（写一个能打赢 Baseline 的控制器）。
代价是它离「具身智能」的学术定义有距离 —— 这点我不含糊，下面「坑」里也会再说。

**是什么（规则一句话讲清）。**

- 平台**没有围栏**。你可以把对手推下去、逼进洞里、或者用前楔把它掀翻。**掉下去或第二次被掀翻即出局。**
- **能量有限。** 移动和转向消耗能量，进入蓝色充能格恢复；**站着不动不回能。**
- **地面会要命。** 洞是立即判负；火焰格会先警告再灼烧并抽能量。
- **站着不动有代价。** 机器人自重会磨损地砖直到塌陷；有些地砖会在警告后消失；**场地随时间收缩**。
- 一局最多两分钟。双方都活着就依次比：被掀翻次数更少 → 剩余能量 → 离中心距离。

控制器的契约极简：导出**唯一一个** `tick(sensors, memory)`，返回 `{ actions: { thrust, turn }, memory }`。
**不许 import、不许依赖、不许网络、不许文件系统、不许时钟、不许随机数 API、不许动态代码生成。**
状态只能放进返回的 JSON memory（上限 64 KiB），每个 tick 都是全新的模块作用域。
在 QuickJS 沙箱里跑。

**为什么现在值得做。**

1. **这是本系列见过的唯一一个「零门槛 + 有对手 + 有排名 + 当场出结果」的东西。**
   打开网页就自动跑一局。没有安装、没有数据集、没有 CUDA 版本。
2. **它顺手提供了一个多模型横评的现成语料。** 仓里有一份 2026-09-11 生成的循环赛榜单：
   **10 个种子 / 对、镜像出生点、1560 局**，engine 0.2.2-r2。前六名（迭代开发模式）：

   | # | 控制器 | 提供方 | Harness | 强度 | 95% CI | 得分率 |
   |---|---|---|---|---:|---|---:|
   | 1 | GPT-6 Astra (ultra) | OpenAI | Codex | 228.7 | 182.9–282.4 | 74.2% |
   | 2 | Fable 5.1 (max) | Anthropic | Claude Code | 190.5 | 154.3–236.4 | 70.0% |
   | 3 | GPT-5.6 Terra (ultra) | OpenAI | Codex | 127.4 | 104.2–159.6 | 60.0% |
   | 4 | Claude Sonnet 5 (max) | Anthropic | Claude Code | 111.2 | 89.1–135.1 | 56.5% |
   | 5 | DeepSeek V4 Pro 0813 | DeepSeek | OpenCode | 106.9 | 85.6–129.4 | 55.4% |
   | 6 | Claude Opus 5.1 (max) | Anthropic | Claude Code | 92.1 | 74.3–112.3 | 51.5% |

   参考基线 Baseline 排第 12（强度 37.2 / 28.3%）。
   **注意 95% CI 大面积重叠** —— 3 到 7 名之间基本分不出显著差异，别把这张表当模型能力排行榜读。
   作者也只说这是「one exhibition tournament」。
3. **它还量化了打法风格**（同一批对局的录像帧测出来的）：接触率、接近率、楔击率、
   每分钟交战次数、速度、转向率、边缘停留时间、每秒耗能、充能次数。
   比如 Fable 5.1 被标成 "Edge play"：**27% 的时间待在边缘**，而 GPT-6 Astra 只有 4%，
   后者是 "Energy burn"（13.6 能量/秒、4 次充能）。**这是一份现成的策略行为数据集。**

**个人怎么分步切进去（带成本和时间）。**

**第一步 —— 纯玩，15 分钟，0 元，不需要任何东西。**

打开 <https://llms-robot-arena.sndesign.it/>，默认自动模拟并播放一局。
选两个控制器、一个种子、一个出生布局，点 **Simulate match**。
**整局是先算完再回放的** —— 可以暂停、拖动、变速、看事件日志。
自动镜头会保持两机在画面内，**Manual camera** 可以自己环绕/平移/缩放。
回放可以导出/导入为 JSON。

还有一个 **Play yourself vs Robot B**：WASD 或方向键（手机上是屏幕按钮）实时打。
打完点 **Copy challenge link**，就生成一条链接 ——
**任何人打开都会看你这局的回放，并能在同一种子、同一对手上试着打赢你。无账号、无服务器。**

**第二步 —— 用你自己的 agent 写一个 bot（半天到两天，成本 = 你的 token）。**

这是核心玩法。做法有两条：

*(a) 本地/仓库路线（推荐，可复现）*

```sh
# 需要 Node.js 24+
git clone https://github.com/nigrosimone/llms-robot-arena
cd llms-robot-arena
npm ci && npm ci --prefix apps/web
npm start                      # http://127.0.0.1:8080
```

然后把 **[AGENTS.md](https://github.com/nigrosimone/llms-robot-arena/blob/main/AGENTS.md)** 整份喂给你的编码 agent。
那一份文件里有完整规则、编程契约、评测流程和黑盒政策 —— 不需要你再解释任何东西。
agent 写完 `packages/bots/<bot-id>.js` 之后：

```sh
# 一致性门（查契约合规，不查战术强度）
node packages/runtime/gate-cli.js packages/bots/<bot-id>.js

# 对局评测（镜像种子协议）
node packages/tournament/cli.js --bots match-bots.json \
     --out results/<bot-id> --mode iterative --budget fuel
```

**及格线是明确的：必须打赢 Baseline。**
在标准的 20 局镜像种子系列里，胜多于负（平局算半分，得分率 > 50%）。
作者特别强调：**过一致性门不算数**，Baseline 是一个「基础的、瞎打的」实现。

*(b) MCP 路线（不写文件，直接在网页里比）*

网页上的 **Connect an assistant** 背后是一个 MCP server（`packages/server`，
Express 5 on µWebSockets，`/mcp` 无状态端点 + `/session` websocket）。
你的 LLM 可以直接把控制器发到页面上跑。本地起：`npm run live`（`http://127.0.0.1:8787`），
然后网页地址加 `?live=http://127.0.0.1:8787`。
线上那份跑在 `live.llms-robot-arena.sndesign.it`。

**成本（token 口径，按官方价目表量级估算）**：
AGENTS.md 全文加规则大约 1 万 token 量级，一轮迭代（读规则 + 写 bot + 读对局结果 + 改）
按输入 ~30k、输出 ~8k 估，跑 5–10 轮：
**Sonnet 5（$3/$15 每百万）≈ $1–2；Opus 5（$5/$25 每百万）≈ $1.5–4。**
也就是**十几块到三十块人民币**能完整做完一次「让我的 agent 造一个能打的 bot」。
这是全期成本最低的一条，而且没有硬件沉没成本。

**第三步 —— 想进官方榜单？先看清楚规则。**

**这一条必须说在前面：仓库明确拒绝「新增模型 bot」的 PR。**
[CONTRIBUTING.md](https://github.com/nigrosimone/llms-robot-arena/blob/main/CONTRIBUTING.md) 原文：
> *We do not accept pull requests that add new models or model-attributed bots to the official catalog.
> We cannot verify that a submitted controller was actually generated by the claimed model, thinking level and coding harness.*

想让某个模型进榜，得联系作者 Simone Nigro（`nigro.simone@gmail.com`）**提供 API key，由他来生成和评测**。
（作者同时警告：**不要把 API key 放进 issue、PR 或仓库文件**。）

**所以对个人来说，现实的三个终点是**：
① 本地造一个能稳定打赢 Baseline 的 bot，导出源码自己留着；
② 用 Copy challenge link 生成一条「来打赢我」的链接发出去；
③ **给模拟器、沙箱、查看器、测试或文档提 PR** —— 这一类是欢迎的，
提交前要跑 `npm test`、`npm run build`、`npm run lint --prefix apps/web`、
`npm test --prefix apps/web`、`npm run e2e`（e2e 用本地 Chrome 的新 headless 模式，不下载浏览器）。

**坑与风险。**

1. **⚠️ 仓库没有 LICENSE 文件。** 这是最大的问题，直接顶在本系列「开源许可允许个人用」这条标准上。
   在浏览器里玩、本地 clone 跑、写自己的 bot，实践上没人会拦你；
   但**分发、fork 发布、把代码拿去用，法律上是不清楚的**。
   **建议先开一个 issue 问许可** —— 这也是这个仓现在最值得提的一条 issue。
2. **「对手是黑盒」是硬规则，不是建议。** AGENTS.md 里用了整整一节说这件事：
   不许读、不许 diff、不许 import 来看、不许打印 `packages/bots` 里别的文件（**包括参考控制器**），
   不许绕道 git 历史 / 打包产物 / source map / 缓存 / 日志，
   **不许让另一个 agent、工具或人代你去看**。搜索项目时要显式排除 `packages/bots/**`。
   如果不小心看到了，规矩是：停止查看、声明暴露、不把信息用进 bot、**不得声称这是一次未污染的评测**。
3. **`fuel` 结果不等于 `wall` 结果。** 一致性门跑出来的 `fuel` 是**确定性的指令预算结果**，
   **不是**「符合挂钟时间预算」的证明。真要考挂钟就得用 `--budget wall`。
4. **一次性提交 vs 迭代开发要如实标注。** AGENTS.md 要求：
   如果任务要求 one-shot，就交第一次生成的文件，不许拿对手反馈调；
   迭代出来的就标成 iterative，**绝不能当成 one-shot 报**。榜单上每一行都标了这一栏。
5. **它不是具身智能研究。** 二维刚体、离散传感、两个动作维度（thrust / turn）。
   它测的是「编码 agent 能不能把一份动态规范变成自治控制器」，
   **不要拿它的结论去推 VLA、真机或 sim2real**。本系列推荐它是因为它对个人极其友好，不是因为它是前沿。
6. 规则版本 `0.2.2-draft`、引擎 `0.2.2-r2` —— **还在 draft**，跨版本的成绩不能混着比。

### 2 · EgoWAM —— 佐治亚理工 CoRL 2026，把野外第一人称人类视频变成世界-动作模型，MIT + 权重全放

**一句话**：Baoyu Li / Xinchen Yin 等（Danfei Xu 组），**MIT 许可**，26 星，9 月 6 日建仓。
主张是「世界动作模型不必只建模像素」—— 同一套 trunk 和 flow-matching 动作头，
**只换世界预测目标**（像素 / RAE 的 DINO 表征 / Track4World 的 3D flow），做成一组可对照的变体。

| 项 | 内容 |
|---|---|
| 代码结构 | `algo/`（HPT 世界-动作模型）、`models/`（stem / trunk / flow-matching 动作头 / WM 头）、`rldb/`（zarr 数据层 + 跨本体 keymap）、`hydra_configs/` |
| 文档 | install / data / training / **robotwin（仿真）** / **hardware（真机部署）** / troubleshooting，六份齐全 |
| 权重 | <https://huggingface.co/boeyyyy/EgoWAM-checkpoints> |
| 真机栈 | ARX5 机械臂 + Project Aria 眼镜 + RealSense（`egowam/robot/`） |
| 仿真桥 | RoboTwin 2.0（SAPIEN 双臂），`external/` **已 vendored，不用 submodule init** |
| 测试环境 | Python 3.11 / PyTorch 2.5 / CUDA 12.1 / **A40、L40S** |

**和本周另一篇撞在一起了**：同一周还有 **[HuRo](https://github.com/3587jjh/HuRo)**（CoRL 2026，Apache-2.0，23 星，9 月 11 日放码），
做的是几乎同一件事的另一半 —— 把第一人称人类视频**机器人化**：重定向手部动作到机器人关节轨迹、
把人的胳膊从画面里抹掉并渲染上机器人，产出 **63 万条机器人化 episode / 1.42 亿帧**（LeRobot V2.0 格式）。
论文报告四个真实操作任务上，预训练规模拉上去后微调完成率 **51.5% → 80.3%**，
空间/视觉分布外 **34.9% → 72.2%**。**一条 `./run_pipeline.sh` 跑完 11 个阶段，全部可续跑。**
两篇放一起就是本周最清楚的一条线：**「人类第一人称视频」正在被当成机器人数据的主矿。**

**个人怎么切进去（三档，按现实程度排）**：
① **只读不跑** —— EgoWAM 的价值有一半在那张「方法变体 × 世界目标 × 配置文件」的对照表里。
它把「世界模型到底该预测什么」做成了可以逐项消融的配置，这是能直接搬进你自己项目的结构。
② **下 checkpoint 做推理/评测** —— HF 上的权重是公开的，比从头训现实得多。
③ **RoboTwin 仿真路线（无硬件）** —— 需要单独建一个 venv（SAPIEN 3.0.0b1 + mplib 0.2.1 和训练环境冲突），
另外下约 200 MB 资产，**还需要能用的 Vulkan/EGL**；无头机器要 `DISPLAY=""` + `PYOPENGL_PLATFORM=egl`。

**坑**：
① **这是集群代码，不是单卡代码。** `sbatch/` 下六个训练启动器 + 一个 robotwin，
官方测试卡是 **A40 / L40S**（都是 48 G）。A4000 16 G 上训练基本没戏，
推理和 RoboTwin 评测能不能跑得看具体变体 —— **仓里没给显存下限，这是个空的数字，也是一个值得交的实验**。
② **`docs/data.md` 里明文写了一组 AWS AccessKey / SecretKey**，用来从对象存储同步数据集。
不管它是不是刻意公开的只读键，**这都是应该给作者提 issue 的点**，
而且意味着**这条数据通路随时可能被吊销** —— 别把 pipeline 建在它上面。
自带数据的人用 `LocalEpisodeResolver`，完全绕开这一段。
③ **部分变体依赖 gated 资产**（Wan VAE / RAE 的 DINO 目标 / Track4World）。
好消息是作者写明了：**BC 和 3D-flow 两个变体一个都不需要，从数据集直接训。**
④ HuRo 那边的门槛更直白：**Linux + ≥24 GB 显存 + CUDA 12.8 驱动**，A4000 16 G 不够。
数据集页当前还标着 "Data coming soon"，放出来的是**机器人化流水线**，不是数据本身。

### 3 · Yeah Hand（Rebelia V2）—— 对标 2000 欧的开源拟人手，机械件这一版**还没放**

**先把最重要的一条放前面：V2 仓里没有机械 CAD。**
61 个文件里是电子（完整 Gerber + 网表 + 元件表 + PDF/EPS 光绘）、固件（人用 / 机器人用两套 Arduino 工程
+ 五个单舵机注册程序）、和两份装配说明 PDF（意大利语原文 + 英文译文）。
**一个 STL / STEP / F3D 都没有。** 机械几何目前在前一代 [rebelia V1 分支](https://github.com/OPSOBOT/rebelia/tree/V1)（23 个机械文件），
**V1 是 OSHWA 认证过的**，V2 README 明写「will be certified with OSHWA after is stable」。

**放进来的理由是那份 BOM 和那套许可组合。**

许可是三件套，都是 copyleft：**硬件 CERN-OHL-S-2.0 / 固件 GNU GPLv3 / 文档 CC-BY-SA**。
作者（原设计 Vittorio Lumare，开发伙伴 [Public Invention](https://www.pubinv.org/project/yeah-robotic-hand/)）
把商业模式也写进了 README：开发测试 → 备货预售 → **版本稳定即以 copyleft 发布并同时开卖** → 用收入养下一版。
**「卖的和开源的是同一版」**，不是常见的「开源一个阉割版」。

BOM 里最关键的一行是**机器人版只要五个舵机**：

| 物料 | 规格 | 数量 |
|---|---|---|
| 舵机 | **WaveShare ST3215**（总线舵机） | 5 |
| 主控（机器人版） | WaveShare ESP32 Servo Driver | 1 |
| 腱绳 | HERCULES 8 股编织鱼线，200 lbs，Φ0.75 mm，灰色 | 1 |
| 腱绳导管 | PTFE 管 OD 3 mm / ID 1.5 mm，长 1 m | 1 |
| 手指紧固 | M3 螺母 ×4、M3×12 内六角沉头 ×4 | — |
| 绕线轮 | M3×10 内六角圆头 ×16（头径 ≤ 5.7 mm） | — |
| 舵机/掌部/盖板 | M2 自攻 8 mm ×20、10 mm ×7、10 mm ×10 | — |

**假肢版**额外要一块自制的 ServoBoard Slim（LM2575T-5G + ESP32-WROOM-32 + sn74lvc1g125/126 + SS8550…，
Gerber 齐全可直接打样）和 **2 个 OyMotion 肌电传感器**。

**成本量级**：ST3215 单价约 $15–16，五个约 $80；ESP32 Servo Driver 约 $20；
鱼线 + PTFE + 五金 + 打印耗材合计几十美元。**机器人版自制 BOM 大致在 ¥700–1000 量级**，
**远低于产品定价的「under 2000 EUR」** —— 那个数字是整机产品价，不是你自己做的成本。
（价格是公开零售的量级参考，未逐项核价。）

**个人怎么切进去**：
① **现在就能做的是电子和固件** —— Gerber 直接送打样，`RebeliaRobot.ino` + `fingers_controller.cpp` 是完整的；
五个 `*FlexionServoRegistration.ino` 是单舵机注册程序，装配时逐个跑。
② **机械件用 V1 分支** —— V1 有 23 个机械文件且经 OSHWA 认证，先把 V1 做出来再跟 V2 的改动。
③ **最有价值的贡献是催/帮 V2 的机械件落地**，以及把那两份 PDF 装配说明变成带图的 Markdown。

**坑**：
① **前面说的：V2 无机械 CAD。** 想「今天就打印一只手」的人，现在做不到。
② **copyleft 是真 copyleft** —— CERN-OHL-S 对硬件、GPLv3 对固件都是传染性的。
想做闭源衍生的，**这只手不行，选 Easyhand（CERN-OHL-P）**。这是本期两只手最实质的区别之一。
③ **OSHWA 认证目前只覆盖 V1**，V2 是未认证状态。
④ 假肢版需要肌电传感器和自制 PCB，**复杂度比机器人版高一个量级**，别从那条路起步。
⑤ 0 星、9 月 14 日建仓（V2 首次公开），仓库结构还会动。

### 🇨🇳 国内 · cadloop —— 把「这个件到底扛不扛得住」补进 text-to-cad 生态的那一格

**是什么。**

MIT，9 月 13 日建仓，**源码注释与文档为中文**。作者的定位说明写得极其克制，值得整段引用逻辑：

> 调研 `text-to-cad` 后的定位收缩：**它已经做得比我们好的，我们不做**。

于是砍掉了三个自研模块（可打印性检查、标定试件库、标准件库，都退役进 `archive/`），
只做生态里唯一空着的一格 —— **结构强度 / 刚度 / 稳定性**。分工表长这样：

| 环节 | 用谁 |
|---|---|
| 建模（参数化 CAD / STEP） | text-to-cad 的 `cad` 技能 |
| 标准件（螺丝/轴承/电机） | text-to-cad 的 `step-parts` |
| 可打印性（壁厚/悬垂/支撑） | text-to-cad 的 `dfam-check` |
| 切片（真实切片器 CLI） | text-to-cad 的 `gcode` |
| 打印机直连 | text-to-cad 的 `bambu-labs` |
| **结构强度 / 刚度 / 稳定性** | 🎯 **cadloop** |

技术栈是**纯开源纯 Python**：STEP/build123d → **gmsh** 网格 → **FEniCSx** 线弹性求解 → 报告。
三件它真正做出来的事：

1. **FDM 各向异性校核** —— 层内 vs 层间分开判据。
   关键设计：**同一份应力场，按打印姿态选对应正应力分量即可，不用对每种摆放重算**（`layer_normal = x/y/z`）。
   作者实测：同一个 FEA 场评三种姿态，**层间应力 27.8 → 13.4 MPa —— 只改摆放**。
2. **结论稳健性** —— 材料参数估错会不会翻转结论？`robustness.py` 把这件事做成机械判据，
   分区 `robust` → `critical`。块状结构裕度 5–30 倍，参数估错无所谓；**薄壁/细杆裕度 < 2.5 倍才必须实测**。
3. **欧拉屈曲** —— 作者给的例子最有说服力：
   **100 mm 长的 5×5 立柱受压 31 N 即屈曲，而按强度能承数百牛。只做强度校核会给出错误的「安全」结论。**

还有一个很少见的设计：**`bench.py` 音叉自检** —— 先用有解析解的悬臂梁标定自己，
**不过就拒绝输出零件结论**。实测误差 −3.48%（容差 ±8%）。

**个人怎么切进去（带成本）。**

```bash
conda create -n cadloop python=3.11 -y && conda activate cadloop
pip install build123d gmsh fenics-dolfinx mpi4py pyyaml numpy scipy

# 金标准算例（柔性铰链，有解析解可对照）
python -m cadloop.examples.flexure_hinge

# 复杂度压测件
python -m cadloop.examples.planetary_gearbox   # 模数 2 行星齿轮箱，1201 面内齿圈，真渐开线
python -m cadloop.examples.airliner            # 22 件、翼展 500.00 mm、NACA 2412 后掠翼
```

接 `dfam-check`（可选但推荐）：

```bash
python <skills>/dfam-check/scripts/dfam_tool.py measure part.stl --angle-limit 45 > dfam.json
python -m cadloop.examples.flexure_hinge --dfam dfam.json --layer-normal y
```

**换机器 / 换材料只改 `config/printenv.yaml`，不动代码** —— 边界条件外置是这个项目最重要的设计。

**成本 —— 这一条和本专题其它项目不一样，要分两笔算：**

- **FEA 求解本身不花一分钱 token。** gmsh + FEniCSx 全在本地 CPU 跑。
  代价是**时间**：作者实测内齿圈构建 2–3.5 s，**10 万四面体网格 49.6 s**。
- **花 token 的是建模和读报告那一圈**：写/改 build123d 模型、读 Markdown 报告、按报告改设计。
  一个中等复杂度零件 3–5 轮迭代，按输入 ~80k、输出 ~20k 估：
  **Sonnet 5（$3/$15 每百万）≈ $0.5；Opus 5（$5/$25 每百万）≈ $0.9。**
  算上重试和缓存未命中，**跑一个件大概 $0.5–2，约 ¥4–15。**
- **真正的隐性成本是材料参数**：默认走保守兜底值（注塑标准值 ×0.8，层间再 ×0.5，SF=2.0），
  只有稳健性判据触发 `critical` 时才需要实测 —— 这正是「先问，再测」那条设计纪律的意思。

**坑（作者自己列的六条，挑最要命的三条）。**

1. **⚠️ 网格收敛未自动执行 → 假通过风险。** 作者原话：粗网格可能低估应力，
   **实测位移只有解析值的 0.374 倍**。**必须手工做 2 点网格对比**，否则「通过」可能是假的。
   这是六条限制里唯一一条会让你得出**错误的安全结论**的。
2. **边界条件只支持平面选择** —— 表达不了圆柱面（轴承孔、轴颈）和逐区切向载荷。
   作者自己标为「**最大缺口**」，面向真实零件时要手工近似。
3. **应力奇异不会自动识别** —— 尖角内凹处 FEA 给出网格相关的非物理值；
   `robustness` 会标 `critical`，但**不会告诉你「这是奇异值」**。
4. 另外三条：各向异性是 screening 级（不是完整横观各向同性本构）、
   不含接触/非线性/动力学/热、材料参数默认非实测。**作者在报告措辞里会明确标注「非实测」。**
5. 0 星、建仓两天。**作者明说欢迎 PR，尤其欢迎攻限制 #1–#4** —— 这是一份写明了的待办清单。

### 🌍 国外 · cadjson —— 一个零件就是一个 JSON 文件，然后产出 STEP / STL / 3MF / 带尺寸的工程图 / Fusion 脚本

**是什么。**

MIT，v0.3.2，9 月 12 日建仓、9 月 14 日仍在推。一句话概括作者的主张：**CAD as text。**

一个零件 = 一个 JSON 文件：命名尺寸（`params`）+ 有序特征列表（`features`）+ 你想要的输出（`outputs`）。
底下用 OpenCascade 内核构建。长这样：

```jsonc
{ "schema": "cadjson/0.1", "name": "l_bracket", "units": "mm",
  "params": { "width": 60, "base_len": 40, "wall_h": 35, "t": 4, "hole_d": 5.5 },
  "features": [
    { "id": "profile", "type": "extrude", "distance": "width",
      "sketch": { "plane": "YZ", "shapes": [ { "type": "path", "start": [0, 0],
        "segments": [ "right base_len", "up t", "left base_len - t", "up wall_h - t", "left t", "close" ] } ] } },
    { "id": "inside_fillet", "type": "fillet", "radius": 3,
      "edges": { "of": "profile", "parallel_to": "X", "near": ["width / 2", "t", "t"] } },
    { "id": "wall_holes", "type": "hole", "face": { "of": "profile", "normal": "-Y" },
      "at": [[-15, 8], [15, 8]], "diameter": "hole_d", "through": true }
  ],
  "outputs": { "step": true, "stl": true, "drawing": { "sheet": true, "dimensions": true } } }
```

**和本系列推过的另外四条建模路线的区别在哪。**

| 路线 | 代表（本系列推过的期数） | 模型要写什么 |
|---|---|---|
| Python code-CAD | SimpleCADforDSH（09-12）、cadloop（本期） | build123d Python 代码 |
| OpenSCAD 回路 | ModelRift openscad-skill（09-13） | `.scad` 源码 + 渲染回看 |
| Mesh 生成 | idea-to-print（09-13，混元3D） | 提示词 → 网格 → 修 |
| Blender agent OS | design-os-3d-blender（09-11） | bpy 脚本 |
| **声明式 JSON** | **cadjson（本期）** | **一份 JSON，无代码** |

**cadjson 的三个真正的差异点**：

1. **选择器不按索引。** 面和边是按**造它的那个特征、法向、方向、凹凸性、几何类型、尺寸或邻近度**选的，
   **永远不按 index**。这一条直击 code-CAD 交给 LLM 时最大的脆弱点 ——
   改一个参数导致边的编号变了，整个脚本静默崩掉。
2. **它产出的不只是模型，还有工程图。** STEP（给任何 CAD）、STL + **3MF**（给打印）、
   **带消隐线的 2D 视图、剖视、带标注的图纸页**、PNG 预览、可在浏览器里转动的 HTML 查看器、
   一份 **能在 Fusion 360 里重建原生时间线的脚本**、以及一份 `report.json` 数字汇总。
3. **文本即版本控制。** 零件进 git、干净地 diff、能被 AI 写和改。仓里自带一个 Claude Code skill
   （`.claude/skills/cadjson/SKILL.md`），`cadjson init my-parts` 会把 skill 复制进你的零件仓。

覆盖的特征：extrude、revolve、fillet、chamfer、shell、孔（普通/沉头/埋头/**真 ISO 螺纹**，
支持 `M3` / `#6-32` 这类标准规格的攻丝或过孔配合）、mirror、线性/极坐标阵列、loft、sweep、text、
导入件、**按配合关系（同轴/贴合/齐平/平行）定位的装配体并做干涉与间隙检查**。
变体用 `extends` 继承基础零件，新特征类型靠插件。

**个人怎么切进去（带成本）。**

```sh
# Python 3.11 或 3.12（Windows / Linux / macOS 都有 wheel）
pip install "cadjson @ git+https://github.com/sclaiborne/cadjson@v0.3.2"
pip install "cadjson[sheets] @ git+https://github.com/sclaiborne/cadjson@v0.3.2"   # 带尺寸图纸页

cadjson validate part.json          # 只查 schema 和参数，不算几何
cadjson build part.json             # STEP / STL / 视图 / 预览 / report → out/<name>/
cadjson view part.json              # 浏览器里转动、隐藏零件、剖切
cadjson info part.json              # 列出每个面每条边 —— 写选择器就靠它
cadjson compare part.json ref.stl   # 体积、包围盒、表面距离 vs 参考网格
cadjson export-fusion part.json     # Fusion 360 脚本（原生参数化时间线）
cadjson export-python part.json     # 等价的独立 build123d 脚本
cadjson init my-parts               # 脚手架一个零件仓，含 Claude skill
```

**成本（token 口径，官方价目表量级估算）。**

这条路线**比 mesh 生成便宜一个量级**，原因很具体：**全程没有图像来回**。

- **写 JSON 本身极省** —— 上面那个 l_bracket 全文不到 400 token。
- **真正烧 token 的是选择器调试回路**：`cadjson info` 会列出每个面每条边，
  这份输出喂回模型是输入的大头。
- 一个带 8–12 个特征的零件，3–6 轮迭代，估输入 60–120k、输出 10–20k：
  **Sonnet 5 ≈ $0.33–0.66；Opus 5 ≈ $0.55–1.1。**
  **跑一个件大概 $0.3–1.2，约 ¥2.5–9。**
- 对照：09-13 那期的 idea-to-print 走混元3D + Blender + 19 项几何门，
  中间要来回看渲染图，**图像 token 是纯文本路线的几倍到十几倍**。
  **想省钱就走 code-CAD / 声明式，想要有机形体才上 mesh 生成。这是一条明确的选型规则。**

**坑（作者的 Status 一节自己列了，照抄要点）。**

1. **⚠️ Fusion 导出是对着假 API 验的，没在真 Fusion 里验过。** 作者原话：
   "the Fusion export is verified against a fake API, not yet inside Fusion"。
   而且**螺纹、loft、sweep、text 和装配体都不导出到 Fusion**；
   导出脚本里的草图几何是数值化的（**参数驱动特征值，不驱动草图尺寸**）。
   **别把 Fusion 往返当成可靠通路。**
2. **⚠️ 许可有一个 AGPL 陷阱。** cadjson 本体是 MIT，几何依赖（build123d / bd_warehouse / trimesh /
   pydantic / click）是 Apache-2.0 或 MIT —— **但带尺寸的图纸页用的是 `draftwright`，AGPL-3**。
   它被做成可选 extra 就是为了装 cadjson 不会把它拖进来。
   **如果你装了 `[sheets]` 并分发这个组合，AGPL 适用于该组合。** 商用前务必看清。
3. **尺寸标注是全自动的，没法指定某一个尺寸**；剖视用灰色填充**而不是剖面线**。
4. **Python 3.13 未测** —— `sheets` extra 在 3.13 上钉了较老的 build123d。用 3.11 或 3.12。
5. **0 星、建仓三天。** schema 版本 `cadjson/0.1`，格式会变。

### 📌 专题分析：这周这条链路上真正变了的东西（4 点）

**1. text-to-cad 从「一个项目」变成了「一个生态位坐标系」。**
本期两条的关系最能说明问题：cadloop **明确按 text-to-cad 的技能清单画了一张分工表**，
砍掉三个自研模块只做它缺的 FEA；cadjson 则是在同一格里另起一条声明式路线。
一个 15.7k 星、仍在日更的仓，正在开始起「谁做什么」的协调作用 ——
**这是一条链路从「各写各的」进入「按缺口补位」的标志**。对个人的实际意义：
**动手前先去 text-to-cad 的技能列表里对一遍**，别再重复造 dfam-check 和标准件库。

**2. 校核这一段正在从「几何」往「物理」推进，而且推进得很克制。**
回看这几期的门：09-13 idea-to-print 是 19 项 DfAM 几何门（PASS/FAIL/UNKNOWN）；
09-12 SimpleCADforDSH 是单体/水密/0.2 mm 包络的几何 QA 硬门。
这些全是**几何层**的判据 —— 能答「能不能打出来」，答不了「打出来能不能用」。
cadloop 是本系列见到的**第一个把线弹性 FEA + 欧拉屈曲接进这条链路的**。
更值得学的是它**没有假装精确**：它做的是「结论稳健性分区」而不是「精确应力值」，
判据看敏感度不看精度，块状件裕度 5–30 倍就不必实测。
**这个思路可以直接抄到任何 agent 化的工程判据上：先问这个指标会不会翻转结论，再决定要不要花钱测。**

**3. 「一个件多少钱」这个问题，本周出现了清晰的分层。**
把本期和前几期的成本口径并排：

| 路线 | token 主要花在哪 | 一个件量级 |
|---|---|---|
| 声明式 JSON（cadjson） | 选择器调试（`info` 输出） | **$0.3–1.2** |
| Python code-CAD + FEA（cadloop） | 建模迭代 + 读报告（**求解 0 token**） | **$0.5–2** |
| Mesh 生成 + 渲染回看（idea-to-print，09-13） | **图像来回** | 高一个量级 |
| 本地模型跑完（dsh-print3d，09-11） | — | **0** |

**规律很干净：token 成本基本正比于「有没有图像在回路里」。**
纯文本回路（code-CAD、声明式、切片器 CLI）都在一杯咖啡以内；
一旦把渲染图/照片塞回模型（mesh 生成、Blender 视觉回看、Computer Use 驱动商业 CAD），成本立刻跳档。
**做选型时这条比「哪个模型更聪明」更能决定你的账单。**

**4. 这条链路上现在最空的两格（接着上期那条继续说）。**
上期指出「从器件数据手册抽装配约束」是空的。本期能再加两条，都来自作者自己标的缺口：
- **圆柱面边界条件**（cadloop 限制 #2，作者标为「最大缺口」）——
  轴承孔、轴颈这类载荷现在表达不了，而这恰好是机器人零件最常见的受力形式。
- **自动网格收敛判定**（cadloop 限制 #4）—— 现在要人工做两点对比，
  不做就有**假通过**风险。这是一个纯工程、边界清晰、半天到几天能做完的 PR。

因为前者告诉你踩坑的位置在哪，后者要你自己去撞。
筛仓的时候可以直接 grep README 里有没有「限制 / 边界 / 不做什么 / Known limitations」一节。

**4. 「AI 辅助开发」开始出现在 README 的显著位置，而且写法在收敛。**
openarm-task-studio 的写法可以当模板：
「AI 参与了代码编写、重构、测试和文档整理；功能设计、运行验证和最终取舍由作者完成。」
—— 说清楚**哪部分是 AI 做的、哪部分是人负责的**。这比一句「AI generated」或者只字不提都好。
本系列的立场：**这不影响项目的可参与性评分，但它改变你读代码的方式** ——
重点看作者声明自己验证过的那部分。

**5. 这周 GitHub 上「全新整机」仍然稀薄 —— 已经是连续第三周。**
09-14 那期观察到硬件侧动作集中在「传感器协议 / 配件改件 / 便宜 IMU 阵列」这种增量上。
本周的两只手部分改变了这个判断（它们是整机，不是配件），
但除此之外，四足、人形、机械臂三个大类里**本周没有一个带完整 BOM 的新整机**。
搜到的四足仓基本是 ROS 2 巡检项目和课程作业；机械臂仓大量是 MeArm / 舵机臂的教学复现。
**结论暂时不变：硬件侧真正的新东西集中在「手」和「末端」，不在「本体」。**
如果你在等一个新的开源四足/人形整机，这三周都不是时候。
