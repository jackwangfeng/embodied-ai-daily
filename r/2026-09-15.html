★ TOP 1（深度）· Easyhand —— 六个 SG90 舵机、一套 STEP、两百多块钱，做一只能抓杯子的五指仿生手

是什么。

一只平面四杆连杆驱动的五指仿生灵巧手，9 月 14 日建仓（昨天），采用 CERN-OHL-P-2.0 （permissive 型开源硬件许可，不传染、允许闭源衍生）。仓里一共 22 个文件，但该有的都有： 一份 STEP 总装、一份 PlatformIO 固件、两份中文文档（硬件/装配、控制系统）， 外加实物正反面照片、三维图、爆炸图和三段演示视频（手指灵活度与手势、抓塑料杯、抓纸包）。

机械上的核心取舍写在第一句：每根手指用一个 SG90 舵机，通过平面四杆连杆带动三个关节联动屈伸， 拇指额外加一个旋转舵机。结果是 16 个关节运动轴、6 个主动自由度。

这不是「每指三舵机」的高配路线，是「一指一舵机 + 连杆耦合」的极简路线。 代价是手指关节不能独立控制（同一根手指三个关节的角度是耦合的）， 好处是整只手只要六个 ¥5 的舵机，而且没有任何腱绳、滑轮、走线问题 —— 全是刚性连杆和销轴。

项 内容
驱动 SG90 × 6（五指屈伸 + 拇指旋转）
主控 ESP32 30Pin / Type-C / CH340C（资料标 ESP32-D0WD、4 MB Flash）
PWM 驱动 PCA9685，I²C 地址 0x40，50 Hz
舵机供电 独立 5 V / 5 A 稳压锂电池组（不接 ESP32 的 5V 脚）
打印 拓竹 PLA，层高 0.2 mm、2 层墙、15% 填充、树状支撑
五金 Φ2 销轴 ×10/×12/×15 各 5 根；M2 金属球头扣 5 对（10 个）
控制界面 ESP32 内置 WebServer，热点 DexterousHand_test（无密码），http://192.168.4.1/

为什么现在值得做。

  1. 这是本系列做到第十一期，见过的「单位成本最低的、能真的抓起东西的五指手」。 翻一下台账：09-14 推的 Vision_Sync_Dexterous_Hand 驱动的是 BrainCo Revo2（商业灵巧手，五位数）； 09-11 的 Open-Gripper-Plus 是双 ODrive + 摆线减速的两指夹爪；LEAP Hand v2 是研究级方案。 Easyhand 的整套物料按公开零售价粗算在 ¥200–300 量级（详见下面的成本表）， 而且演示视频里它真的把一次性塑料杯和纸包抓起来了。
  2. 它把「灵巧手」这件事的入场门槛降到了跟做个四轴机械臂差不多。 没有 FOC、没有 CAN、没有编码器、没有腱绳预紧，六路 PWM 加一块 PCA9685 就是全部电控。 一个做过 Arduino 小车的人可以直接上手。
  3. 作者把「不知道的东西」明确标成不知道，这在 0 星新仓里很少见。README 和文档里几处原话： 「未提供抓取力、额定负载或重复定位精度的测量数据」「程序角度不等于手指关节实际转角」 「网页数值不能视为实测角度，抓握参数也不是力控制设定值」。 它不假装自己是个有力控的灵巧手，它就是一只位置控制的、连杆耦合的、便宜的手。

个人怎么分步切进去（带成本和时间）。

第零步 —— 先看视频，20 分钟，0 元。 仓库首页直接嵌了三段 GitHub 托管的 MP4。先确认「连杆耦合手指到底能抓什么」，再决定买不买料。 这是唯一一个在花钱之前能做的判断，别跳过。

第二步 —— 打印（半天到一天，看你有几台机器）。

下载 cad/left_hand_asm.stp
→ 用支持 STEP 的 CAD（FreeCAD 免费即可）打开总装
→ 按独立零件导出 STL
→ 切片：层高 0.2 / 2 层墙 / 15% 填充 / 树状支撑

这一步是这个仓最大的摩擦点：仓里只有 STEP 总装，没有现成的 STL，也没有拆好的打印板。 喷嘴尺寸、温度、摆放方向、支撑阈值都没给，得自己按机器定。 打完先清支撑和关节孔毛刺，空载手动试销轴和球头扣能不能自由动，再装传动。

第三步 —— 接线与首次上电（2 小时）。

逻辑连接（作者给了完整对照表）：

ESP32 3V3   → PCA9685 VCC
ESP32 GND   → PCA9685 GND
ESP32 GPIO21 → SDA
ESP32 GPIO22 → SCL
电池组 +5V  → PCA9685 V+（舵机电源端）
电池组 GND  → PCA9685 GND      ← 三方必须共地

舵机通道：拇指屈伸 CH0 / 食指 CH1 / 中指 CH2 / 无名指 CH3 / 小指 CH4 / 拇指旋转 CH5。

烧录：

# PlatformIO 打开 firmware/ 目录，板型 esp32dev，Arduino 框架
pio run
pio run --target upload
pio device monitor --baud 115200

依赖版本是钉死的：Espressif32 5.2.0（Arduino-ESP32 2.0.5）、 Adafruit PWM Servo Driver Library 3.0.3、Adafruit BusIO 1.17.4。别自己升。

第四步 —— 校准（这一步决定成败，留一个晚上）。

作者给的顺序不能颠倒：

  1. 先卸掉舵盘或连杆负载，烧录，确认每个通道对应哪个舵机；
  2. 程序一上电就写自然姿态（拇指屈伸 30°，其余五轴 20°）， 按这个姿态装舵盘，装错了机械限位就全乱；
  3. 小幅调单轴，确认方向和可用行程，按实际无干涉行程改 main.cpp 顶部的 THUMB_MAX 等限位；
  4. 单轴过了再试预设手势 / 抓握 / 连续动作。

角度范围：拇指屈伸 0–90°，其余五轴 0–105°。四档速度 25 / 45 / 90 / 120 °/s，默认 45。 运动更新周期 20 ms，当前角度逐步逼近目标。 SERVOMIN=102 / SERVOMAX=492 是 0–180° 指令到 PCA9685 计数的映射端点，不是微秒。

第五步 —— 你能贡献什么（这才是推荐它的理由）。

这个仓现在有四个明显的空格，每个都是半天到一周的活：

  • 右手。 仓里只有 left_hand_asm.stp，是左手。镜像一份右手总装，提 PR。
  • 拆好的打印板 / STL 包。 上面第二步那个摩擦点，你替所有后来的人省掉一次。
  • 实测数据。 抓取力、额定负载、重复定位精度 —— 作者明确写了「未提供」。 一个数显推拉力计一百块钱，量五个手指的指尖夹持力，就是这个仓现在最值钱的数据。
  • 把热点加上密码。 现在 DexterousHand_test 无密码，作者自己写了「周围可连接热点的设备能够操作灵巧手， 适用于本地受控演示」—— 说明他知道，只是还没做。

坑与风险。

  1. 仓建于昨天（2026-09-14），0 星，只有作者一个人。 结构、接口、角度映射都可能改。 要在这上面做东西，先 fork 钉住 commit。
  2. 只有 STEP，没有 STL，没有打印板，没有逐零件数量。 前面说过了，这是真实工作量，别低估。
  3. 无密码 AP + 无认证网页控制。 只在你控得住的局域网/无网环境下用。
  4. SG90 是塑料齿的。 连杆机构一旦装配干涉，堵转很容易崩齿。 作者写了「如出现卡滞或持续堵转，切断舵机电源并检查装配与限位」—— 这句话要当真。 备几个舵机，或者一开始就上金属齿的 MG90S（尺寸兼容，贵一点）。
  5. 没有任何反馈。 没有关节位置传感、没有力传感、没有电流采样。 网页上那个 0–100 的「抓握参数」是多轴协调的插值参数，不是力控设定值。 想做力控得自己加电流采样或者指尖触觉 —— 那是另一个项目了。
  6. 左手 + 连杆耦合 = 不适合做 VLA 的执行端。 如果你的目标是接 LeRobot / π0 做操作学习， 这只手的自由度和可控性都不够。它适合做人机交互、手势展示、教学、触觉实验的载体。

3 · mini-quadruped —— 纯 numpy 重写四足步态控制，24 项自校验，「已知边界」一节比正文还硬

一句话：不依赖 MuJoCo、Drake 或任何物理引擎，全部 numpy， 核心是一个运动学仿真器而不是动力学仿真器 —— 机身怎么动完全由「落地的脚不打滑」这一条约束解出来。

python -m quadruped.test_quadruped    # 24 项自校验测试
python demo_trot.py                   # 8 组机动指令对照表 + demo_trot.svg

四个文件、一个 DESIGN.md，全部代码加起来不到 10 个文件：

文件 内容
kinematics.py 3-DOF 腿（γ 侧摆 / α 髋 / β 膝）FK、闭式 IK、解析雅可比、可达性钳制
gait.py 步态相位、摆动/支撑轨迹、转向、偏航精确合成、Raibert 落足点
controller.py TrotController（步态 + Raibert 反馈 + 偏航前馈）、KinematicSimulator、2D Procrustes 位姿解算
stabilizer.py 凸包 / 支撑多边形 / 稳定裕度 / 切比雪夫中心 / ZMP / 摩擦锥力分配

为什么推荐它：本系列翻过大量四足仓，绝大多数是「跑 Isaac Lab 训一个策略」。 这个仓走的是相反方向 —— 把运动学那一层从零写一遍，并且用可复现的数字证明它是对的。 实测表里前进 vx=0.40 → 实际 0.40000 m/s、高度偏差 2.8e-16 m； FK→IK 往返 3.2e-15 rad；雅可比 vs 数值差分 5.8e-10。 零依赖、零硬件、零显卡、几秒钟跑完 —— 这是全期门槛最低的一条。

它最值得学的不是代码，是 README 的「已知边界（诚实记录）」一节，五条全是自曝：

  1. 是运动学仿真，不是动力学仿真 —— 忽略 roll/pitch、地面反力与足端滑移， 接触被建模成「世界坐标位置冻结」。能严格检验步态逻辑，回答不了「会不会翻」「会不会打滑」。
  2. 力分配是静态的，摩擦锥是投影而非重解 —— 伪逆解接触力后把越锥的切向分量就地限幅， 限幅后竖直分量仍满足旋量，但切向总量不再满足：作者实测 50 N 前推时有 21.2 N 剪切被丢掉。 它只用来回答「力矩可行吗」，不参与仿真闭环。
  3. 爬行步态只验证了支撑多边形，机身横移没实现（名义质心裕度 0、切比雪夫中心余量 6.7 cm）。
  4. 交错落地时接触集可能只剩 1 个约束，此时偏航运动学上不可观测，代码退回全部继承接触。
  5. dt 与步态周期不整除会引入 1 tick 边界量化（0.4 s 配 2 ms 整除；0.5 s 配 2 ms 不整除）。

能把「我这里有 21.2 N 的剪切被静默丢掉了」写进 README 的仓，值得多看两眼。

坑：① 没有 LICENSE 文件（作者可能只是忘了）—— 想用先开 issue 问，别默认可以。 ② 1 星、9 月 13 日建仓，是个人练习项目的形态，不要当库依赖。 ③ 上面那五条边界是真边界，别拿它的输出去论证真机稳定性。

★ TOP 1（深度）· LLMs Robot Arena —— 让编码 agent 写机器人控制器，然后把它们扔进同一个擂台

先说清楚它在本系列里的位置。 这不是一个 VLA、不是一个本体、不是一个 benchmark 论文。 它是一个浏览器里的物理擂台：两台同样身体、同样电机、同样前楔的机器人在一块悬空平台上对打， 区别只有控制它们的那段 JavaScript —— 而那段 JavaScript 由 LLM 写。

作者自己写了一句很重要的自我限定：

It's not an AGI benchmark. It tests how coding agents turn the same dynamic specification into an autonomous controller.

放进本系列是因为它恰好落在四条标准的正中间：不需要任何硬件、不需要显卡、不需要账号、 不需要 API key 就能先玩，而且有一个明确可交付的终点（写一个能打赢 Baseline 的控制器）。 代价是它离「具身智能」的学术定义有距离 —— 这点我不含糊，下面「坑」里也会再说。

是什么（规则一句话讲清）。

  • 平台没有围栏。你可以把对手推下去、逼进洞里、或者用前楔把它掀翻。掉下去或第二次被掀翻即出局。
  • 能量有限。 移动和转向消耗能量，进入蓝色充能格恢复；站着不动不回能。
  • 地面会要命。 洞是立即判负；火焰格会先警告再灼烧并抽能量。
  • 站着不动有代价。 机器人自重会磨损地砖直到塌陷；有些地砖会在警告后消失；场地随时间收缩。
  • 一局最多两分钟。双方都活着就依次比：被掀翻次数更少 → 剩余能量 → 离中心距离。

控制器的契约极简：导出唯一一个 tick(sensors, memory)，返回 { actions: { thrust, turn }, memory }。 不许 import、不许依赖、不许网络、不许文件系统、不许时钟、不许随机数 API、不许动态代码生成。 状态只能放进返回的 JSON memory（上限 64 KiB），每个 tick 都是全新的模块作用域。 在 QuickJS 沙箱里跑。

坑与风险。

  1. ⚠️ 仓库没有 LICENSE 文件。 这是最大的问题，直接顶在本系列「开源许可允许个人用」这条标准上。 在浏览器里玩、本地 clone 跑、写自己的 bot，实践上没人会拦你； 但分发、fork 发布、把代码拿去用，法律上是不清楚的。 建议先开一个 issue 问许可 —— 这也是这个仓现在最值得提的一条 issue。
  2. 「对手是黑盒」是硬规则，不是建议。 AGENTS.md 里用了整整一节说这件事： 不许读、不许 diff、不许 import 来看、不许打印 packages/bots 里别的文件（包括参考控制器）， 不许绕道 git 历史 / 打包产物 / source map / 缓存 / 日志， 不许让另一个 agent、工具或人代你去看。搜索项目时要显式排除 packages/bots/**。 如果不小心看到了，规矩是：停止查看、声明暴露、不把信息用进 bot、不得声称这是一次未污染的评测。
  3. fuel 结果不等于 wall 结果。 一致性门跑出来的 fuel 是确定性的指令预算结果， 不是「符合挂钟时间预算」的证明。真要考挂钟就得用 --budget wall。
  4. 一次性提交 vs 迭代开发要如实标注。 AGENTS.md 要求： 如果任务要求 one-shot，就交第一次生成的文件，不许拿对手反馈调； 迭代出来的就标成 iterative，绝不能当成 one-shot 报。榜单上每一行都标了这一栏。
  5. 它不是具身智能研究。 二维刚体、离散传感、两个动作维度（thrust / turn）。 它测的是「编码 agent 能不能把一份动态规范变成自治控制器」， 不要拿它的结论去推 VLA、真机或 sim2real。本系列推荐它是因为它对个人极其友好，不是因为它是前沿。
  6. 规则版本 0.2.2-draft、引擎 0.2.2-r2 —— 还在 draft，跨版本的成绩不能混着比。

是什么。

MIT，9 月 13 日建仓，源码注释与文档为中文。作者的定位说明写得极其克制，值得整段引用逻辑：

调研 text-to-cad 后的定位收缩：它已经做得比我们好的，我们不做。

于是砍掉了三个自研模块（可打印性检查、标定试件库、标准件库，都退役进 archive/）， 只做生态里唯一空着的一格 —— 结构强度 / 刚度 / 稳定性。分工表长这样：

环节 用谁

技术栈是纯开源纯 Python：STEP/build123d → gmsh 网格 → FEniCSx 线弹性求解 → 报告。 三件它真正做出来的事：

  1. FDM 各向异性校核 —— 层内 vs 层间分开判据。 关键设计：同一份应力场，按打印姿态选对应正应力分量即可，不用对每种摆放重算（layer_normal = x/y/z）。 作者实测：同一个 FEA 场评三种姿态，层间应力 27.8 → 13.4 MPa —— 只改摆放。
  2. 结论稳健性 —— 材料参数估错会不会翻转结论？robustness.py 把这件事做成机械判据， 分区 robust → critical。块状结构裕度 5–30 倍，参数估错无所谓；薄壁/细杆裕度 < 2.5 倍才必须实测。
  3. 欧拉屈曲 —— 作者给的例子最有说服力： 100 mm 长的 5×5 立柱受压 31 N 即屈曲，而按强度能承数百牛。只做强度校核会给出错误的「安全」结论。

还有一个很少见的设计：bench.py 音叉自检 —— 先用有解析解的悬臂梁标定自己， 不过就拒绝输出零件结论。实测误差 −3.48%（容差 ±8%）。

🌍 国外 · cadjson —— 一个零件就是一个 JSON 文件，然后产出 STEP / STL / 3MF / 带尺寸的工程图 / Fusion 脚本

是什么。

MIT，v0.3.2，9 月 12 日建仓、9 月 14 日仍在推。一句话概括作者的主张：CAD as text。

一个零件 = 一个 JSON 文件：命名尺寸（params）+ 有序特征列表（features）+ 你想要的输出（outputs）。 底下用 OpenCascade 内核构建。长这样：

{ "schema": "cadjson/0.1", "name": "l_bracket", "units": "mm",
  "params": { "width": 60, "base_len": 40, "wall_h": 35, "t": 4, "hole_d": 5.5 },
  "features": [
    { "id": "profile", "type": "extrude", "distance": "width",
      "sketch": { "plane": "YZ", "shapes": [ { "type": "path", "start": [0, 0],
        "segments": [ "right base_len", "up t", "left base_len - t", "up wall_h - t", "left t", "close" ] } ] } },
    { "id": "inside_fillet", "type": "fillet", "radius": 3,
      "edges": { "of": "profile", "parallel_to": "X", "near": ["width / 2", "t", "t"] } },
    { "id": "wall_holes", "type": "hole", "face": { "of": "profile", "normal": "-Y" },
      "at": [[-15, 8], [15, 8]], "diameter": "hole_d", "through": true }
  ],
  "outputs": { "step": true, "stl": true, "drawing": { "sheet": true, "dimensions": true } } }

cadjson 的三个真正的差异点：

  1. 选择器不按索引。 面和边是按造它的那个特征、法向、方向、凹凸性、几何类型、尺寸或邻近度选的， 永远不按 index。这一条直击 code-CAD 交给 LLM 时最大的脆弱点 —— 改一个参数导致边的编号变了，整个脚本静默崩掉。
  2. 它产出的不只是模型，还有工程图。 STEP（给任何 CAD）、STL + 3MF（给打印）、 带消隐线的 2D 视图、剖视、带标注的图纸页、PNG 预览、可在浏览器里转动的 HTML 查看器、 一份 能在 Fusion 360 里重建原生时间线的脚本、以及一份 report.json 数字汇总。
  3. 文本即版本控制。 零件进 git、干净地 diff、能被 AI 写和改。仓里自带一个 Claude Code skill （.claude/skills/cadjson/SKILL.md），cadjson init my-parts 会把 skill 复制进你的零件仓。

覆盖的特征：extrude、revolve、fillet、chamfer、shell、孔（普通/沉头/埋头/真 ISO 螺纹， 支持 M3 / #6-32 这类标准规格的攻丝或过孔配合）、mirror、线性/极坐标阵列、loft、sweep、text、 导入件、按配合关系（同轴/贴合/齐平/平行）定位的装配体并做干涉与间隙检查。 变体用 extends 继承基础零件，新特征类型靠插件。

这条路线比 mesh 生成便宜一个量级，原因很具体：全程没有图像来回。

  • 写 JSON 本身极省 —— 上面那个 l_bracket 全文不到 400 token。
  • 真正烧 token 的是选择器调试回路：cadjson info 会列出每个面每条边， 这份输出喂回模型是输入的大头。
  • 一个带 8–12 个特征的零件，3–6 轮迭代，估输入 60–120k、输出 10–20k： Sonnet 5 ≈ $0.33–0.66；Opus 5 ≈ $0.55–1.1。 跑一个件大概 $0.3–1.2，约 ¥2.5–9。

坑（作者的 Status 一节自己列了，照抄要点）。

  1. ⚠️ Fusion 导出是对着假 API 验的，没在真 Fusion 里验过。 作者原话： "the Fusion export is verified against a fake API, not yet inside Fusion"。 而且螺纹、loft、sweep、text 和装配体都不导出到 Fusion； 导出脚本里的草图几何是数值化的（参数驱动特征值，不驱动草图尺寸）。 别把 Fusion 往返当成可靠通路。

📌 专题分析：这周这条链路上真正变了的东西（4 点）

1. text-to-cad 从「一个项目」变成了「一个生态位坐标系」。 本期两条的关系最能说明问题：cadloop 明确按 text-to-cad 的技能清单画了一张分工表， 砍掉三个自研模块只做它缺的 FEA；cadjson 则是在同一格里另起一条声明式路线。 一个 15.7k 星、仍在日更的仓，正在开始起「谁做什么」的协调作用 —— 这是一条链路从「各写各的」进入「按缺口补位」的标志。对个人的实际意义： 动手前先去 text-to-cad 的技能列表里对一遍，别再重复造 dfam-check 和标准件库。

2. 校核这一段正在从「几何」往「物理」推进，而且推进得很克制。 回看这几期的门：09-13 idea-to-print 是 19 项 DfAM 几何门（PASS/FAIL/UNKNOWN）； 09-12 SimpleCADforDSH 是单体/水密/0.2 mm 包络的几何 QA 硬门。 这些全是几何层的判据 —— 能答「能不能打出来」，答不了「打出来能不能用」。 cadloop 是本系列见到的第一个把线弹性 FEA + 欧拉屈曲接进这条链路的。 更值得学的是它没有假装精确：它做的是「结论稳健性分区」而不是「精确应力值」， 判据看敏感度不看精度，块状件裕度 5–30 倍就不必实测。 这个思路可以直接抄到任何 agent 化的工程判据上：先问这个指标会不会翻转结论，再决定要不要花钱测。

3. 「一个件多少钱」这个问题，本周出现了清晰的分层。 把本期和前几期的成本口径并排：

路线 token 主要花在哪 一个件量级

规律很干净：token 成本基本正比于「有没有图像在回路里」。 纯文本回路（code-CAD、声明式、切片器 CLI）都在一杯咖啡以内； 一旦把渲染图/照片塞回模型（mesh 生成、Blender 视觉回看、Computer Use 驱动商业 CAD），成本立刻跳档。 做选型时这条比「哪个模型更聪明」更能决定你的账单。

4. 这条链路上现在最空的两格（接着上期那条继续说）。 上期指出「从器件数据手册抽装配约束」是空的。本期能再加两条，都来自作者自己标的缺口：

  • 自动网格收敛判定（cadloop 限制 #4）—— 现在要人工做两点对比， 不做就有假通过风险。这是一个纯工程、边界清晰、半天到几天能做完的 PR。
