2026-09-09 · 具身智能可参与项目日报

今日主线：「先买传感器，别买执行器」成了最优的入场姿势。今天两区的最强项目指向同一件事 —— 把成本堆在执行端（舵机）是过去的默认，而 8 月底以来一批项目把只读的那一半单独拆出来卖：$27 的磁编码器 leader arm（对比舵机方案 $144）、€182 的手部动捕（去掉 €1040 的舵机后剩下的部分）、以及不用真机就能跑闭环评测的导航 VLA 框架。软件侧同步的变化是评测配置和 checkpoint 一起放出来，让个人第一次可以「不买机器人也能交出一个可比对的分数」。

🇨🇳 国内

★ TOP 1（深度）· OpenBMB SimpleNav —— 六个导航 benchmark 的 checkpoint 和评测配置一起放出来了

类型：软件 ｜ 硬件成本 0 元（纯仿真）｜ 周期 3–7 天出第一个分数 ｜ 许可 MIT

是什么。 清华 THUNLP、AI9Stars、OpenBMB、HITDIP 四方联合开源的导航 VLA 统一框架，2026-08-27 上线。它不是又一个模型，而是把「异构导航数据 → 长时序 VLA → 训练 → 闭环评测」这四段用明确接口串成一条可复用的流水线：数据侧走转换适配器进来（保留每个数据集自己的坐标系语义），模型侧组件可替换，训练由可移植 config 定义，benchmark 专属逻辑关在评测插件里，结果可追溯到代码 / 数据 / config / checkpoint / 模拟器版本。骨干是 Qwen3.5-VL 4B，配 BATS 长历史选择、时序视图编码、视觉 token 缓存和 DiT-B 动作头。同时支持空中（无人机）和地面导航。

为什么现在值得做。 关键不在框架，在于它把六个 benchmark 的「可移植评测配置 + 已训练 checkpoint」一起放出来了：OpenFly、TravelUAV、AerialVLN、EVT-Bench、R2R-CE、RxR-CE。此前个人想在导航这条线上做点什么，第一道墙不是显卡而是「跑不起来评测」—— 每个 benchmark 一套模拟器、一套坐标约定、一套动作协议，光对齐环境就能耗掉两周，而且跑出来的数字没法和论文比。SimpleNav 给的是 bash NavVLAeval/vlnce/r2r/run_eval.sh 这个级别的入口，加上 local/ 的固定资源布局，你第一次能在没有机器人、没有集群的情况下产出一个别人认得的数字。另外它每篇文档都有 _ZH 中文版（安装、数据、模型、训练、评测、结果全套），这在同量级的开源框架里几乎是独一份。

对比昨天推的 LightNav-0：那是一个导航 VLA 模型（4B，零样本跨本体）；SimpleNav 是承载这类模型的框架 + 评测底座。两者是上下游，不是同一件事。

个人怎么切进去。

  1. 第 1 天（0 元，2–3 小时）：clone，uv sync --frozen --no-dev 装环境，先只跑 uv run python -c "import torch, transformers" 确认环境干净。先不碰模拟器 —— 这一步的目的只是把 Python 3.10 + CUDA 那一层坐实。
  2. 第 2–3 天：从 ModelScope 组织页 下 R2R-CE 的 checkpoint（local/checkpoints/r2r/pytorch_model.pt）和对应场景资产，跑 NavVLAeval/vlnce/r2r/run_eval.sh。选 R2R-CE / RxR-CE 而不是 OpenFly —— 前者后端是 Habitat，后者要 AirSim（Unreal 场景包大、Linux 上更难伺候）。目标数字是 README 里的 Val-Unseen SR 49.2 / NE 4.7 m，跑到接近就算复现成功。
  3. 第 4–7 天（真正的产出）：挑一条你能改的东西提 PR。最容易切的是给一个还没适配的公开导航数据集写一个转换适配器（框架明确把这件事设计成插件），或者补一份缺的模型卡（README 列了模型卡必须包含的十项内容，标准是现成的）。产出物 = 一个被合并的适配器 + 一份可追溯的评测记录，比「我跑通了 demo」有用得多。
  4. 本机备注：这台机器 RTX A4000 16G —— Qwen3.5-VL 4B 推理评测够用；全量训练（六个 benchmark 的 config 都是给多卡写的）不要想，要练手就上 LoRA 或换小 backbone。

坑 / 风险。 ① 评测配置里有「server-specific configs are not published」这句话，也就是官方跑分用的服务器侧配置没全放，你复现的数字可能和表里有几个点的偏差，报告时要写清用的是 config_portable.yaml；② 模拟器资产是最大的时间坑，AirSim 那三个（OpenFly / TravelUAV / AerialVLN）要 Unreal 场景包，磁盘和下载都以几十 GB 计，第一次别碰；③ 框架自己在 README 里写了「不是安全认证的飞控系统」，别把它接到真无人机上；④ checkpoint 的 config 必须和 backbone / tokenizer / 相机顺序 / 历史设置 / 动作契约 / 统计量键逐项对齐，对不上会静默出垃圾结果而不是报错 —— 这是这个框架最容易踩的坑。

出处。 OpenBMB/SimpleNav 相关：项目主页（含 demo 视频） ｜ 数据 / 环境 / 模型 ModelScope 组织页 ｜ Release 01 完整跑分表 ｜ 中文安装文档

2 · StreamPI —— 给 π0.5 装上时序记忆，不加一个参数

类型：软件 ｜ 硬件成本 0 元 ｜ 周期 1–2 周 ｜ 港大 + ACE Robotics

  • 是什么 / 为什么。 8-26 上 arXiv、8-27 开源代码。核心观察是 π0.5 这类领先 VLA 一次只看一帧，既没有记忆也拿不到多帧聚合出来的精细空间感；而窗口式多帧模型每步重算整段历史，代价太高。StreamPI 把每个「视觉观测 + 语言指令」当成一个原子时间单元：单元内双向注意力保留跨模态对齐，单元间因果注意力提供时序上下文，KV cache 避免重算 —— 全部通过改注意力掩码 + 拉长 token 序列实现，不引入任何新参数，所以能直接继承 π0.5 的预训练权重。LIBERO 平均 98.3%（π0.5 是 96.9%，LIBERO-Long 从 92.4 → 95.0）；单张 RTX 4090 上把上下文从 1 帧拉到 5 帧，平均推理延迟只从 94.4 ms 涨到 103.6 ms。
  • 怎么切进去。 代码是 openpi 的 fork，examples/libero/ 和 examples/inference.ipynb 都在。最省事的路径：从公开的 pi05_base checkpoint 起，先用 T=1 跑一遍推理确认链路通（不加参数这个设计让单帧模式天然可用），再用 train_stream5_libero_4_nodes.sh 的单节点变体在 LIBERO-Goal 单个 suite 上做小规模复现。产出物是一条「上下文长度 vs 成功率 vs 延迟」的曲线 —— 这个消融别人还没做过几遍。
  • 坑。 ① README 的 News 写的是「2026-08-30: Code and model weights will be released」，代码在了，官方 StreamPI 的 fine-tuned 权重尚未确认放出 —— 想直接拿他们的分数就用，暂时不行；② 全量 fine-tune π0.5 是给 4 节点写的，16 GB 单卡跑不动全量，只能 LoRA / 缩 batch / 缩 suite；③ 继承 π0.5 意味着要接受 Gemma 的许可（仓库里单独放了 LICENSE_GEMMA.txt），商用前自己看清。
  • 出处。 hku-sail/StreamPI 相关：arXiv:2608.26067 ｜ 项目主页 ｜ 上游 openpi

3 · HumbleArm —— ¥200 起的桌面六轴 ROS 机械臂，把「最简」做到了极致

类型：硬件 ｜ 成本约 ¥200–400 ｜ 周期 3–5 天

  • 是什么 / 为什么。 8-22 上线的国产开源桌面六轴臂，硬件就三样：Arduino UNO + 一块 16 路 I2C 舵机驱动板（地址 0x2D）+ 6 路舵机。链路是 ROS 节点 → rosserial 串口桥 → Arduino → I2C 驱动板 → 舵机，并把当前角度回传到 current_joint_angles。它的价值不在性能，在于它是目前能找到的、最便宜的一条「完整走一遍机械臂软件栈」的路 —— 仓库里同时给了 Tkinter 关节滑块 GUI、末端 6 自由度 GUI、数值法逆运动学求解器（带可达性判断）、蒙特卡洛工作空间计算、修正过的 URDF（display / gazebo 两版）、RViz / Gazebo launch、MoveIt 配置包，以及 Hardware_files/ 里的结构件 STL、G-code 和接线图。
  • 怎么切进去。 先纯软件：装 ROS，跑 workspace_calc.py 算工作空间、在 RViz 里看 URDF 数字孪生 —— 这一步 0 元，先确认你能读懂这套坐标和关节映射。确认了再买件装机，接 real_arm_bridge.py 上真机。产出物：一台自己装的六轴臂 + 一份自己算的工作空间包络图。
  • 坑。 ① 6 路普通舵机 + Arduino UNO 的组合没有力矩反馈、没有闭环，current_joint_angles 回传的是「下发过的角度」不是实测角度，别指望做精细抓取或采模仿学习数据；② 只有 3 个 star、单人维护，遇到问题基本得自己啃；③ 仓库里混进了 .idea/ 这类 IDE 配置和第三方 MoveIt 教程工作区，clone 下来先分清哪些是正主。
  • 出处。 XiangxingZ/HumbleArm 相关：Embodied-AI-Start（8-25 上线的中文具身学习地图，151 star，配 MuJoCo / Isaac Sim 教程入口）

★ TOP 1（深度）· Open-source Leader Arm —— $27.45 的遥操作主臂，还不需要 follower

类型：硬件 ｜ 成本 $27.45（约 ¥195）+ 打印件 ｜ 周期 3–5 天 ｜ 8-25 上线，9-6 仍在更新

是什么。 一条给 SO-ARM 用的开源 leader arm（遥操作主臂）。它的全部聪明之处在一句观察：leader arm 的关节从来不需要被驱动，它只需要报告自己的角度。所以标准 LeRobot leader arm 上那 6 个 STS3215 舵机（$24 × 6 ≈ $144）可以整体换成 6 个 AS5600 磁编码器 —— 单价约 ¥13，还顺带让整条臂轻得多、手动移动更省力。AS5600 的 I2C 地址是固定的 0x36 改不了，作者用一片 TCA9548A 八通道 I2C 复用器给每个编码器分一条通道解决冲突。全套 BOM：6 × AS5600 + 磁铁、6 × 608 轴承、1 × TCA9548A、1 × ESP32、导线、60 颗 M3×10 螺丝、一块洞板、一根橡皮筋 —— 合计 2,619 印度卢比，$27.45。

为什么现在值得做。 这条是六条里唯一同时满足「便宜到可以试错」和「不依赖别的硬件到货」的：当前版本已经跑通对 MuJoCo 里带物理的仿真 SO-ARM 的遥操作，你可以在场景里真的把方块抓起来放进框，完全不需要买 follower 臂。 这就把遥操作采数据这件事的先决条件从「先花一两千买一套主从臂」压成「花两百块打几个件」。而 8 月的行情已经很清楚 —— 卡人的不是模型也不是算力，是有没有一批干净的演示数据；leader arm 就是产数据的那台机器。仓库完整度也超出这个价位：19 种共 49 个打印件（全部设计成免支撑、已按打印方向摆好）、接线图、ESP32 固件（只用内置 Wire 库）、25 步带配图的装配指南、两个可直接跑的 Python 脚本。

个人怎么切进去。 这条今天就能下单、周末就能装完：

  1. 今天（0 元，1 小时）：先跑软件侧。pip install "mujoco>=3.2" pyserial，clone mujoco_menagerie，把 teleop_sort_task.py 打开看一眼它怎么把六个角度喂给仿真 follower —— 硬件还没到就能先把这层看明白。
  2. 第 1–2 天：下单 6 个 AS5600 + 磁铁（务必成套买，径向磁铁单买很难配到）、6 个 608 轴承、TCA9548A、ESP32。同时开始打印：PLA、0.2 mm 层高、15% 填充。注意 bearing_housing 需要打印中途嵌轴承 —— 在 10 mm 高度（0.2 mm 层高下是第 50 层）加一个暂停，塞进 608 轴承压平再继续。
  3. 第 3 天：按接线图连好，刷 firmware/firmware.ino，串口 115200 看通道扫描 —— 每条通道打印 AS5600 found, magnet ok 才算好，打 -1 就是接错 / 缺磁铁。通过后固件以 100 Hz 流出六个逗号分隔的读数。
  4. 第 4 天：按 25 步装配指南装机（只有 joint_0 和 joint_5 的编码器先装，其余四个最后装，这样布线不打结）。装完 python teleop.py --port /dev/ttyUSB0，启动时把主臂摆到参考位姿再回车（脚本用硬编码的自然静止位姿做对齐基准，这一步错了整条映射都是歪的）。
  5. 之后：teleop_sort_task.py 做方块分拣，把轨迹按 LeRobot 格式录下来 —— 这就是一份仿真演示数据集，可以直接传 HF。真 follower 到货后同一套读数不用改。

坑 / 风险。 ① 磁编码器没有力反馈 —— 舵机版 leader arm 能给你阻尼和限位手感，这版全靠一根橡皮筋做重力补偿，长时间操作更累，精细任务的数据质量要自己评估；② AS5600 是 12 位单圈绝对式，装配时磁铁与芯片的间距和同心度直接决定读数噪声，rotor 里的磁铁没压平会一路影响到关节角；③ 六个编码器走一片复用器是串行轮询，100 Hz 是当前实测值，别指望往上大幅提；④ 仓库有 LICENSE 文件但 GitHub 没识别出标准 SPDX 类型，商用前自己打开确认条款；⑤ 作者只在仿真 follower 上验证过，接真 SO-ARM 的标定和限位需要你自己补。

3 · AlbertPro —— 14 cm 四足，MuJoCo 里学会走，导成 C header 跑在 ESP32 上

类型：软硬件全套 ｜ 硬件约 ¥150–300（8 舵机 + ESP32 + PCA9685 + 打印件，README 未给 BOM 价，此为按常见件估算）｜ 周期 1–2 周 ｜ MIT

  • 是什么 / 为什么。 8-23 上线的小四足：机身 14 × 11 × 2 cm、站高约 13 cm、4 × (髋 + 膝) = 8 自由度。整条 sim2real 闭环塞在一个仓里：MuJoCo 里用 PPO + GAE 训策略 → 导出成纯 C 头文件 → ESP32 + PCA9685 以 100 Hz 驱 8 个舵机。策略小到离谱 —— 24 → ReLU(64) → tanh(8)，2120 个 float、8.3 KB，所以能整个塞进单片机。动作空间是 ΔΔθ（网络输出的是「对一个持续 delta 缓冲的增量」，等于加速度级关节控制），作者的说法是这让步态天生平滑，不靠 reward shaping 硬调出来。训练曲线、四个 checkpoint 的对比视频（round 49 乱扑腾 → 849 已经在小跑）、1080p60 渲染全在仓里，跑到 0.25 m/s。
  • 怎么切进去。 硬件到货前先跑 RL/AllLegs_parallel.ipynb（4 个 MuJoCo worker 进程并行，约 4 倍速）—— 这是本机 RTX A4000 最合适的一条：策略只有 64 个隐单元，瓶颈在 MuJoCo 的 CPU 物理而不是显卡，A4000 完全不吃力，一个下午能训出会走的策略。然后 render_cinematic() 把 checkpoint 渲成成片。想上真机就打 hardware/albert_pro.stl，导出 trajectory.h 或 policy.h 刷进 ESP32/Albert_AML_meta/（四种步态，蓝牙发单字符 f/b/l/r/s 切换）。产出物 = 一条自己训出来的四足步态 + 一段能证明它在真机上走的视频。
