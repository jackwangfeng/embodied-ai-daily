★ TOP 1（深度）· PhysBrainEvalKit —— 把 28 个空间 / 具身 benchmark 收进同一条命令，而且允许你只有一张卡

是什么。

一套面向视觉语言模型的空间与具身智能评测工具包，9 月 8 日建仓，9 月 15 日还在推，21 星。 作者是 DeepCybo · 中关村学院 · 中关村人工智能研究院（这三个署名印在模型卡的 logo 图上， 不是我推断出来的）。它是在开源的 EmbodiedEvalKit 基础上扩出来的，这次放出的是：28 个 benchmark 的适配器、统一的 HuggingFace 推理接口、 点定位类任务的统一指标协议，以及一个「模型常驻 + 分片」的执行器。

配套模型是 PhysBrain 1.5，以 Qwen3-VL 为骨干，扩了动作 token 和视觉状态 token， 把语言回答、结构化空间输出、末端执行器轨迹、未来世界状态全部写成离散 token， 用同一个自回归目标训练，没有任务专用头。HF 上放了 8B 和 2B 两个尺寸 （8B 23 个赞 / 207 次下载，2B 12 个赞 / 152 次下载，均为本文写作时的数字）， 另有一个可以直接在浏览器里传图试的 Space。作者报告 8B 在这套 28 项的组合上总分 72.5， 自称在被评的开源模型里排第一。

28 个 benchmark 的名单和数据源在 README 里逐行列了 HF 仓库地址，覆盖三类：

类别 代表 数量
沿用 EmbodiedEvalKit 协议 ERQA、EgoPlan2、SAT、BLINK、CV-Bench、VSI-Bench、EmbSpatial、COSMOS、RoboVQA、VLABench… 12
点定位 / grounding（改用统一 micro-F1） Part-Affordance-2K、PIOBench、PixMo-Points、PointBench、RefSpatial-Bench、RoboAfford、RoboRefit、RoboSpatial-Home、VABench-Point、Where2Place 10
工具包之外、沿用各自官方规则 ERQA-PLUS、ViewSpatial、MindCube、MMSI-Bench、3DSRBench、Q-Spatial-Bench 6

为什么现在值得做。

具身 VLM 这一年最大的问题不是没模型，是没有一把公认的尺子 —— 每篇论文报的 benchmark 组合不同、 prompt 不同、点定位的判对标准更是各写各的。这个仓做的事情就是把这些钉死： 统一输入协议、统一 prompt 模板、贪心解码（temperature=0.0、top_p=1.0、top_k=-1、seed=3407）、 benchmark 级和分片级的 --resume。只有 MMSI-Bench 是故意的例外，它显式开采样 （--mmsi-temperature、--mmsi-seed）。

对个人的意义在另一处：这套东西整个社区都没有「在消费级单卡上到底能跑哪些、要多久、要多少显存、 数据集一共多大」这张表。 作者用的是多卡分片跑法（--gpus 0,1,2,3 --models-per-gpu 2）， README 里没有任何单卡数字。这张表就是你能交出去的第一份东西，它不需要你有新想法， 只需要你有一张卡和耐心，而且它对后面每一个想复现的人都有用。

个人怎么分步切进去。

Step 0（5 分钟，0 元）—— 先别装环境。打开 HF Space demo， 传一张你自己场景的图，试试它的空间理解、具身推理和点定位。如果这个模型的能力和你关心的事没关系， 后面几步就别做了。

Step 1（约 1 小时）—— 环境。 Python 3.10+，作者用 3.11 验证。

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

分片启动器额外要 Bash、taskset、nvidia-smi。 ⚠️ FlashAttention 版本会影响分数：作者写明 PhysBrain 1.5 是在 FA4 上训的， 用 FA4 评测结果正常，用 FA2 会有小幅波动（作者称在可接受范围内）。 你如果用 FA2，报数字时要注明。

Step 2（半小时）—— 选模型，这一步决定你能不能在 16 G 卡上跑完。

候选 bf16 权重量级 A4000 16 G
DeepCybo/PhysBrain1.5-2B 约 4–5 GB ✅ 宽裕，可以 --models-per-gpu 2
Qwen/Qwen3-VL-4B-Instruct 约 8–9 GB ✅ 单 worker 可跑，长视频 benchmark 要留余量
DeepCybo/PhysBrain1.5-8B 约 16 GB ❌ bf16 放不下，要量化或 offload（作者未提供量化配置）

（权重量级是按参数量 × 2 字节的估算，不含 KV cache 和视觉 token 的激活，实际峰值更高； 以你自己 nvidia-smi 看到的为准。）

建议的第一枪：PhysBrain1.5-2B + --only ERQA,PointBench。 一个多选题类、一个点定位类，正好各覆盖一种指标路径。

Step 3（时间取决于网络）—— 先 dry-run，再下数据。

export HF_HOME=/data/huggingface          # 指到大盘，别用系统盘
export HF_DATASETS_CACHE=/data/huggingface/datasets
bash scripts/eval_qwen3vl.sh \
  --model-path /models/PhysBrain1.5-2B --model-name pb15-2b \
  --output-base /results/pb15-2b --gpus 0 --models-per-gpu 1 \
  --cpu-per-worker 4 --only ERQA,PointBench --dry-run

⚠️ --dry-run 只验证模型配置和 CLI 参数并打印计划，不下载数据、不检查数据集文件 —— 这是 README 明说的，别把它当成「预检通过」。 28 个数据集加起来有多大，官方没公布 —— 这是你能交出去的第二个数字。

Step 4（跑全量）—— 去掉 --dry-run，加上 --resume 和固定的 --run-id。 中断之后用同一个 --run-id 重启可以复用未完成的分片。单卡就 --models-per-gpu 1。

Step 5（出表）—— python scripts/summarize_benchmark_scores.py --help 做聚合， 然后把「显存峰值 / 每个 benchmark 的墙钟时间 / 数据集体积 / FA2 与 FA4 的差」写成一个 issue 交回去。 这一步才是产出。

成本与时间。 全程没有 API token 开销（模型全在本地跑）。 自有 A4000：只有电费和时间，2B 跑完 28 项的量级估计是一整天到两天（作者未给单卡基准， 这是按 VLM 评测的一般吞吐做的量级猜测，不是实测）。 要跑 8B 的话，租一张 4090/A100 按市面 ¥2–4/小时估，先用 --only 把流程跑通再包时段。

坑与风险。

  1. ⚠️ 仓里没有 LICENSE 文件。 这是它最大的风险：gh repo view 返回的许可是空。 README 只写了「数据集许可由各自所有者管辖」，没说代码本身按什么许可发布。 用之前先开 issue 问作者，别默认可用。
  2. 点定位的分数不能和各 benchmark 的官方数字对比。 那 10 个任务作者改用了 统一的 micro-averaged F1（同时衡量预测有效性和目标覆盖），这是他们自己的协议， 见 docs/final_point_metrics_protocol.md。
  3. 两个轨迹类 benchmark 报的是 100−NRMSE，为了让「越大越好」一致 —— 读表时别按原指标理解。
  4. 只有 HF backend。 分片启动器目前不支持 vLLM / SGLang（模型卡里说模型本身兼容， 但这套评测的执行器不支持），吞吐上不去就是不去。
  5. 数据集许可各不相同：28 个数据集各自的访问条款要逐个看，商用前尤其如此。

2 · OptiDuck —— 把 microduck 搬到一块 ¥150 的 Radxa 板子上，外加一份 149 KB 的中文踩坑教程

先说清楚它和前两期那两条 microduck 的区别（避免你觉得在看重复内容）：

期 条目 讲的是
09-12 Microduck 装机教程 整机 BOM 与装配，核价约 ¥3700–4200
09-13 microduck-playground 四组可复现 RL 实验 + ONNX 策略 + 打印件
本期 OptiDuck 换一块 SBC（Radxa ZERO 3W）从零 bring-up，以及子模块工程的组织方式

是什么。 一个 umbrella 仓：本体只放文档和归档，三块代码以 git submodule 引入 —— 上板软件栈（pollen-robotics/microduck 的本地变体， 一堆 Rust daemon：robotd/configd/btd/padd/updaterd 加 robotctl/duckctl CLI）、 RL 训练仓（microduck_rl 的变体， mjlab + MuJoCo 任务、HD1910 舵机台架标定、BAM 作动器辨识）、 结构硬件（JoyandAI/OpenMicroDuck，SolidWorks CAD + BOM）。

主控从官方路线换成了 Radxa ZERO 3W（RK3566 / 2 GB），跑 Radxa OS（Debian 13，6.1 内核）， 舵机总线走 UART2，姿态传感器走 I2C4，步态策略在 MuJoCo 里用 RL 训完导出 ONNX 上板。

真正的价值在那份 149 KB 的中文教程（仓根目录那份「Radxa ZERO 3W 零基础部署调试教程」）， 第 0 节直接叫「踩坑血泪史（必看！帮你节省 2~3 小时）」，七条都是只有真上过手才写得出来的：

  1. 电源不够 → 内核能起来，但 TF 卡物理设备根本识别不到
  2. Windows 上烧 Armbian 镜像的已知 bug → 分区表被清掉
  3. Armbian 设备树里只有通用 radxa-zero3，没有 ZERO 3W 专用 dtb
  4. PowerShell 的 $env:USERPROFILE 展开坑
  5. SSH Connection refused → 板子上压根没装 openssh-server
  6. initramfs 里 ls /dev/mmcblk* 两种情况的区别
  7. 重启后 Wi-Fi 不自动连 → 开机即失联（凭据被存进了用户密钥环）

第 6 节还有一段值得单独读的：先跑 7 条诊断再动手（启动配置文件叫什么、/dev/ttyS2 在不在、 舵机总线上有没有 getty 在抢串口 ← 这条最阴），然后 6.7 节把它抽象成方法论： 「换一块新板子 / 换个新机器人，怎么自己设计 bring-up」。这一节和 microduck 没关系， 对任何 SBC 机器人都成立。

个人怎么切进去。 最低成本路线是先只买板子（Radxa ZERO 3W 零售价 ¥150 上下， 按你自己的渠道核价）：照教程烧卡、配好免密登录、跑那 7 条诊断、跑 setup-board.sh， 这一步就能验证你会不会踩那七个坑，而且一个舵机都还没买。 再往上才是整机（以 OpenMicroDuck 的 BOM 为准，量级参考 09-12 那期的 ¥3700–4200 核价）。 纯仿真的话，microduck_rl 里 HD1910 的 BAM 参数已经拟合进 vendor/bam/bam/params/hd1910/*.json，不下载原始标定数据也能训。

坑。

  • 许可是混的：软件 Apache-2.0，但 OpenMicroDuck 的 CAD 与文档是 CC-BY-NC-SA-4.0，非商用。
  • 子模块要两步提交：子仓 push 完，还得回主仓 git add <子模块路径> && git commit 把指针推上去， 否则别人 clone 到的还是旧 commit。README 把这条单独写了一节，说明作者自己被咬过。
  • 大文件不在 git 里：HD1910 标定原始数据约 426 MB、训练权重归档约 405 MB，走 Release 附件， clone 下来是没有的。
  • ⚠️ 仓根目录有一个 56 字节的小文本文件，文件名显示它记录的是作者自己的远程登录地址。 我没有打开它，也不建议你去看 —— 但把这类文件提交进公开仓是个坏习惯，值得给作者提一个 issue。
  • 新仓（9 月 15 日建），1 星，作者本人还在推。

★ TOP 1（深度）· RLE-Bench —— 给「编码 agent 当机器人学习工程师」出了一份资格考试，其中两题不用 GPU

是什么。

9 月 14 日放出的基准，MIT 许可，33 星，在线排行榜已经开了。 它问的问题是：编码 agent 能不能干机器人学习工程师（Robot Learning Engineer）的活？ 不是「能不能控制机器人」，而是开发策略、搭感知系统、设计本体这一整套工程工作。

九个任务族，四类：

任务 类别 要做的事 要 GPU 吗
task01 交互控制 agent 在环，解厨房操作任务 是
task02 交互控制 给未来的任务搭可复用的工具与技能（评分方式：另一个全新 agent 拿你造的工具去解一个没见过的任务） 是
task03 交互控制 解具身推理挑战 是
task04 策略开发 训人形全身动作跟踪策略，交 ONNX 是（参考预算 1×RTX 5090）
task05 策略开发 在限量 replay 预算下训 VLA（NanoVLA Recipe） 是（参考预算 1×H100）
task06 感知估计 对抗性传感下估物体位姿 视变体而定
task07 感知估计 清料箱：磁吸 Franka 把 12–16 个冲压钢件收进料巢 否（纯 CPU）
task08 机械设计 设计一个麦轮移动底盘，要同时扛住 Panda / UR5e / xArm7 三条臂 否（纯 CPU）
task09 机械设计 遥操作硬件与软件协同设计（Gello 重力补偿） 否

评测方式是这套东西最硬的地方：agent 在一个容器里干活、写产物到 /logs/artifacts/， verifier 是另一个独立镜像，拿隐藏的 seed、隐藏的场景、私有的评分代码重跑。 以 task08 为例：verifier 把你交的 robot.xml 里的 arm_* 子树删掉， 换上可信的适配器和三条标准臂，跑 A–E 五个动力学场景 × 三个隐藏 seed， 再把你的 controller.py 放进 uid 隔离的进程里跑十二个货架目标、1 kg 和 2 kg 各一遍， 还会重放第一个目标检查确定性。最终分数是「三条臂里最差的那条」。 validity 里有两个 gate（模型能加载、结构连通），挂掉就把总分封在 0.15。

为什么现在值得做。

三个理由，按重要性排：

  1. 它是本季度第一个把 agent 放进「有物理后果」的工程任务里、并且能自动打分的东西。 之前 09-15 那期写的 LLMs Robot Arena 是同一方向的浏览器擂台，但那是表演赛 （1560 局、置信区间大面积重叠）；RLE-Bench 有隐藏 seed、私有评分、确定性重放和 gate。
  2. task07 / task08 / task09 纯 CPU。 这意味着门槛不是显卡，是 Docker 和耐心 —— 对只有一张 16 G 卡（甚至没有卡）的个人来说，这是本期唯一一个「今晚就能开跑」的国外项目。
  3. RLE-Bench 2.0 正在公开征集任务，明码写着共同作者署名和高影响力贡献的现金奖励 —— 详见下面比赛一节，这是本期新发现的入口。

个人怎么分步切进去。

Step 0 —— 先避开 README 的第一个坑。 README 里的安装命令写的是 git clone https://github.com/RLE-Bench/RLE-Bench-dev.git，那个仓不存在 （我查了，GraphQL 报 Could not resolve to a Repository）。用：

git clone https://github.com/RLE-Bench/RLE-Bench.git      # 默认分支是 master，不是 main
cd RLE-Bench && make install && source .venv/bin/activate

Step 1（10 分钟）—— 体检。

rlebench list      # 有哪些任务族、各自准备好了没
rlebench doctor    # 本机缺什么依赖

需要 Linux + Git + Make + uv + 跑着的 Docker。GPU 任务还要 Docker 能拿到 NVIDIA 卡。

Step 2（半小时–数小时，取决于镜像构建）—— 准备最便宜的那题。

rlebench prepare task08     # 机械设计，无需 GPU
