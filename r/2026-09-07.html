★ TOP 1（深度）· PrimeBot 家庭双臂操作挑战赛 —— 1,500 小时数据 + 仍在收提交的公开赛道

类型：软件 / 数据集 + 比赛 ｜ 硬件成本 0 元 ｜ 周期 2–4 天出第一次提交 ｜ 报名状态：开放，剩 9/9、9/11 两轮评测

是什么。 这是 IROS 2026 Workshop 下挂的 Real-World Household Bimanual Manipulation Challenge，主办方把三样东西一次给全了：

  1. 数据：1,500 小时双臂家务操作演示，中英双语说明，LeRobot 格式。既有真机遥操作数据，也有 UMI 手持采集数据（含标注与 IMU）。HF 上已被下载 23.9 万次。
  2. 本体描述：challenge_data/robot_description/x2w.urdf —— 官方明确开放给非商用的教学、实验、研究使用。
  3. 评测通道：线上只提交动作预测结果（不用交图像、标注、本体状态），Google Form 投递，北京时间每个评测日 10:00 统一跑分，当天更新 leaderboard。

配套论文 arXiv:2609.03591（9 月 3 日提交）用这批数据训了 XR-2 这个 VLA，并系统研究了两条 scaling 轴：专家演示数据量、以及真人实时接管产生的 DAgger 纠正数据。两条轴上成功率都随数据量稳定上升。

为什么现在值得做。 对个人来说，具身智能最难的从来不是「找不到模型」，而是**「没有一个别人认可的地方证明你的模型行」。RoboChallenge 那类远程真机评测解决了一半，但排期和名额有限；这个挑战赛把门槛压到了极致 —— 提交的是一个动作预测文件，不需要任何硬件、不需要跑仿真环境、不需要排队。而且它是有明确日期、正在收提交**的，不是那种「报名已截止但页面还挂着」的僵尸比赛：评测日排在 8/26、8/28、8/31、9/2、9/4、9/7、9/9、9/11，今天这轮已经跑过，还剩两轮。

个人怎么切进去。

  1. 今天（2 小时，0 元）：hf download 拉 validation_data 和 example_data/online_submission，先照着示例格式拼一个最笨的 baseline（上一帧动作重复 / 训练集最近邻），把「读数据 → 出 25 维预测 → 打包成 zip → Google Form 提交」这条链路走通。这一步的目标只是不报错，别管分数。
  2. 明后两天（A4000 16G 够用）：官方明说「考虑参赛队算力，评测不超过 4 个任务」—— 所以不用训通用模型，按任务各训一个小模型就行。LeRobot 里的 ACT 或 SmolVLA 直接在 25 维动作上微调即可，本机单卡跑得动。
  3. 9 月 9 日 10:00 前：提交第一版真模型。同一支队伍可以多次提交，官方取评测前最新的一版，所以先占位、再迭代是完全允许的。
  4. 9 月 11 日：最后一轮。线下阶段需要交完整 docker，官方提供了含推理框架和机器人运行环境的 base docker，入围了再说。

评分细节（不看会白跑）。 分数与动作预测误差的 MSE / MAE 相关，只在 25 维上计算，也只需要提交 25 维。时间轴上也不是全段计分：一条 1000 帧的 episode 被切成 4 段，只在 [99, 420) 和 [420, 910) 两段上算分 —— 但提交的预测长度仍然要是完整的 1000 帧。这两条只要错一条，提交格式就废了。

坑 / 风险。 ① 线上分数是离线动作预测误差，不是真机成功率 —— MSE 低不代表机器人能把活干成，别把 leaderboard 名次当能力证明；② 只剩两轮，9/11 之后线上通道就没有意义了，想参与得今天动手；③ URDF 明确限非商用，商业项目别碰；④ 数据体量大，先只下 validation 和示例，别一上来拉全量。

出处。 challenge-2026/challenge_data（数据集 + 完整赛规，中英双语） 相关：论文 arXiv:2609.03591（XR-2 与 1,500 小时数据的 scaling 研究） ｜ Leaderboard（IROS 2026 Workshop） ｜ LeRobot 主仓（ACT / SmolVLA 基线）

2 · LightNav-0 —— 亮源新创的 4B 导航 VLA，一条命令对着 mp4 就能跑

类型：软件 ｜ 硬件成本 0 元（16G 单卡够）｜ 周期 1 天出结果 ｜ 9 月 1 日发布

  • 是什么 / 为什么。 基于 Qwen3-VL-4B-Instruct 的通用导航大脑，Apache-2.0，发布一周 453 star。它不给任务加专用预测头：双通道 pointing token 表达与本体无关的空间意图，再用 RVQ 动作 tokenizer（3×256 码本，horizon 10）解成 (10, 3) 的机器人局部航点 [前进 m, 左移 m, 偏航 rad]。指令跟随、开放词汇目标导航、视觉跟踪三件事活在同一个模型里，并且零样本跨人形 / 四足 / 轮式 / 无人机四种本体。训练侧的关键是 Real2Sim2Real 数据引擎：把 2000+ 个互联网真实场景转成可复用的仿真世界，产出 4000+ 小时导航 VLA 经验，再走「具身推理中训 → SFT → 在线 RL」三段。10 个仿真设置上 SOTA。
  • 怎么切进去。 不用有机器人：pip install "lightnav[vllm,video] @ git+..." 装好，hf download 拉权重，然后 lightnav-predict --video clip.mp4 --instruction "follow the person in the red shirt" —— 拿手机拍一段走廊视频就能看输出。要闭环就起 lightnav-serve，用自带 WebSocket 客户端驱动。Habitat VLN-CE / ObjectNav / EVT-Bench 的复现配方在 docs/。产出物：一份自己场景下的导航输出可视化，或一个 Habitat 分数。
  • 坑。 ① 4B bf16 + vLLM 在 16G 上跑得动但要留 KV cache 余量，视频帧数别拉太长；② eval_config.json 里的视频尺寸、SlowFast 历史分层等参数必须和训练一致，改了就废，推理代码会自动读它，别手动覆盖；③ 输出是航点不是电机指令，接真机得自己补底盘控制那一层。
  • 出处。 lightrobo/LightNav-0 相关：HF 权重 ｜ arXiv:2608.30935 ｜ 官方博客（9 月 1 日）

★ TOP 1（深度）· GRABETTE —— 没有机器人也能采出 LeRobot 数据集

类型：硬件（+ 配套软件全开源）｜ 成本按 BOM 采购，树莓派级 ｜ 周期 2–3 周 ｜ Apache-2.0

是什么。 Pollen Robotics（Microduck、Reachy Mini 的东家）开的一套机器人操作数据采集工具链。一个 GRABETTE 装置录同步的相机 + IMU 流，可以手持、也可以装在夹爪上；后处理用 SLAM 恢复相机轨迹，直接导出成 LeRobot 数据集。整条采集链路与机器人无关（robot-agnostic）。

仓库分成四个包：grabette（手持采集设备，跑树莓派，HTTP/WebSocket）、gripette（装在机器人上的夹爪电机，跑 Pi Zero 2W，gRPC）、grabette-postprocess（工作站上跑 SLAM 并生成数据集）、casquette（头戴 POV 设备，WIP）。硬件侧给了完整 BOM 表和 Onshape CAD，两套装配指南分开写。集成示例用 OpenArm 7-DoF + Gripette，附 MuJoCo 仿真、Diffusion Policy 训练代码，以及 π0.5 微调 + 远程 GPU 部署的现成配方。8 月 26 日还新开了 grabette-os，直接给现成的树莓派系统镜像。

为什么现在值得做。 过去一年的进展把整条链路上的瓶颈一格一格往后推：模型侧被 SmolVLA 打穿（单卡可微调），本体侧被 3D 打印 + 总线舵机打穿（千元级），剩下最后一个卡人的环节就是「你得先有台机器人才能采数据」。GRABETTE 把这一环拆掉了 —— 手持设备录你自己的手在干活，SLAM 补出轨迹，出来的东西格式上和遥操作数据一样能喂给 policy。这意味着硬件还没到货的那两周不再是空转，可以先把数据攒起来。这也是 Isaac 0.5 那份 scaling law 里明确度量过的一类数据（UMI 数据与遥操作数据的配比）。

个人怎么切进去。

  1. 第 1 天（0 元）：先别买件。clone 仓库（装 Git LFS，mesh 是 LFS 存的），拿官方样例跑一遍 grabette-postprocess，确认「录制文件 → SLAM → LeRobot 数据集」这条链路在你机器上通。这一步能验掉大部分环境问题。
  2. 第 1 周：照 BOM 表 采购、打印结构件，烧 grabette-os 镜像 —— 比自己配树莓派环境省一整天。
  3. 第 2 周：录 50 组自己的家务演示（开抽屉、倒水、叠衣服都行），导出成 LeRobot 数据集直接传 Hugging Face。产出物很硬：一份公开的、别人能直接训的自有数据集。
  4. 第 3 周：用 integrations/Pi05 的配方微调 π0.5，或走 integrations/DiffusionPolicy。两条路共用同一套数据管线。
  5. 换本体：packages/ 里的核心不依赖 OpenArm，加一个 integrations/<你的臂>/ 即可，OpenArm 那份就是参考实现。

坑 / 风险。 ① SLAM 轨迹质量吃场景纹理 —— 白墙、纯色台面这类弱纹理环境轨迹会飘，采集前先在目标场景试录一段验证；② casquette（头戴 POV）标注为 WIP，别把它算进计划；③ BOM 挂在 Google Sheet 上，国内访问要自备条件，建议先把表导出存本地；④ 手持采集的数据和真机遥操作数据存在分布差异，别指望纯手持数据训出的 policy 直接在机器人上满血，它更适合做预训练 / 数据增量。

2 · motion-bricks.cpp —— 把 NVIDIA MotionBricks 搬到 CPU 上，没显卡也能生成动作

类型：软件 ｜ 硬件成本 0 元（纯 CPU 可跑）｜ 周期 半天 ｜ 9 月 2 日建仓，Apache-2.0，135 star

  • 是什么 / 为什么。 NVIDIA MotionBricks 的 C++23 / GGML 移植，支持 CPU 与 Vulkan 两条推理路径，对外是稳定 C ABI（可以从 PureGo 之类的绑定调用）。功能是从关键帧动态生成动作 / 动画，游戏和机器人都能用。已实现的 batch-one G1 推理链路是端到端完整的：严格 GGUF 加载、root/duration 规划、pose-token 预测、VQ 解码、418/414/413 特征转换、风格对齐、骨骼动画输出，CPU 与 Vulkan 共用同一套公开 API 且在参考测试集上保持相同的 duration 与 pose-token 决策。意义在于它把「动作生成」这件事从显卡上摘了下来 —— 笔记本、树莓派级设备上做运动生成变得现实，这对本体上算力受限的场景直接有用。
  • 怎么切进去。 cmake --preset debug && cmake --build --preset debug && ctest --preset debug 三条命令。配置阶段会自动下载并 SHA-256 校验 0.73 GB 的 G1 F32 GGUF 权重和风格包到 generated/，也可以先 python scripts/download_gguf_weights.py 单独拉。离线构建加 -DMOTIONBRICKS_DOWNLOAD_MODELS=OFF。产出物：一段自己关键帧驱动生成的骨骼动画，以及 CPU vs Vulkan 的耗时对比。
  • 坑。 ① 这是社区移植，不是 NVIDIA 官方发布，端到端做完的只有 batch-one G1 这条路径，别默认其他配置也通；② 0.73 GB 权重下载走的是构建流程，网络不好会卡在 cmake 配置阶段，建议先手动跑下载脚本；③ 权重仓库和 revision 可以用 MOTIONBRICKS_MODEL_REPOSITORY / MOTIONBRICKS_MODEL_REVISION 覆盖，改之前先记下原值。

  1. 数据采集正在和机器人本体解耦。 GRABETTE 这类手持 / 头戴设备 + SLAM 的组合，让「先攒数据、后买硬件」第一次成为一条正经路线。PrimeBot 那份数据集里同时给了真机遥操作数据和 UMI 手持数据，也是同一个信号：两类数据已经被主流管线一视同仁地使用。对个人来说这条变化最实在 —— 硬件在路上的那两周不必空转。
