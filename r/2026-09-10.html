🇨🇳 国内

★ TOP 1（深度）· PhysBrain 1.5 —— 中关村系的具身 VLM，2B / 8B 权重 9 月 8 日刚上线

类型：软件 ｜ 硬件成本 0 元 ｜ 显存：2B 约 5 GB、8B 需量化才进 16 G ｜ 周期 1 天出结果，1–2 周做完一轮微调

是什么。 DeepCybo 团队（联合中关村学院、中关村人工智能研究院）在 2026-09-08 放出的具身视觉-语言模型，同时上线 8B 和 2B 两个尺寸。它的设计不是「又一个 VLA」，而是把具身交互的闭环拆成三件事塞进同一个自回归骨干：理解观察到的世界、生成目标导向的动作、预测环境会怎么变。实现方式很直接 —— 在预训练的 Qwen3-VL 上扩词表，加入专门的 动作 token 和视觉状态 token，语言回答、结构化空间输出、末端执行器轨迹、未来世界状态全部表示成离散 token，用同一个 next-token 目标联合训练，没有任何任务专用 head。看 config.json 能验证这一点：架构就是原版 Qwen3VLForConditionalGeneration，只有 vocab_size 从 Qwen3-VL 的 15 万出头涨到 168576，多出来的一万多个就是那套统一动作码本。

具体能力分三块：① 具身理解 —— 在 28 个具身空间智能 / 规划 benchmark 上，8B 拿到 72.5 总分，开源模型里排第一，官方说法是「与领先闭源模型相当」；② 动作预测 —— 给指令 + 观测（+ 可选历史动作），输出下一段末端执行器动作 chunk，动作码本跨不同臂和控制配置共享，一个 checkpoint 驱动多种本体；③ 未来状态预测 —— 给当前观测和指令，预测一秒后的 RGB + 深度图 + 机器人 mask。

为什么现在值得做。 三个理由，按重要性排：

第一，它是标准 Qwen3-VL 接口，不是又一套要你从源码编译的私有框架。官方明说可以直接复用 Transformers、vLLM、SGLang、LLaMA-Factory、ms-swift、veRL。这是本条和大多数具身模型最本质的区别 —— 你不需要学一套新的训练栈，LLaMA-Factory 的 LoRA 配置改个模型路径就能开跑。社区反应也印证了这点：权重上线不到一天，mradermacher 就出了 2B 的 i1-GGUF 量化。

第二，2B 这个尺寸是真的能在这台机器上做完整实验的。bf16 下 2B 约 5 GB，A4000 的 16 G 可以放下模型 + 一个像样的 batch 做 LoRA。8B 是 4 个 safetensors 分片、bf16 约 17–18 GB，16 G 卡装不下，必须走 4-bit 或 offload。

第三，它给了个人一个稀缺的中间形态：不是纯 VLM（不会输出动作），也不是纯 VLA（除了动作啥也不会）。你可以只用它的指点 / affordance / 轨迹推理能力当感知前端，接到自己已有的控制器上 —— 这条路不需要任何机器人硬件。

个人怎么切进去。

  1. 今天（0 元，10 分钟）：先开 官方 HF Demo Space 传张自己屋里的照片，试试空间理解、指点定位和规划。先确认它对你关心的场景有没有用，再决定要不要下 17 GB 权重。
  2. 第一天（本机，2 小时）：拉 2B，用 stock transformers 起推理。因为架构名就是 Qwen3VLForConditionalGeneration，AutoModelForCausalLM / AutoProcessor 直接就能加载，不需要 trust_remote_code 之外的任何东西。跑通「图片 + 一句指令 → 点坐标」这条最短链路。
  3. 第 2–3 天：用 EmbodiedEvalKit（官方评测用的就是它）在一两个你能跑动的 benchmark 上复现 2B 的分数。产出物是一张「2B 在 X benchmark 上的复现分 vs 官方报的分」对照表 —— 官方 README 明说 2B 那一列被排除在开源排名之外、没有单独详述，这块是真空地带，谁先测谁就有话说。
  4. 第 2 周：LLaMA-Factory 或 ms-swift 上做一次 LoRA。别一上来微调动作 token（动作码本的编解码细节技术报告还没出），先微调空间理解 / 指点这一侧 —— 输入输出都是纯文本坐标，数据你自己就能标。
  5. 本机备注：. /workspace/cuda/env.sh 那套是给 onnxruntime 用的，跑 PyTorch 不需要。2B 全量微调在 16 G 上偏紧，LoRA 宽裕。

坑 / 风险。 五条，前两条是硬伤：

① 没有声明许可证。 HF 模型页的 tag 里没有任何 license: 字段，仓库里也没有 LICENSE 文件。这意味着你现在既不知道能不能商用，也不知道能不能再分发微调权重。 个人学习无所谓，任何往外发的东西先去问作者。 ② 配套 GitHub 仓库还没公开。 README 的 citation 指向 github.com/DeepCybo-PhysAI/PhysBrain-1.5，今天核过是 404。所以：没有官方推理示例、没有动作 token 的编解码脚本、没有微调配方。你拿到的就是权重 + 一份模型卡，动作那一路目前基本用不起来，能立刻用的是理解 / 指点 / 轨迹推理这一侧。 ③ 技术报告没出，README 里写的是「更多评测细节将在技术报告中给出」。72.5 这个数是官方自评自报的，虽然他们说明了会用统一 metric 重测所有对比模型（这点比多数论文诚实），但没有第三方复现。 ④ 8B 在 16 G 卡上不能 bf16 跑，见上。 ⑤ 训练数据来源、是否包含中文场景、动作码本覆盖哪些本体，模型卡里都没写。

出处。 DeepCybo/PhysBrain1.5-8B 相关：PhysBrain1.5-2B（本机首选） ｜ 官方在线 Demo Space ｜ 社区 2B i1-GGUF 量化 ｜ EmbodiedEvalKit（官方评测框架）

🌍 国外

★ TOP 1（深度）· BittleJuice —— 一台 $319 的机器狗，从 MuJoCo 学步到真机 50 Hz 走路的完整闭环

类型：硬件（含全套软件）｜ 硬件约 $319（≈ ¥2270，Petoi Bittle X v2）｜ 0 元也能玩（附训好的策略 + 仿真）｜ MIT ｜ 周期：一晚上到一周

是什么。 8-27 上线、9-6 仍在推的仓，做的是一件很具体的事：在 MuJoCo 里训一条行走策略，然后让它在一台真的 Petoi Bittle X 上以 50 Hz 走起来。仓里包含仿真、实测拟合的 plant model、把「指令 → 动作」延迟从 198 ms 砍到 54 ms 的固件补丁，以及一个不依赖 torch / mujoco 的独立运行时。训练好的策略随仓发布，所以从「拆箱的机器人」到「会走的机器人」可以完全不训练；想先看效果，三分钟、不需要任何硬件。

为什么现在值得做。 这是本期唯一一条四条标准全部干净命中的：$319 在预算内、单机 CPU 就够（PPO 跑一个 64 隐单元的网络，瓶颈在 MuJoCo 物理）、终点明确（robot 走路）、依赖全开源。但真正让它值得写深度的是它诚实的程度，这在开源机器人仓里非常罕见：

  • 它主动告诉你这条策略是开环的。 README 专门做了一个 blindfold 测试 —— 把两路 IMU 都替换成常量「直立静止」，策略几乎没反应：速度只掉 1.1%，在专门用来抓「有没有在读重力」的 4° 斜坡上只掉 0.2%。作者的原话是「闭环闭在管道里，不在策略里；这个机器人跑的是一段学会的节奏，而不是在对什么做出反应」，并且把它列为未开放的问题，还给出了猜测的原因（策略几乎不摔，所以没有任何东西在选择恢复能力）和一条 blindfold_test.py 让你自己验。
  • 它告诉你哪个指标才算数。 判断策略能不能迁移的不是 reward 曲线，而是 tools/mj_deployability.py 输出的 slew 饱和率：随仓策略是 2.6%，阈值 15%。
  • 它告诉你这台机器人有多烂。 三条硬约束驱动了整个代码库的设计：读不到关节位置（固件能推一个，但每个关节约 20 ms 且期间腿是软的，全身读一遍实测只有 9 Hz，而控制环每 tick 只有 20 ms）—— 所以 dof_pos / dof_vel 全程是估计值，用主机自己发出去的目标过一遍舵机响应模型算出来，并且仿真器也观测同一个估计值而不是它自己的 ground truth；没有原始陀螺仪（角速度是从融合姿态流差分出来的，这决定了噪声下限）；舵机很慢，而 MuJoCo 默认执行器快得多，两级必须一起拟合否则同一份延迟会被算两遍。结论作者直接写了：有意思的活儿在 plant model 里，不在算法里，RL 就是普通 PPO。

2 · Perceptron Isaac 0.5 —— 第一个把视频理解和机器人控制放进同一个骨干的开源前沿模型

类型：软件 ｜ Apache-2.0 ｜ 36B 稀疏，单卡跑不动，本条明确超出「投入可控」标准 ｜ 周期：读论文 1 天，真跑要租卡

  • 是什么 / 为什么。 Perceptron 在 8-26 放出的开放机器人基础模型：360 亿参数稀疏模型，一个骨干同时做多模态视频理解、具身推理、空间 grounding、任务进度估计和机器人控制。训练规模是 35+ 种机器人系统、10 万小时机器人经验、100 万小时通用视频、3 万亿多模态 token。它最有价值的产出其实不是权重，而是一条视频 / 机器人数据的 scaling law：在同一个 action loss 2.50 的目标下，用 1000 小时通用视频训的模型需要约 5900 小时遥操作数据，用 100 万小时通用视频训的只需要约 28 小时 —— 210 倍的遥操作需求缩减。这个数字直接回答了「我该去采数据还是去爬视频」这个所有人都在猜的问题。
