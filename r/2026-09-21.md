## 🇨🇳 国内

### 1️⃣ 【深度】Qi-hub-dot/microduck-locomotion-diagnosis —— 把一个 2164★ 项目里没人回答的 issue 复现、定位、修好

**是什么。**
[microduck_rl](https://github.com/pollen-robotics/microduck_rl) 是 Pollen Robotics 给 Microduck
（25 cm、约 800 g、14 个 Dynamixel XL330 的小双足）开源的训练代码，MuJoCo-Warp 做 GPU 物理、PPO 训到 50 Hz 再导 ONNX 上真机。
仓库里有个开放 issue [#46](https://github.com/pollen-robotics/microduck_rl/issues/46)：**走路任务训不出来**。
报告人用 4 张 L4 跑了七组对照实验，结论是策略收敛到原地站着、脚从不离地，**这个 issue 至今没有回复**。

这个仓库是一个人把它从头做完的完整记录：在 Windows 上跑通 → 复现失败 → 拆奖励定位原因 → 改掉 → 再测 →
**最后发现项目自己的评估指标有系统性偏差**。四件事每件都有落盘证据和源码行号。

**为什么现在值得做。**
这是个人参与开源具身项目**性价比最高的那种姿势**：不需要自己定义问题（issue 已经写好了）、
不需要硬件（纯仿真）、不需要说服谁（issue 摆在那里没人管），产出终点非常硬 ——
一条能被 maintainer 验证的 PR 或 issue 回复。

而且它给出的三条结论本身就有迁移价值，任何人调 legged locomotion 的奖励都会撞上：

1. **`air_time` 奖励的门控问题。** 它的权重 3.0 是所有正项里最大的，但门控只比较**有没有指令**，
   不问**实际有没有前进** —— 被命令前进却原地踏步的策略照样拿满这份奖励（microduck 把
   `command_threshold` 设成了 0.01）。改成按「实际水平速度达到指令 30%」门控后，
   `error_vel_xy` 从 0.43 降到 **0.35**。
   注意作者这里和报告人的现象还不一样：报告人测到 `air_time ≈ 0.002`（脚从不离地），
   作者复现出的是 **0.9997（脚一直在抬但不前进）** —— 卡的位置不同，是一个更具体的漏洞。
2. **前向 / 侧向误差等权是错的。** 单独写脚本测「它到底走不走」：固定前进指令跑 20 秒，
   路径走了 **7–9.5 米**、一千步只摔一次、轨迹平滑 —— **它会走，只是横着滑走**。
   逐步读身体系速度：恒定指令 `(+0.30, 0.00)` 下第 7 步前向 +0.112、侧向 **−0.230**，侧漂到了前向的两倍。
   把侧向误差乘 3 倍、跟踪项权重 2.0 → 4.0，同一第 7 步侧漂降到 **−0.044**（五分之一），前向几乎没变，
   `error_vel_xy` 从 0.35 降到 **0.21**。
3. **那个指标本身会高估误差约三倍。** 把测量从 8 步延到 400 步看稳态：前向速度稳定在 0.23–0.27
   （指令 0.30，跟踪率 77–90%），侧向在 ±0.06 内，**逐帧稳态误差 0.07，而同一时刻日志里的
   `error_vel_xy` 是 0.206**。看实现就明白了 —— 它把五类指令模式（站住 / 只控朝向 / 世界系 /
   只控前向 / 普通）的误差混在一起，还做整回合累积平均，把起步加速段（误差 0.30）和踉跄（0.17–0.24）都算进去。
   **盯着这一个数字，没法判断策略会不会走**，这也解释了报告人为什么查不出是哪类环境在失败。

**坑与风险。**

1. **仓库没有 LICENSE。** 作者自己的分析文字和脚本默认保留所有权利，**想引用或二次分发先开 issue 问**。
   上游 microduck_rl 的许可另算，提 PR 时以上游为准。
2. **作者的环境是 Windows + RTX 4070。** 上面第 2 步的 10 小时是他的口径，本机要按 ×2–2.5 折算。
   `4096` 并行环境在 A4000 16G 上要先确认显存够 —— MuJoCo-Warp 的显存占用随环境数近似线性，
   跑不起来就先降到 2048 并在结论里注明（并行数会影响 PPO 的样本效率，**不要拿不同并行数的曲线直接对比**）。
3. **修复本身是有范围的，别过度宣称。** 作者自己写明：`air_time` 的门控用的是「线性范数 + 角速度绝对值」，
   所以被命令**原地转身**的环境也通过门控 —— 但转身时原地踏步本来就对，不算漏洞。
   真正的漏洞只在「被命令前进却原地踏步」这一类。往 issue 里写的时候照抄这个范围说明。
4. **接相机的三个坑他已经踩过了**（深度图 `(B,1,H,W)` 不能和向量观测放同一扁平组，要单独成组 + `concatenate_dim=0`；
   默认 `obs_groups` 不含 camera，不显式挂 CNN 会报 `No 2D observations are provided`；
   平铺 MLP 处理不了 1024 维图像，要换 `SpatialSoftmaxCNNModel` 配 `cnn_cfg`）。做第 5 步直接抄，别重走。

### 2️⃣ DeRuiChen258/ACT-so101 —— ACT 全流程复现，TorchScript 导出到 C++ 新进程重载，12.69 ms

- **是什么**：SO-101 上的 LeRobot ACT 实验台，四段闭合：数据集审计 → CUDA 训练 → TorchScript 导出 →
  **C++（LibTorch）在独立新进程里重新加载并前向**，最后用 MuJoCo Menagerie 的 SO-ARM100 把真实抓取回放出来。
  上游编排是一个 C++17 CLI（`actlab`），Python 只出现在数据集扫描、导出、离线评测、可视化这几个点。
- **数字（全部实测、逐条有落盘证据）**：训练 3000 步 loss **13.628 → 0.716**，27 samples/s，**峰值显存 3.69 GB**，15.3 分钟；
  TorchScript 与官方 pipeline **max_abs_diff = 0.0**（freeze+reload 相对差 3.59e-4）；
  C++ 推理 **mean 12.69 ms / p95 14.05 ms**（warmup 5 + 30 次），C++ vs Python 最大绝对差 0.0445；
  专家 vs 预测末端 MAE 0.1206 m；物理抓取在 1.00×/1.05×/1.10×/1.20× 四档尺寸下全部 HELD。
- **本机口径**：他的卡是 **RTX 5070 Laptop（sm_120）**，模型只有 51.6 M 参数、峰值显存 3.69 GB ——
  A4000 16G 跑训练**绰绰有余**，折算约 **30–40 分钟**跑完 3000 步。推理侧折算约 **25–32 ms**，
  仍然远高于 SO-101 的控制需求。这是本期最容易在本机一天内完整复现的一条。
- **最该抄走的一条**：`infer_act` 这个**跨进程重载硬门禁**。很多人的 checkpoint 只在训练脚本的 Python 进程里能跑，
  一换进程就废；把「独立进程加载 `.pt` 并前向」做成流水线里的一道 PASS/FAIL，是部署前最便宜的一次体检。
- **坑**：① **README 自己顶着一行免责**：本项目未接真机、未接仿真环境，**仿真成功率 / 真机成功率一律 `NOT_MEASURED`**，
  离线动作误差不等于任务成功率 —— 引用时别把 MAE 当成功率；
  ② LibTorch 是 `2.12.0+cu132`、训练侧是 `torch 2.11.0+cu130`，**跨版本加载他实测通过**，但换你自己的组合要重验；
  ③ 数据集路径写死在 `configs/paths.yaml` 里的作者目录，改自己的再跑。

### 3️⃣ N-B-Studio/5010-3DOF-Foc-kinematic-chain —— 三个 5010 云台电机做成的 FOC 三关节链，MIT，STEP 齐

- **是什么**：一条**可复用的三关节串联 FOC 平台**，既能当腿（髋 / 膝 / 踝），也能当 3-DOF 机械臂。
  三个 5010 电机走 **CAN 1 Mbps** 分布式 FOC；主控 STM32H723 跑 **1 kHz 外环** + 安全状态机 + UART 命令；
  **每个关节另配一颗独立的输出端编码器**（AS5047P，挂在 STM32G030 编码器节点上），外加足底触点开关。
- **为什么值得做**：现在开源腿足几乎都直接上成品准直驱模组（RobStride / 宇树 / 本末），一条腿就四位数起。
  这个仓库是少见的**「从航模云台电机自己搭一条带输出端编码器的关节链」**的完整路径：
  固件、IK、URDF、RViz、STEP 装配体都在，而且**把安全做成了显式命令**
  （`CLEAR` / `ZERO` / `POWER ON` / `ARM` / `DISARM` / `POWER OFF`，加关节空间 PD 的力矩上限和看门狗）。
  **输出端编码器**这件事尤其值钱 —— 只有电机端编码器的自制关节，减速齿隙和形变是看不见的，
  做力控 / 落地检测时会被这段未知量直接拖死。
- **个人怎么切进去**：① 先只做**一个**关节：一颗 5010 + 一块 FOC 驱动板 + 一颗 AS5047P，
  把「电机端 vs 输出端」的角度差扫出来，这张图本身就是能发出去的结果；
  ② 再照 STEP 打印连杆串成三关节，跑仓库里的 Python IK 轨迹，用 RViz 看 `JointState`；
  ③ 想更进一步：它的 1 kHz 外环 + CAN 是现成的底座，**把上层换成本机上跑的策略**即可。
- **成本估算（未实测，按国内电商常见价推）**：5010 云台电机 3× ≈ ¥300–450、FOC 驱动板 3× ≈ ¥300–600、
  STM32H723 核心板 ≈ ¥100–180、STM32G030 + AS5047P 3× ≈ ¥150、CAN 收发器 / 线材 / 电源 ≈ ¥200、
  打印件 ≈ ¥100 —— **整条链大致 ¥1200–2200，单关节起步约 ¥300–500**，在预算内。
- **坑**：① README 里 YouTube 是 `TODO`，**演示只有 B 站那一条**，下手前先看完；
  ② 驱动板型号 README 没写死（只说「CAN FOC 驱动器」），选板要自己确认协议和 1 Mbps 波特率；
  ③ 5010 是航模云台电机，**持续力矩很小**，拿它当腿只能做轻质验证平台，别指望承重；
  ④ 安全命令齐全不等于安全 —— 1 kHz 外环 + 力矩上限第一次上电务必先 `DISARM` 状态空跑一遍。

### 2️⃣ j1s4nn/wmdrift —— 给自回归视频世界模型补一套「说得出数字」的失效诊断，纯 CPU 能跑

### 1️⃣ 🇨🇳 BUAA-CI-LAB/EmbodiInfer —— 北航做的「具身版 vLLM」，π0.5 一次前向从 74.33 ms 压到 38.89 ms

**是什么。**
一个**同时服务推理和 RL rollout** 的具身模型执行引擎。操作策略、世界-动作模型、循环式导航策略
走同一套 Python 接口，引擎负责批处理、会话状态、多卡分发，各模型只写自己的 adapter（加载 / 预处理 / 解码）。
配套还有一个 [EmbodiRun](https://github.com/BUAA-CI-LAB/EmbodiRun)：配一个模型、一个算力节点、一个机器人或仿真器，
整条闭环从一个文件里跑起来。两个仓库都是 2026-09-20 才推的。

**为什么对「连续决策」关键。**
它做的四件事恰好对应连续流的四个痛点：
**CUDA graph 重放** prefix 和 decode 路径（省内核启动）、
**跨环境批处理**（多个环境的观测攒一批、或者随环境推进滚动聚合）、
**循环会话**把导航策略的隐状态跟着观测走（显式 commit / reset / cancel）、
**同一个引擎直接出 log-prob 供 RL refit**。第三条尤其少见 —— 大多数推理框架假设每次请求无状态，
而连续感知的导航策略恰恰是有状态的。

**数字（作者口径：RTX 4090、BF16、batch 1、每个模型 1600 条 LIBERO-10 观测，2026-09-09 记录）。**

| 策略 | 优化前 | 优化后 | 吞吐 | 折算到本机 A4000（×2–2.5） |
|---|---:|---:|---:|---|
| π0.5（10 步去噪） | 74.33 ms | **38.89 ms** | 25.71 obs/s | **约 78–97 ms → 约 10–13 Hz** |
| GR00T N1.7（4 步去噪） | 45.51 ms | **31.30 ms** | 31.95 obs/s | **约 63–78 ms → 约 13–16 Hz** |

降幅：π0.5 **−47.7%**、GR00T **−31.2%**。基线走 SDPA，优化路径加了原生推理和 prefix graph，
π0.5 用 Triton 写的 prefix / denoising attention，GR00T 用 SDPA。
计时口径是**解码后的 CPU 观测进 → CPU 动作出**，warmup 10 条跨任务观测之后才开始计。
**batch 32 时 GR00T 优化路径达到 59.33 obs/s**（同一张卡）。

**个人怎么切进去。**

**坑。**
① **刚发两天（2026-09-20 首推、2★）**，接口还会动，别急着在上面盖生产代码；

### 2️⃣ 🌍 kaarelkaarelson/lingbot-world-v2-realtime —— 1.3B 世界模型跑到 16.1 FPS，一张六级优化阶梯全部量了

- **是什么**：把 LingBot-World 2.0（1.3B 视频世界模型）的推理**在不改模型的前提下**提到
  **单张 RTX 5090 上 16.1 FPS**，是论文原码的 **2.7×**，且**无损**。
  WASD 连续输入 → 连续出画面，`lingbot play dragon` 就是一个能玩的窗口。
- **横向对比（同一条 22 秒片段，`lingbot bench`，2026-09-17 在 RunPod 5090 上测）**：
  原论文代码 2.68 s/chunk（6.0 FPS）、SGLang Diffusion 2.48（6.45）、LightX2V 2.07（7.73）、
  NVIDIA FlashDreams 1.85（8.65）、**本项目 0.98（16.1）**。
- **那张阶梯（这才是能带走的东西）**：主机同步（每层都 CPU↔GPU 同步 → 记账搬到 GPU）2.68→2.57；
  解码器（Wan 2.1 VAE fp32 → fp16 + 亚像素上采样）2.57→**1.95**；编译（eager → 单张编译图）1.95→1.68；
  矩阵乘（bf16 linear → torchao FP8 rowwise）1.68→1.47；注意力（FlashAttention-2 → SageAttention 2.2）1.47→**1.04**；
  内核融合（norm / RoPE / residual / FP8 量化融成一个）1.04→0.98。
  总体：内核启动 ~20 000 → **~4 800**，主机同步 110 → **2**，GPU 占用 90% → **98%**。
  作者还诚实地写了**到此为止**：FP8 matmul 已到卡峰值 90%、解码卷积 83%，手写注意力内核最多再换 1 FPS，所以不写。
- **本机能不能跑：不能，要说清楚。** 作者自己标的最低配是 **RTX 4090 / 24 GB（未测，预计 ~12 FPS）**，
  **A4000 16G 装不下**；而且 A4000 是 **sm_86（Ampere）**，**没有 FP8 张量核**，
  阶梯里的第四级直接用不了，第五级 SageAttention 走 INT8 路径能不能覆盖 sm_86 也要自己验。
  所以本条的价值是**方法论而非可复现性** —— 六级里**主机同步、fp16 解码器 + 亚像素上采样、
  单张编译图、内核融合这四级在 A4000 上一样成立**，拿去优化你自己在跑的 DiT / 扩散策略，是能落地的。
- **个人切入点**：把这张阶梯当模板，对你手头的策略逐级测一遍（**每一级单独计时，不要一把梭**），
  最容易吃到的是前两级 —— 主机同步和 fp32 解码器几乎是所有开源实现的默认坑。
- **坑**：① **仓库没有 LICENSE**，权重要 HF token 自己下，上游模型的许可另算；
  ② 首次启动编译 ~2.5 分钟，之后 35 秒 —— **测速要跳过首次**（和本机 CUDA 那套规矩一样）；
  ③ 「无损」是有口径的：六级里四级 bit-identical，FP8 和注意力内核在相同输入上单独核过，
  其余用 PSNR/SSIM/LPIPS 与原 fp32 解码器对比，数字在 `quality_summary.tsv`；
  ④ 它是**世界模型**不是控制策略，别直接当 VLA 引擎用。

### 📌 专题小结

1. **这周的加速全部发生在「重复性」上，而不是「模型更小」上。** rMuscle 复用跨执行的内部状态、
   EmbodiInfer 复用去噪步之间的中间结果和 CUDA graph、SkipVLA 复用经典规划器去跳过自由空间、
   VLA-ULAP 复用一个 7.4 M 的本地头去跳过云端调用。四条路子不同，假设是同一个：
   **连续控制里绝大多数前向是在重复算已经算过的东西**。这对个人是好消息 —— 这类优化不需要重训模型。
2. **「一步生成」这条路本周被明确打了个问号。** One-Step Drifting 那份技术报告把速度提了 9 倍，
   成功率却在 LIBERO-Long 掉到 26%，而且三个种子方差只有 2.6 个百分点。
   它列的可疑因素里有一条特别值得记：**同步的 LIBERO 评测根本不会走异步 overlap 那条路径** ——
   也就是说，一步生成的收益要在**异步执行**下才可能兑现，用同步 benchmark 评它本身就低估了它。
   凡是看到「一次前向省了多少毫秒」，先问评测是不是异步的。
3. **触觉终于开始按自己的时间尺度进闭环了。** Agile-WAM 和 ForceDelta-VLA 是从两头逼近同一件事：
   前者让触觉 latent 只预测下一帧、视觉 latent 预测更远（**承认两种模态的采样节奏不同**），
   后者让力修正在两次参考动作更新**之间**生效（**承认动作块的时间粒度太粗**）。
   过去把触觉当成「多一路图像」塞进视觉编码器的做法，本周被这两篇同时绕开了。
4. **一个不好的信号：本期六篇论文无一放出可跑代码。** 对照本专题前两期（FlashVLA、StreamPI、edge-reflex、
   Dexmal 三件套都是有仓库的），这周是纯论文周。所以主条目只能从工程仓库里选，
   也是为什么两条都落在推理侧 —— **带硬数字又有代码的，这周只有推理侧那两个**。
5. **给本机的一条实操建议**：EmbodiInfer 的 4090 数字折到 A4000 是 π0.5 ≈ 10–13 Hz、GR00T ≈ 13–16 Hz。
   这个频率**够做桌面操作，不够做动态任务**。想再往上，本期给的两条现实路径是
   **量化**（EmbodiInfer 自带 π0.5 / StreamVLN 的量化 benchmark）和 **云边交替**（VLA-ULAP 那套思路，
   本地那颗 7.4 M 的头在 A4000 上是白送的算力）。
   另外若要在执行侧补上连续目标流，[ServoPy](https://github.com/OpenGHz/servopy)（MIT，PyPI 上直接装，
   NumPy 是唯一必需依赖，Panda 演示 **100 Hz 伺服 / 500 Hz 物理**，纯 CPU）是本周新出的现成件 ——
   它把「新目标随时进来、下一个控制周期就用上」这件事做成了库。

## 📈 趋势观察

**这周最值得记的一条：个人参与开源具身项目的姿势，正在从「造新东西」转向「给已有项目补一把尺」。**
本期国内 top1（microduck 诊断）和国外第 2（wmdrift）是两个互不相干的人、在两个互不相干的项目上，
做了同一件事：**上游把失效现象描述清楚了，但没有量化，于是个人写出那个缺失的测量工具**。
microduck 那条更狠一步 —— 它量到最后发现**上游自己的评估指标高估误差约三倍**，
这解释了为什么 issue 报告人用七组对照实验也定位不到问题。
这种贡献不需要算力、不需要硬件、不需要你比 maintainer 聪明，只需要你**真的把数字逐帧读一遍**。
对只有一张 A4000 的个人来说，这是当前投入产出比最高的一类工作。

**第二条：「诚实性披露」开始变成开源具身仓库的标配，而且是自发的。**
本期 ACT-so101 在 README 顶部写「未接真机、成功率一律 `NOT_MEASURED`，离线动作误差不等于任务成功率」；
microduck 那条主动标注自己修复的**适用范围**（只覆盖「被命令前进却原地踏步」，不含原地转身）；
wmdrift 写明合成 fixture 上的阈值不能当通用门限；One-Step Drifting 把自己报成**权衡而非改进**；
gridfinity-designer 把实测 / 估算 / 假设三类数字分列。
五个项目、三个国家、互不相识。对个人的直接影响是：**现在往 README 里写一句「我没验证什么」，
比多贴一张 GIF 更能让人认真看你的仓库。**

**第三条：本周论文和代码明显脱节。** 专题二那六篇新论文，数字都很硬（11.9 ms、19.9 ms、82.2%、2.5×），
**但没有一篇放出可跑代码**（一篇标 coming soon、一篇只有项目页）。同一周里能直接跑的工程，
反而都来自没有论文的个人 / 实验室工程仓（EmbodiInfer、lingbot、ServoPy）。
短期内如果你要**复现**，看仓库；如果你要**找方向**，看论文 —— 这两条线这周是分开的，别指望论文自带代码。

**第四条：硬件侧出现了「不买模组，自己搭关节」的回潮。** 5010 那条（三个航模云台电机 + 独立输出端编码器 +
1 kHz STM32 外环，整链 ¥1200–2200）和 primo 那条（30 个 RobStride、整机 €30 000）是同一周的两个极端。
前者承重弱但**把输出端编码器这件事做对了**，后者设计完整但个人买不起。
中间那一档 —— 「能承重、又在四位数人民币内的开源关节」—— 依然是空的。
